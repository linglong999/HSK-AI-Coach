## 2. 借鉴 / 偏离 OpenMAIC（一手结论）

### 借鉴（源文件）

| 借鉴点 | 源 | 本项目落地 |
|--------|-----|-----------|
| append-only ledger + 摘要分离 | `engagementEvent` → `engagementSummary` + `instructor-memory.ts` | `error_ledger` 记事件，`summarize` 产摘要，agent 只消费摘要 |
| 规则 bucket 画像抽取（分桶+上限+截断） | `extractLearnerMemory` | 按 KP 聚合高频偏误/复习队列/掌握度 |
| staged 状态机（draft→pending→confirmed） | `fold.ts` handover/task_completion | **复用既有** error_graph pending/confirmed，不重造 |
| 惯犯调策略（repeatError→升级提示） | `tier-guidance.ts` | `repeatErrorCount>=3` → 画像标记为"惯犯"供 planner 主动点出 |

### 偏离（守宁漏勿错 / 不适用）

| OpenMAIC 做法 | 本项目改法 |
|---------------|-----------|
| 惯犯一次 stuck 即算（`>=1`/`>=2`） | 阈值 **`>=3`**（防误报污染画像） |
| PBL 任务流 staged 模型（Git 非完全） | 通用 error ledger + 复用已有 pending/confirmed（非重造状态机） |
| 全轮次永久记忆 | 环形窗口 + 摘要，不永久膨胀 |

## 3. 核心：M8 复用既有 engine，新增"事件/画像"层

M8 不重造图谱的两段式（引擎已实现：`ingest_error`→pending，`confirm_item`→confirmed，`get_review_queue` 排除待确认）。M8 的增量是 **`memory/writeback.py` + `memory/error_ledger.py` + `memory/summarize.py`**：

```
engine/graph/error_graph.py   # 已有：两段式 pending/confirmed + get_review_queue（不动）
engine/memory/
  error_ledger.py   # 通用 append-only 事件账本（决策 A-乙）
  writeback.py      # 写回编排：疑识→形成 pending；确认→进图谱并记 ledger 事件
  summarize.py      # 从图谱 + ledger 生成画像常错点摘要（决策 C）
```

## 4. error_ledger（决策 A-乙）

通用事件账本，每 learner 一个 JSON（复用 LearnerMemory 原子写风格）：

```python
class ErrorLedger:
    # 事件类型（仿 OpenMAIC engagementEvent，面向 HSK）
    KINDS = {"observation_error", "repeated_error", "concept_confirmed", "concept_reviewed"}

    def record(self, learner_id, kind, kp_id, signature=None, evidence="", ts=None) -> str:
        # append-only，返回 event_id；按 signature 判 repeated
    def count_for_kp(self, learner_id, kp_id) -> int          # 该 KP 事件数
    def repeated_count(self, learner_id, kp_id) -> int         # 重复信号（同 signature 累计）
    def is_repeat_offender(self, learner_id, kp_id, threshold=3) -> bool  # 惯犯判定（B-乙）
    def recent(self, learner_id, window=50) -> list            # 环形窗口截断
```

- 事件结构：`{id, kind, learner_id, kp_id, signature, evidence, ts}`
- 同 `kp_id`+`signature` 再出现 → `repeated_error` 类别并累加 repeated_count
- `ring buffer`：超窗口（如 500）丢最老，控膨胀（仿 fold MAX_ENGAGEMENT_EVENTS）
- 原子写（tmp+rename），异常不损旧文件

## 5. writeback.py（写回编排）

桥接 planner 与 error_graph/ledger，两段式分两个入口：

```python
class Writeback:
    def on_suspected(self, bias):        # 疑似：识别命中 → 调 graph.ingest_error（uncertain→pending）
    def on_confirmed(self, kp_id, evidence):  # 确认：explain/verify → 记 ledger concept_confirmed
    def on_repeated(self, kp_id):        # 惯犯：ledger.is_repeat_offender → 标记画像
    def review_queue(self):              # 透传 get_review_queue（供 planner 主动提醒）
```

- **疑似**：`graph.ingest_error(uncertain=...)` → 自动进 pending 队列（复用）
- **确认**：写 `error_ledger.concept_confirmed` + 更新 graph 信用
- **惯犯**：`repeated_count>=3` → `summarize` 时置高优先（供 planner 点出）

## 6. summarize.py（决策 C 画像摘要）

```python
def build_profile_summary(graph, ledger, learner_id, focus_kp=None) -> str:
    """图谱→画像常错点摘要。
    决策 C-乙：返回字符串摘要；若 focus_kp 给定则只含该 KP 相关（按需注入省 token）。"""
```

摘要结构（仿 extractLearnerMemory 桶式、上限+截断）：
```
## 常错点
- [惯犯] 把字句（HSK3）：重复 3 次，优先级 2.1
- 量词（HSK1）：重复 1 次，优先级 1.5
## 复习提醒
- 被字句（HSK4）优先级 3.2 到期复习
```
- 从 `graph.get_review_queue()` 取高优先级项 + `ledger.repeated_count` 标记惯犯
- `focus_kp` 给定 → 只保留该 KP 行（决策 C-乙，planner 涉及某 KP 时才注入）

## 7. 接入点（供 planner）

`writeback` 挂到 planner 动作序列后端；`summarize.build_profile_summary` 作为给 LLM 的可选上下文片段（`focus_kp` 由 planner 按当前动作注入）。设计文档约定"画像原文不进全量，按需取"（对齐 state-context）。

## 9. 验收标准

- [ ] 偏误先入"疑似"（pending），确认后变"已确认"并入图谱（复用引擎，测试覆盖）
- [ ] `is_repeat_offender(kp, 3)` 正确判定惯犯（≥3 才算）
- [ ] `build_profile_summary` 生成含惯犯+复习提醒的摘要；`focus_kp` 只含该 KP
- [ ] 空图谱/无事件时摘要安全返回（不崩）
- [ ] 既有测试全部 PASS，零新增依赖

## 10. 边界声明

- **不重造图谱状态机**：复用 pending/confirmed；M8 只加 ledger 事件与画像摘要层（对齐 OpenMAIC"不推倒重来"）。
- **宁漏勿错**：惯犯阈值 ≥3 防误报污染画像；确认才记 concept_confirmed，疑似只入 pending 不入画像。
- **按需注入**：画像摘要默认不每轮全量塞，`focus_kp` 控制（省 token，仿 state-context）。
- Ledger 为**窗口截断**（如 500），不永久膨胀。
