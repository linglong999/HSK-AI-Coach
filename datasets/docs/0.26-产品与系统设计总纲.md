## 第 1 章 · 产品定位与核心闭环

### 1.1 一句话定位

**HSK-AI-Coach** 是面向 HSK 中文学习者的 **AI 偏误纠错陪练**：输入一句中文或一段对话，它告诉你错在哪、为什么错、该怎么改，并把每次纠正沉淀进一张**偏误图谱**，过段时间主动拉你复习。

**拿它练习写/说中文，而不是拿它问答案。**

### 1.2 核心闭环

```
偏误检测 → 讲清原因 → 学习者复述检验 → 沉淀进复习计划
```

- 识别偏差 → 输出修正与类型
- 费曼式讲解（四段式）
- 学习者用自己的话复述 → 判定是否真懂（不过则降难度重讲）
- 图谱沉淀 → 到期主动复习

### 1.3 产品哲学（演变后形态）

项目经历了"纠错引擎 → 会话伙伴 + 按需脚手架"的定位转向：

| 维度 | 早期（纠错引擎） | 现在（习得伙伴） |
|---|---|---|
| 主导 | 逐句纠错 | 场景对话里开口习得为主 |
| 纠错角色 | 主线 | **卡壳才触发的脚手架** |
| 介入 | 高频打断 | **能交流就不打断，卡住才出手** |
| 数据 | 仅确诊图谱 | 偏误图谱(确诊) + L1 迁移带(candidate) + 复习队列 |

### 1.4 与 OpenMAIC 的关系（方法论借鉴，不搬其编排内核）

- OpenMAIC 是**空白知识传授**（对象啥都不会，从零生成一整节课），多智能体编排内核。
- 本项目的研发注入是**响应式诊断型教学**（对象带偏误来，对症"当下那一口"），生成单元从"一节"降到"一个回合"。
- **裁定**：守 **对话式教学闭环**（学习者↔单个 AI 老师，可控、可校验、贴合费曼）；弃多智能体自由讨论（发散、贵、难守"宁漏勿错"，与图谱权威冲突）。——此为演进红线。

### 1.5 核心亮点（对外叙事）

- 偏误识别做到"宁可漏判，不误报"——干净句误报确定性护栏压到 **0%**
- 费曼式复述检验——讲完让学习者用自己的话复述，而不是看一遍答案就"懂了"
- 偏误图谱是**唯一权威**——确定性数据层，AI 只能选路径、不能改数据，结果可复现
- 介入时机三档（none/light/block）——流利时静默记录，卡壳/求助才出手，打断上限服务端强制
- 教学语言分层——英文脚手架讲规则，中文载体装例句与词汇
- 零配置跑通 + BYOK——clone 即跑；未配 Key 有访客额度，界面内加任意 OpenAI 兼容供应商

## 第 2 章 · 架构总纲

### 2.1 一句话架构

**planner 自由 ReAct 为唯一对话入口；router 拆散收编；全部可交互能力收敛到统一 Skill 协议。**

### 2.2 分层架构图

```
┌─ 出入口层 ───────────────────────────────────────────
│  serve.py (HTTP:8612)
│    /api/dialog  →  planner 自由 ReAct（唯一对话入口）
│    /api/process →  router 兼容 runner（保留，前端在用，不进新叙事）
│    /api/verify  →  Verifier 复述验证
│    /api/generate→  GenerationEngine 费曼/练习单元
│    /api/graph   →  ErrorGraph 快照
└──────────┬──────────────────────────────
┌─ 编排层 ─────────────────────────────────────────────
│  planner.loop(ReAct)  唯一决策点（选哪个技能/怎么答）
│  读 list_all → 自主选技能 → 串 action/text → MAX_STEPS=6 内终止
└──────────┬──────────────────────────────
┌─ 能力层（统一 Skill 协议）─────────────────────────
│  identify_errors · explain_error · verify_retell
│  lookup_knowledge_point · get_review_queue · generate_unit
│  retrieve_corpus · web_search · parse_document
│   ↑ planner 只认这一套接口；技能自带 guardrails 框边界
└──────────┬──────────────────────────────
┌─ 引擎/服务层 ───────────────────────────────────────
│  recognizer · explainer · verifier · generation(authoring/validator/generator)
│  rag 倒排检索 · learner_memory · writeback(两段式) · error_ledger
│  tools/call_tool（web_search/parse_document 生效；asr/tts 留位）
│  intervention · persona · transfer（母语迁移带）
└──────────┬──────────────────────────────
┌─ 数据层 ─────────────────────────────────────────────
│  error_graph（唯一权威）· datasets 词表/知识点（+官方 xlsx）
│  transfer_rules_* · scenarios_* · memory/<learner>.json
│  data/*.json（gitignore）· 全 stdlib
```

垂直贯穿三条主线：
- **自由**：仅编排层 —— planner 自主决定调度。
- **约束**：数据写 —— 图谱唯一权威，写永远走 writeback 两段式 + 幂等键；技能 guardrails 框边界。
- **降级**：任一引擎/工具失败 → 结构化 `degraded[]`，绝不崩、绝不污染（零依赖许诺不变）。

### 2.3 统一 Skill 契约

每一个可交互能力 = 一个 Skill 对象。四段式结构化字段 + `run(context) -> result`：

```
metadata: name / version / summary / triggers / input / output / guardrails
input_schema / output_schema   # 供 planner 校验与生成调用
run(context) -> result         # 真正执行对应引擎
to_manifest()                  # 渲染完整详情给 LLM
```

- 引擎一律不改动；技能只做入参映射、出参封装、四段式描述与护栏。
- 零第三方依赖。

### 2.4 自由技能总清单

记号：`[引擎]`=已实现并被技能包装；入参只列最小可用面。

| # | 技能 name | 包引擎 | 入参要点 | guardrails（防误选/防越界） |
| --- | --- | --- | --- | --- |
| 1 | `identify_errors` | Recognizer | text, level, native_lang | 仅整句需找错时；空串不给 |
| 2 | `explain_error` | Explainer | fragment/偏误 | 已识别出的错才讲解；不衍生知识 |
| 3 | `verify_retell` | Verifier | key_points, restatement | key_points 是唯一覆盖点来源；不自己造覆盖集 |
| 4 | `lookup_knowledge_point` | 词表/知识点 | query/知识点名 | 查定义用；不查偏误 |
| 5 | `get_review_queue` | ErrorGraph | — | 拉低掌握/到期项；不写图谱 |
| 6 | `generate_unit` | GenerationEngine | unit_type, context | explain/practice/… 写回默认关，practice 命中已确认偏误才开 |
| 7 | `retrieve_corpus` | engine/rag | query, top_k, kp_only, level | 答疑引用权威语料；不编造来源；未命中如实说 |
| 8 | `web_search` | tools | query, max_results | 未配 key→not_configured；结果仅供补充不照搬 |
| 9 | `parse_document` | tools | text/url | 文本/简单文档；复杂 PDF 留位 |
| 10 | `graph_snapshot` | ErrorGraph | — | 只读快照；**不经技能暴露**，由 `GET /api/graph` 直接提供 |

> **router 拆散语义**：原 `router.process` 的"识别→讲解→验证→图谱→复习队列"固定序不再作为新叙事主入口；各能力为自由技能（#1/#2/#3/#5/#10），由 planner 按需自由串联，确定性闭环作为技能组合由 planner 自然复现。**不新建组合技能**。
>
> **实际注册**：`skills/` 已注册 **9 个**（#1–#9）；#7 `retrieve_corpus` 与 #4 `lookup_knowledge_point` 共享同一 RAG 索引实例。

### 2.5 planner = 唯一对话入口

自由 ReAct 循环（`planner/loop.py`，`MAX_STEPS=6`）：

```
system = list_all() 紧凑技能清单 + 全局规则
messages = [system] + history + [user(user_input)]
for step in range(6):
    raw = llm(messages)                       # LLM 输出 JSON 数组文本
    items = parse_json_array(raw)             # 自写 parser（OpenMAIC 式）
    for it: text→累积；action→REGISTRY.get(name).run(params)→tool_result 喂回
    终止：本轮有 text 且无待续 action → break
达 6 步 / 解析失败 → fallback（不崩）
```

**skill 调用防编造/参数校正确立为正规则多轮惯例**（见 §7.4、§7.5）。

### 2.6 防漂移边界（自由 ReAct 与确定性如何共存）

| 原则 | 落地 |
| --- | --- |
| **自由在调度** | planner 可自主选技能、自由回答、自由追问 |
| **约束在写** | 图谱写入仅经 `writeback`（疑似→确认两段式），幂等键防重复 |
| **权威不动** | 偏误图谱 = 唯一权威源；planner 只读它做复习/画像提醒 |
| **引擎不改** | 所有引擎只被技能包装，不改动 |
| **卡不乱长** | 前端卡片只能沿权威边（KP→关联→混淆→待复习）生长，无自由发散 |

"Agent 不直接对话"旧表述，收窄为"**planner 不直接写权威数据**"——它只是纯选择器。

### 2.7 对话 JSON 契约 v1（`/api/dialog` 出参）

字段表见真源（接缝契约适用结构与本结构相关），核心结构：

```
{
  "dialog_version": "v1",
  "learner_id": "...",
  "conversation_id": "...",       // 会话归属；同 id 复用延续上下文，不传=default
  "text": "……",                   // 给用户的自然语回复
  "used_skills": ["identify_errors", ...],
  "steps": 3,
  "fallback": false,
  "trace": [ {name, params, ok, result}, ... ],   // 技能轨迹 → 前端"学习成果卡"
  "degraded": [ {stage, reason, fatal}, ... ],    // 结构化降级
  "graph": {...},                  // 图谱快照（前端省一次 GET）
}
```

**M5 多轮记忆已接入**：`/api/dialog` 服务端 `LearnerMemory` 为多轮上下文唯一权威源——按 `conversation_id` 读 `to_llm_history()` 注入 planner，本轮 user + assistant 追加落盘；前端透传 `history` 不再使用（详见第 6 章）。

**与接缝契约的关系**：接缝契约 v1 是"单次纠错闭环"（`/api/process`）的确定性出参，**保留**供前端既有卡渲染；dialog 契约是"自由对话"的 planner 出参。两者不互斥。

## 第 4 章 · 教学法设计

### 4.1 语言分层（教学层英文 + 内容层中文）

**边界**：

```
英文（教学层）                      中文（内容载体，永不翻译）
UI 导航/按钮/设置/toast            被检查的学习者句子
planner 对学习者说的话              偏误片段 / 修正句
explainer 讲解正文（英壳）          例句、词汇、句型
verifier 反馈（pass/partial/fail）  中文语法术语（量词/补语/语气词…）
fallback 降级文案                   偏误类型标签（语法-语序，图谱键）
生成单元 self_language=en 的正文    复习队列的知识点名
```

**关键规则**：
- `native_lang` 非 `zh`（含 "en"/"EN"/"英语"/"vi" 等一切非 zh 值）→ 英文模式；`zh` 或空 → 中文模式。注意 `"英语"` 描述的是英语母语者 → 英文模式。
- **语言由系统确定性注入，非 LLM 自觉传参**：`LANG_INJECTED_SKILLS = ("explain_error","verify_retell","generate_unit")`，注入发生在 trace 记录**之前**（前端成果卡看到的即实际下发参数）。
- **语言政策分级比例**（0.19 项12 定稿）：讲解/说理用母语壳、句子/词汇保持中文（不翻译掉要学的中文）；母语比例随 HSK 渐退：HSK1–2 以母语壳为主、中文示例兜底；HSK3 中英混合；HSK4+ 以中文为主、仅关键处给母语提示。**非英语母语初学者不强制英文**。
- 英文渐褪出（HSK4-6）本版未做等级联动，等级自适应留后续。

### 4.2 介入时机（三档 + 打断上限）

**设计哲学**：能交流就不打断，卡住才出手。确定性函数（非 LLM 自觉）：

```
def decide_intervention(state, interrupt_used, cap) -> "none"|"light"|"block":
  if interrupt_used >= cap: return "none"            # 打断上限 → 静默
  ask_help = detect_help_intent(state.text)          # 主动求助
  empty    = len(state.text.strip()) < 3             # 输出空/犹豫
  unclear  = state.max_conf < 0.55                   # 含义不清（识别置信低）
  streak   = recent_error_rate(state, 5) >= 0.6      # 近5句≥3错
  if ask_help or unclear or empty or streak:
    if ask_help or unclear: return "block"           # 语义阻断 → 上讲解(含归因)
    return "light"                                   # 其余 → 引导提问，不下结论
  return "none"                                      # 流利产出 → 静默记录
```

- **升级规则**：`light` 后下一句仍 `unclear` → 自动升 `block`。
- **默认阈值**：`cap=3`（每场对话打断上限）、`max_conf<0.55`、`error_rate≥0.6(近5句)`。
- 主动求助正则宁漏勿错：精确匹配"问语言本身"句式（怎么说/什么意思/is it correct…）；泛化求助词（"help me"）与场景产出句（"帮我看看菜单"）不命中。
- **cap 优先于一切**：cap=0 时求助句也静默；`>120` 字视为学习材料，不识别不介入，交给 parse_document。

**recast 三档梯度（0.19 项8 定稿）**——**none 档（流利产出有隐错）**＝先整句正确 recast 覆盖需修正处，再**只轻点 1 个最关键错误**；不罗列、不讲规则、不打断节奏，错误照常后台入图谱。light＝引导性提问；block（求助/卡壳）＝才逐条点错+讲解。修复了"隐性反馈被显性点名破坏"。
- recast 教学文案收敛为**单一常量** `RECAST_DIRECTIVE_ZH/EN`，intervention 与场景 [Scene] 段共用同一口径，消除双份维护漂移。

### 4.3 persona 个性化层

字段（已拍板：只保留"回复风格"单字段，去掉 style/tone 双档）：

```json
{
  "reply_style": "default|rigorous|friendly|pragmatic|creative|socratic",
  "address": "如何称呼我（自由文本）",
  "identity": "AI 人设描述（自由文本）",
  "custom_instructions": "自定义规则（自由文本）",
  "interrupt_cap": 3
}
```

风格六档（英文教学层也按此执行）：`default` 跟随语言指令默认、`rigorous` 专业严谨、`friendly` 亲和友善、`pragmatic` 高效务实、`creative` 天马行空、`socratic` 启发引导。

**注入与共处规则**（0.19 项11 措辞定稿）：
- `POST /api/profile` 仅更新 persona 块，服务端为权威；前端「个性化」tab 保存即 POST。
- system 追加独立 `[Persona]` 段（与 GLOBAL_RULES/Scene 并列不冲突）；`identity` 优先于场景角色；`reply_style` 覆盖默认说话方式；`default` 回退语言指令默认。
- `interrupt_cap` 由服务端**确定性执行**（cap=0 求助也静默），brief 内仅作 LLM 告知。
- **措辞**："先扬后抑"→"先肯定再指正"（非教学术语且含贬义，中英双语统一）。

### 4.4 母语迁移带（L1 Transfer）

**精确定位**：母语迁移假设走**独立"候选假设 + 待确认"带，不进确诊图谱**。假设对象只读——不写偏误图谱（confirmed/pending 均不碰）、不进 ledger、不进复习队列；消费方仅 explainer（讲解明示母语成因）与前端展示。

**结构化决策**：
- 结构化迁移知识表，不靠 LLM prompt；独立候选带；先英语母语者高频迁移，可插拔。
- 规则落位 `datasets/transfer_rules_<l1>.json`（**非 data/**——data/ 被 gitignore，规则是分发资产）。
- 韩语(l1=ko) 用专用规则表；未知/空/未收录 l1 或表缺失/损坏 → 降级英文通用表并告警。韩语别名：korean/한국어/韩语/韓語/韩国语→ko。
- 规则表字段须含 `ref / strategy / nature`；en 表同步回填，ref 字段用户核验后定稿。
- 签名函数解耦：`_SIGNATURES` 以 sig 字符串为键，允许多个规则复用同一签名。

**匹配算法**：

```
match(errors, native_lang) -> list[TransferHypothesis]
  1) native_lang 为 zh 或空 → 返回 []（迁移只对非中文母语者）
  2) 对每个 error e，for rule in rules[native_lang]:
       if type 或 kp 命中 → 二次确认 signature 启发（宁漏勿错）→ append
  3) 任一条件不满足 → 不产假设（无命中默认不追因）
```

**假设对象字段**（并入识别结果独立字段，不进图谱 confirmed 边）：

```json
{ "rule_id": "en-order-num-adv", "l1": "en", "conf": 0.4, "status": "candidate",
  "fragment": "...", "l1_anchor": "母语习惯成因", "zh_signature": "中文典型表现",
  "correction": "修正建议" }
```

约束：`conf < 0.7` 永不到确认阈值；`status` 恒为 `candidate`（假设，不是确诊）。

**规则收紧纪律（0.19 项4/5/6 定稿）**：
- zh_signature 收紧：删"形容词+名词直连缺'的'"类（「漂亮衣服」合法）；只保留多层领属与代词/名词领属。
- 规则④加"非对比语境"限定（「他高，我矮」光杆形容词合法）。
- 新增 en-ba-avoidance（把字句回避）：英语母语典型迁移，anchor kp-ba-sentence、conf 0.38、走 hypotheses 候选层；真回避检测进 backlog（现有 `_is_legal_ba_disposal` 护栏防误报）。

### 4.5 教学语言注入的回落

- 全默认 persona 未配置 → 回落 0.21 语言指令默认（英文脚手架 + 中文内容载体）。

## 第 5 章 · 数据资产与评测

### 5.1 偏误图谱（唯一权威）

- **两段式**状态机：`ingest_error` → pending（疑似）→ `confirm_item` → confirmed；`get_review_queue` 排除待确认（宁漏勿错）。
- **写接口**：节点 upsert / 进待确认队列 / 幂等跳过 / 写失败局部降级不崩整体。
- **幂等键**：`event_key` 稳定（用实体本身做 key，不依赖进程内随机值如 `hash()`）。
- **confusion 边**：同句 ≥2 KP → 建混淆边；只画已确认的边。
- **mastery 初始值 = 0**；fail 分支不 touch `last_learnt_at`；未捕获确认侧（concept_confirmed）对确认键的临界行为均已回归锁定。

### 5.2 评测系统（tutor-quality 回归门槛）

**定位**：改 prompt/persona/技能/引擎后，能自动回答"这次改没改坏教学质量"——一个可复跑命令输出 pass/fail + 逐维度分 + red line。

**三层并联 judge**：

| 层 | 判什么 | 实现 |
|---|---|---|
| L1 程序断言 | 偏误定位（span/type/correction）、漏判/误报、复述验证有无执行 | 确定性代码 |
| L2 LLM-judge | 讲解完整度、话术自然度、语言分层、介入时机 | 独立 LLM 按 rubric 打分 |
| L3 红线硬判 | 见下 5 条 | 程序 + LLM 复核，单独一票否决 |

**6 维 rubric（各 1–5 分）**：
1. 偏误定位准确；2. 讲解四段完整；3. 复述验证严格（连续 2 次不过是否降难度、拒绝假懂）；4. 介入时机合理；5. 语言分层守约；6. 归因谨慎（不污染图谱）。

**5 条 red line**（触发任一 → 该 case fail，直接阻断）：
- R1 教错了（correction ≠ 黄金 correction）
- R2 误报干净句
- R3 漏了复述验证
- R4 流利时过度打断
- R5 归因污染图谱（把假设当事实写进图谱）

**回归门槛**：任一 red line 触发 → 整体 fail；`pass^k-style` 累计 pass 率 < 阈值（首版 **90%**）→ 门禁失败，写入测试套件。触发时机为开发/改动后跑回归，非用户对话时。

**目录形态**：`datasets/eval/tutor_quality/`（rubric.md / cases.json / run_tutor_judge.py / judge.py / README）。无 API Key → `--mock`（只跑 L1 + 红线，L2 跳过标记）。

**版本冻结**：每次跑记录模型、prompt 版本、case 版本、日期；case 冻结版本，改 case 需升版（对齐"冻结版本避免结果无法比较"）；LLM-judge 用 human gold set 校准（首版人工核 20 条 L2，报告与人工一致率）。

### 5.3 效果指标（可复现）

| 能力 | 关键指标 | 值 |
|---|---|---|
| 偏误识别（45 句黄金集） | F1 / 精确 / 召回 | 0.97 / 100% / 94.12% |
| | 干净句误报 / 对抗过度纠正 | 0% / 0 |
| 文件讲解（41 条） | 偏误分流正确率 | 94.1% |
| 复述验证（60 条） | 判定一致性 / 通过准确率 | 88.2% / 94.4% |
| 图谱数据层 | 幂等/单调性/写接口 | 18/18 PASS |
| M6 自由对话（真实实跑） | 技能轨迹命中（≥80%）| 86.7% / 80.0%（两轮连续达标）|
| | 终止率 / 平均步数 | 100% / ≤2 |

**评测三集拆分**（o5 定稿）：run_eval 的 F1 指标拆为种子偏误 / 干净对照 / 对抗 三集，报告含 bootstrap 置信区间，增加透明度。

**度量口径**：续学率 / 通关率 / 满意度（对话结束 1–5 星评分自动回写，指标随使用自动更新）等 4 指标带**口径文档**；对话级指标与数据闭环（`engine/metrics.py`）。

### 5.4 教学内容数据资产

- **HSK 引用本源**：《国际中文教育中文水平等级标准》GF0025-2021；syllabus 带 provenance 字段说明来源层级。
- **例句数据**：独立 `datasets/grammar_examples.json`（键=考纲 id，例句数组），不回写 syllabus 的 examples 字段。有明确 grammar 结构的按结构生成；grammar 为空标记 `auto_pending` 入审查清单，不硬填。

- **造题方式**：确定性挖空（从例句按语法点规则定位挖空位生成填空题，绑定考纲点）。
- **词表口径**：实测 "3208 / 1200"（stats.word_count/char_count），note 文案与实测一致。
- **诚实声明**：教学内容为**作者自审、未受教师仲裁**（三处背书式表述已改为诚实声明，非"经二语教师仲裁"）。

### 5.5 OCR + RAG

- **RapidOCR**（本地推理、零 API 费）：图片/PDF 一键转文本进纠错链；OCR 校正语料沉淀进检索索引，RAG 回答带来源。校正语料必须用**真实 OCR 引擎实测**生成的误读对，禁止人工构造候选数据。
- **RAG 引擎**（`engine/rag.py`，`HSKLexicalIndex`）：轻量倒排索引（posting list 缩小候选）、单字+术语白名单分词（不引 jieba）、coverage+phrase+术语词+标题/知识点加权打分、**三源合并**（知识清单+词表+偏误图谱，图谱是差异化卖点）。
- `retrieve_corpus`/`lookup_knowledge_point` **共享同一 RAG 索引实例**；索引每次 run 幂等 ingest_graph（节点只增不删）；pending 疑似项不进检索（宁漏勿错）。

## 第 6 章 · 记忆与画像

### 6.1 多轮对话记忆（LearnerMemory）

- JSON 文件 + tmp+rename 原子写（延续零依赖铁律，不用 SQLite/IndexedDB）。
- 存储：**messages 追加式 + 会话状态快照**（仿 OpenMAIC chat_message + chat_session_state）；隔离维度 `channel: learner_id : session_id`。
- 结构：`profile` 顶层显式块 + `sessions[]` 嵌套（含 id/title/status/message_ids/messages）；持久化裁剪窗口 `PERSIST_WINDOW=200`，注入窗口 20。
- 上下文注入：确定性摘要（最近 N 条 × 单条字符上限），非全量塞入。
- `to_llm_history()` 规范化：过滤 system/raw → 只透 user/assistant。
- **会话生命周期**：同一次纠错对话复用同一 `conversation_id`；切换知识点/课程/隔天开新 id；长期画像永远按 `learner_id` 跨 session 检索。

### 6.2 记忆 × 图谱打通（writeback 两段式 + error_ledger）

- **error_ledger**（通用 append-only 事件账本，每 learner 一个 JSON）：`KINDS = {"observation_error","repeated_error","concept_confirmed","concept_reviewed"}`；同 kp+signature 再现 → repeated_error；ring buffer 窗口截断控膨胀。
- **撤销记账语义**（已回归锁定）：
  - `repeated_count` 只数观察类事件（observation_error/repeated_error），确认/复习**不计入**（避免错 2 次+确认 1 次被误判惯犯）。
  - 确认事件改写 repeated_error 仅对 observation_error 生效（二次确认不误标）。
  - `latest_evidence` 只取观察类事件，确认后错误原句不被"复述验证通过"覆盖。
- **writeback 两段式**：`on_suspected`（疑似→pending）、`on_confirmed`（确认→记 ledger concept_confirmed + 更新图谱）、`on_repeated`（惯犯判定）、`review_queue`。
- **惯犯阈值 = ≥3**（宁漏勿错，防误报污染画像）。
- **画像注入**：`build_profile_summary(graph, ledger)` 每轮注入 planner system；`build_profile_facts` 写回 `mem.profile`（图谱×账本×记忆三线汇合）；写入失败仅记 degraded 通知，不阻塞对话。
- **措辞**："惯犯"→"高频×N"（如"你的高频知识点"），去标签化、降心理负担；代码内部字段 `repeat_offender` 保留。

### 6.3 检索/画像/记忆联动

- `retrieve_corpus` 每轮幂等 ingest_graph → 对话中新增已确认偏误下一问即可检索；pending 不进检索。
- verifier pass 触发 `on_confirmed`，fail 不 touch `last_learnt_at`（防"假懂"污染掌握度）。

## 第 7 章 · 工程铁律与协作约定

### 7.1 零第三方依赖

后端全部 Python 标准库，前端原生 JS+SVG 单页（零 npm/CDN），clone 即跑。例外依赖（RapidOCR/pymupdf）为可选，缺失时自动降级不污染其它功能。

### 7.2 确定性编译原则（继承自 0.8 Archify 启示，已落地）

LLM 产出 typed JSON → 确定性校验 → 自包含交付，是一条可规模化的可靠流水线——**LLM 只做理解，确定性层保可复现**。六条原则（P1–P6）在本项目对应：
- P1 authoring/schema 分离但互指（接缝契约与 schema 是机器真源，文档引用不重抄）
- P2 诊断按稳定 code + evidence + supportedFixes（可被机器消费）
- P3 修复有 priority（先正确性，后美观）
- P4 语言一致性：不支持就明说，不静默降级
- P5 证据与叙事分离（宁漏勿错在架构层的同构）
- P6 确定性布局 + 自包含交付

**稳定诊断码全集**（生成单元校验器 `GenerationUnitValidator`）：`code_invalid_json` / `code_unknown_type` / `code_missing_required` / `code_field_wrong_type` / `code_task_kind_invalid` / `code_forbidden_missing` / `code_keypoints_empty` / `code_postponed_not_null` / `code_context_mismatch` / `code_title_dup` / `code_title_too_long` / `code_question_count_high`。

### 7.3 生成引擎流水线（authoring → LLM → 校验 → 自愈 → 写回）

```
build_*_prompt → LLM.chat_json_strict → GenerationUnitValidator
                    │ 失败/非法JSON            │
                    ▼                          ▼
       更新槽位 ◀──诊断反馈(repair_feedback) 有诊断→拼接修复提示重试（自愈，max_repairs=1）
                                              │ 仍失败
                                              ▼
                              写回图谱(可选 practice.targets_errors) → 降级结果
```

- `chat_json_strict`：JSON mode + 重试 1 次 + 降级抛 `JSONStrictError`，不静默透传坏结果。
- 校验器返回按 repair_order 升序（先正确性后结构）。
- **默认不自动写回图谱**，由编排层显式 `write_back=True` 调用（守"图谱唯一权威、无自由发散"）。

### 7.4 skill 参数校验（schema + 自纠）

- 每个技能带 input/output schema；`validate_params()` 零依赖轻量校验器（type/required/enum/properties）。
- **宽松纠正取向**：LLM 常见错型自动纠正（'3'→3、'true'→True、enum 大小写不敏感匹配）；不可安全纠正的（缺必填/空值、bool 硬当 int、array/object 形态错、enum 越界）返回结构化错误；未声明字段放行（planner 常带上下文字段，宁宽勿严）；array 不自动包装（掩盖形态错误更危险）。
- 调用前校验失败 → 技能不执行 + `skill_error_reply` 喂回 LLM 下一轮自纠（**不打 fallback**，对标 is_error tool_result 模式）；MAX_STEPS=6 兜底防死循环。
- **注意事项**：Python bool 是 int 子类须先排除。

### 7.5 防编造与关键教学约束（必写进系统层）

- **防编造等关键指令必须写进 GLOBAL_RULES**（planner 拼进 system），**不能只放在技能 metadata.guardrails**——后者对 LLM 不可见，LLM 自由裁量会打破设计。
- **确定性判定死守**：若判断只靠 prompt 指令落地，LLM 自由裁量会打破设计；关键教学行为约束应写成最高位硬规则 + 给替代出口。

### 7.6 发布预检四道闸

对外推送到共享仓库前必须全过：
①**安全**（扫密钥 sk-/ghp-/xox + 真实 .env 不入库只留 example）；②**隐私**（扫个人身份/本地绝对路径/真实邮箱）；③**合规**（License + 数据来源声明 + 第三方原始语料不入库）；④**门面**（README/测试数/功能态校准到真实）。
- **凭据一旦进入"会留存"的上下文一律按已泄露处理**，明确通知轮换。
- README 是"可复现"承诺第一关，数字/状态必须与真实同步。

### 7.7 代码与工程注意（防回归）

- **消息/文本编码**：Powershell `Invoke-RestMethod` 发中文 body 会按非 UTF-8 编码损坏；回测须用 Python UTF-8 字节请求。
- **mock.patch 命名空间**：patch 需打在模块**实际导入**的命名空间，而非源模块（如 `engine.generation.why` 里 `from engine.llm.client import LLMClient`，测试应 patch `engine.generation.why.LLMClient`）。
- **CI pipefail**：GH Actions 默认 `bash -e -o pipefail`，凡"匹配 0 行/0 文件"的 grep/find/wc 都会误红；数非注释非空行用 awk（恒定退出 0）或管道尾加 `|| true`。
- **测试替身描述符陷阱**：`setUpClass` 里存函数为类属性，测试方法中 `self.llm` 实例访问会把函数绑定为方法（隐式多 self 参数 → TypeError）；用 `type(self).llm` 或对象替身。
- **环境依赖单测必须显式隔离全局配置**：本机 .env 有真实 Key，不 patch 会渗透进断言。
