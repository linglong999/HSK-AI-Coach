# 0.21 · 教学语言分层（英壳 + 中文内容载体）

> 日期：2026-09-02 · 界面 + 讲解英文化（面向英语母语学习者）
> 状态：已实现，测试 285 全绿（260→285）

## 一、背景与决策（用户拍板）

**问题**：项目面向外国留学生，但界面、讲解、错误提示全是中文——对 HSK1-2 初学者是双重认知负担（既要学中文内容，又要用中文界面理解"为什么错"）。

**调研结论**（HelloChinese / Duolingo / LingoDeer / Pleco 等主流中文学习产品）：
- 教学层（讲解、错误标签、引导语）用**学习者母语**（英语）
- 内容层（例句、词汇、句型、被检查的句子）保持**中文**
- 英文脚手架随等级**渐褪出**：HSK1-2 重英文，HSK4-6 逐渐全中文

| 决策点 | 结论 |
| --- | --- |
| 改造深度 | **界面 + 讲解英文化**（推荐项，用户拍板），不是全量翻译 |
| 语言边界 | 教学层英文；内容载体（原句/修正句/例句/词汇/中文语法术语）永远中文 |
| 默认语言 | 新用户默认 **en**（`--lang en` + 前端 localStorage 默认）；可切 zh 全中文 |
| 语言来源 | **系统约束，非 LLM 自觉**：planner 确定性注入技能参数，不依赖模型自觉传参 |
| 词表/图谱/知识点 | **不动**：偏误类型标签（"语法-语序"）、图谱节点名、HSK 词表均为数据层，保持中文 |
| 向后兼容 | 后端各接口 `native_lang` 缺省 = 空串 → 行为与 0.20 完全一致（全中文）；既有 260 测试零改动 |

## 二、语言分层边界

```
英文（教学层）                      中文（内容载体，永不翻译）
─────────────────────────          ─────────────────────────
UI 导航/按钮/设置/toast            被检查的学习者句子
planner 对学习者说的话              偏误片段 / 修正句
explainer 讲解正文（英壳）          例句、词汇、句型
verifier 反馈（pass/partial/fail）  中文语法术语（量词/补语/语气词…）
fallback 降级文案                   偏误类型标签（语法-语序，图谱键）
解析失败 [format_error] 重试喂回     key_points 中文要点原文
生成单元 self_language=en 的正文    复习队列的知识点名
```

判定规则：`native_lang` 非 `zh`（含 "en"/"EN"/"英语"/"vi" 等一切非 zh 值）→ 英文模式；`zh` 或空 → 中文模式。注意 `"英语"` 是非 zh 值 → 英文模式（"英语"描述的就是英语母语者）。

## 三、后端改造（native_lang 全链路）

```
前端语言开关 (localStorage hsk-lang, 默认 en)
  │  POST /api/dialog {text, native_lang}
  ▼
serve._do_api_dialog
  native_lang = payload.native_lang（缺省回落启动参数 --lang → Router.native_lang）
  ▼
Planner.run(native_lang=...)
  ├─ _build_system → GLOBAL_RULES_EN（规则 8 LANGUAGE POLICY：英壳+中例句）
  ├─ 解析失败重试喂回 → 英文 [format_error]
  ├─ fallback_reply(reason, native_lang) → 英文降级文案
  └─ _inject_lang（确定性注入，trace 记录注入后参数）
       ├─ explain_error / verify_retell → 顶层 params.native_lang
       └─ generate_unit → EN 时注入 context.self_language + language_directive
  ▼
引擎层（判定逻辑零改动，只换文案/提示词）
  ├─ explainer: SYSTEM_PROMPT_EN（英壳+中例句约束）+ 英文 user prompt
  │             _fallback_explanation 英文模板（中文修正句保留）
  └─ verifier: pass/partial/fail 反馈英文；中文要点原文保留（_prompt_for_missing）
```

### 关键实现点

1. **`planner/loop.py`**
   - `GLOBAL_RULES_EN`：完整英文版全局规则，规则 8 显式 LANGUAGE POLICY（英壳+中例句，禁止把中文内容翻译成英文）
   - `LANG_INJECTED_SKILLS = ("explain_error", "verify_retell", "generate_unit")`：语言由系统注入而非 LLM 自觉传参（对标 0.18 guardrails 教训——关键指令必须进系统层）
   - 注入发生在 **trace 记录之前**：前端学习成果卡看到的 params 即实际下发参数
2. **`engine/explainer.py`**：双 system prompt（`SYSTEM_PROMPT_EN` 含 "LANGUAGE RULE: English explanation shell; Chinese for correct sentences, examples, and usage-rule terms"），降级模板双语
3. **`engine/verifier.py`**：判定/聚合逻辑不动；三档反馈文案双语；引导问题保留中文要点原文
4. **`planner/fallback.py`**：`_MSG_MAP_ZH/_MSG_MAP_EN` 双文案表
5. **`engine/serve.py`**：`--lang` 启动参数（默认 en）作为 API 直连用户缺省；前端 payload 恒优先

## 四、前端改造（web/index.html）

1. **i18n 字典**：`I18N = {en:{...}, zh:{...}}`，262 键全覆盖（静态文案 + 动态渲染 + toast + placeholder + aria-label + 内置 prompts）
2. **翻译基建**：`t(key)`（en→zh→key 回落）、`tf(key, map)`（{占位符}插值）、`setLang(l)`（持久化 localStorage `hsk-lang`）、`applyLang()`（data-i18n / -html / -ph / -title / -aria 五类属性 + 重渲染侧栏/地图/队列/模型选择器/设置 tab）
3. **设置面板新增「语言」tab**：English / 中文 两个选项，复用主题 swatch 样式，active 态反映当前语言
4. **`sendPrompt` 上送 `native_lang: LANG`**：对话主链教学语言跟随前端语言开关（服务端 `--lang` 仅作 API 直连缺省）
5. **默认 en**：`localStorage` 无记录 → 英文界面 + 英文讲解（新用户即目标用户）；老用户首次进入无 hsk-lang 记录也切英文——已有学习者需手动切回中文（已知取舍：目标用户是英语母语者）

## 六、review 修复记录

1. **trace 注入可见性**：语言注入原在 `_dispatch_action` 内部复制参数，trace 记录的是注入**前**参数——前端成果卡与调试看不到语言约束实际生效。修复：注入移到 `run()` 循环内 trace 记录之前。
2. **generate_unit 语言缺口**：生成单元是教学层内容（费曼卡渲染给学习者），但未被列入语言注入——EN 模式下 planner 说英文、生成的单元却是中文壳。修复：`_inject_lang` 对 generate_unit 在 EN 时注入 `context.self_language` + `language_directive`（引擎既有字段，zh 是引擎默认不动；LLM 已显式给的 directive 不覆盖）。
3. **测试替身陷阱**（Python 描述符协议）：`setUpClass` 里 `cls.llm = lambda ...` 存为类属性后，测试方法中 `self.llm` **实例访问会把函数绑定为 bound method**（隐式多出 self 实参 → planner 调用 TypeError → 500）。修复：类访问 `type(self).llm`。既有测试用 `ScriptLLM` 对象（非函数）无此问题——函数类属性经实例访问才触发绑定。
4. **前端验收线**：JS `node --check` 通过；`$()` 引用 44 个 id 全部存在（gRoot 为运行时创建的 SVG 根，误报排除）；200 个 i18n 引用键 en/zh 两侧全覆盖；反引号 206 偶数平衡（0.19 单/反引号混淆教训的例行检查）。
5. **隐性真实 LLM 调用清零**（既有问题，本次 review 连带修掉）：网络层探针（patch `urllib.request.urlopen` 计数）发现既有套件有 2 个用例的识别器未注入替身——`test_planner.PlannerLoopTest.test_agent_calls_skill_then_text` 与 `test_serve_dialog.PlannerTraceTest.test_trace_on_success_and_fallback`。`.env` 有真实 Key 时每次全量测试都会**真调 DeepSeek**（隐性花钱 + 非确定性：断言不依赖识别结果所以照样绿，直到 Key 失效才暴露）。修复：两处注入 `FakeRecognizer`。修后探针复核：全量 285 测试 **0 未 mock 网络调用**，耗时 27.6s → 13s。双语测试自身同步加固：PlannerLangTest 注入假 explainer/generation（断言升级为"引擎实收参数"），修前该模块单跑 18.9s（含约 17s 隐性真实调用），修后 1.3s / 0 调用。

## 七、已知边界（设计内）

- **图谱/词表/知识点数据层不动**：偏误类型标签（"语法-语序"）、知识点名保持中文——它们是图谱键与内容本体，翻译会造成数据层分叉
- **英文渐褪出（HSK4-6 减英文）**：本版未做等级联动——当前是"EN 全量脚手架"，等级自适应英文褪出留待后续（需在 prompt 层按 user_level 调节 LANGUAGE POLICY 强度）
- **M6 评测**：黄金集/评测脚本走缺省 native_lang（中文模式），协议与阈值零改动
- **generate_unit 经 `/api/generate` 直连**：`language_directive`/`self_language` 由调用方显式传（0.16 既有行为，不强制）
