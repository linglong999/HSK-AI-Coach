## 1. 定位（复制 agent-design M9 目标）

建立**分能力域**工具注册表，落地 `web_search` + `parse_document` 两个文字工具；语音（ASR/TTS）留 provider 位，不破坏零依赖。全程**仅标准库**，引擎一律不改动。

## 2. 已确认设计决定（agent-design，直接采用）

| 决策点 | 结论 |
|--------|------|
| 注册表组织 | **分能力域**：web_search / parse_document / asr / tts 各一张 provider 表 + 一个路由函数，外加薄统一门面 `call_tool` 给 planner |
| 外部接入 | **配置驱动、默认关**：注册 + 接口就位，配了 provider/key 才启用；未配 key 返回"未配置"提示，不崩 |
| 语音范围 | **只落文字工具**：web_search + parse_document；ASR/TTS 留 provider 位默认关 |

## 3. 借鉴 / 偏离 OpenMAIC（一手）

| 点 | OpenMAIC 源 | 本项目落地 |
|---|---|---|
| provider 注册表独立于实现 | `lib/web-search/constants.ts` `WEB_SEARCH_PROVIDERS` | `tools/registry.py` 每能力域一张表 |
| switch(provider) 路由分发 | `lib/web-search/index.ts` `searchWeb()` | 每能力域一个路由函数 |
| 未配置 key 分层语义 | `app/api/web-search/route.ts` `MISSING_API_KEY` / Brave 优雅降级 | 统一返回结构化 **`not_configured`**（不崩，planner 可据此提示用户） |
| 配置驱动 / 默认关 | `lib/server/provider-config.ts`（server-managed/disabled） | env + `.env`（复用 settings.py `_load_dotenv`）|

**偏离（守零依赖 / 更稳）**：
- OpenMAIC 是 Node/多依赖 → 本项目**纯 Python 标准库**（urllib/json/os）。
- OpenMAIC 多 provider + HTML scrape fallback → 本项目**不做脆弱 scrape**，未配 key 即 `not_configured`（宁漏勿错）。
- 白名单 per-user 证据薄弱 → 本项目明确并入 `call_tool`，默认放开两个文字工具。

## 5. 设计细节

### 5.1 `registry.py` — 能力域注册表（配置驱动、默认关）

```python
# 每能力域一张 provider 表 + 配置驱动判定
CAPABILITY_DOMAINS = {
  "web_search": {
    "default_provider": os.getenv("WEB_SEARCH_PROVIDER", ""),  # 空 → 默认关
    "providers": { provider_id -> {name, requires_key, api_key_env, call} },
  },
  "parse_document": {...},
  "asr": {...}, "tts": {...},   # provider 位，默认关
}

def resolve_provider(domain, provider_id=None) -> (config, error)   # 未配置 → 明确 error，不 raise
def is_enabled(domain) -> bool
```

- provider 配置字段：`id / name / requires_key / api_key_env / default_base_url / call`（贴 OpenMAIC `WebSearchProviderConfig`）。
- 配置驱动：`WEB_SEARCH_PROVIDER`、`TAVILY_API_KEY` 等 env + `.env`。

### 5.2 `__init__.py` — 薄统一门面 `call_tool`

```python
def call_tool(name, provider=None, params=None, learner_id="default", role="learner") -> dict:
    # 1) 白名单：learner/role 不在允许集 → {"ok":False,"status":"tool_not_allowed"}
    #    默认放开 web_search + parse_document（贴 agent-design「默认放开」）
    # 2) 分发到能力域路由；未配置 → {"ok":False,"status":"not_configured"}
    #    路由内 try/except → 结构化 error，绝不抛异常
```

返回统一结构：`{"ok":True,"name","provider","data"}` 或 `{"ok":False,"status":"not_configured"|"tool_not_allowed"|"error","message"}`。

### 5.3 `web_search.py` — 网页搜索路由（配 key 即可用）

- `search(provider_id, query, max_results)`。
- 未配 key → `{"ok":False,"status":"not_configured","message":"请在 .env 配置 WEB_SEARCH_PROVIDER 与对应 key"}`，**不崩**。
- 配了 → 经 **`urllib`** 请求配置的搜索 API；**transport 可注入**（对齐 planner 的 llm_call 注入模式），测试零网络依赖。
- 返回 `results[]`（title/link/snippet）。

### 5.4 `parse_document.py` — 文档解析路由

- 本地解析：文本（UTF-8 原样）、简单文档。
- 输出块结构 `{"ok":True,"blocks":[{"type":"text","text":...}]}`。
- 复杂输入（PDF/Office）→ 走 provider 位默认关，返回 `not_configured`；本地失败 → `{"ok":False,"status":"error"}`，不崩。

### 5.5 `asr_providers.py` / `tts_providers.py`

仅 provider 注册表（id/name/requires_key/api_key_env/call 接口）**默认关**。`call_tool("asr"|"tts",...)` 一律 `not_configured`，供 future `pronunciation_assessment` 启用。

## 6. 对接 planner（M1 已登记，M9 落地可用）

- M1 技能清单已登记 `web_search`(#10)/`parse_document`(#11) 预留位。M9 加两个**薄 skill**（包 `call_tool`），`build_registry()` 注册后 `planner.registry.list_all()` 自动可见。
- `GLOBAL_RULES` 可选补一行："查最新/未知资料→web_search；上传文本/文档求知→parse_document"。
- planner `_dispatch_action` 已兼容：工具 `not_configured` 作为 `tool_result` 喂回，**不崩**。

## 7. 边界声明（守铁律）

- **零依赖**：仅标准库（urllib/json/os/re），不引入 requests/bs4。
- **不建复杂引擎**：web_search 不落 HTML scrape；parse_document 不在本地做复杂 PDF/OCR。
- **配置驱动默认关**：`not_configured` 是正常路径不是异常。
- **不污染图谱/画像**：工具结果只作为 `tool_result` 喂回，不自动写记忆（延续 M5/M8 边界，宁漏勿错）。
