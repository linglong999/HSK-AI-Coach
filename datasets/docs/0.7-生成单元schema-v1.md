# 生成单元 Schema v1 · 设计文档

> **对齐**：模型/讲解引擎的响应式诊断型教学 —— 借鉴 OpenMAIC"两阶段生成 + 强 schema"，但落为**对话驱动的回合级生成单元**，而非整节自足课堂。
> **版本**：v1（首发单元 explain + practice；dialogue/interactive/pbl 后置建类型位）
> **参考**：OpenMAIC（https://github.com/THU-MAIC/OpenMAIC），取其轻量方法论，弃其多智能体编排内核。

---

## 0. 一句话定位

> **生成单元变小，方法论不变。**

OpenMAIC 是空白知识传授 —— 对象啥都不会，从零"生成一整节课"（SceneOutline → slide/quiz/interactive）。
我们是**响应式诊断型教学** —— 对象带着偏误来，需要"对症当下那一口"，所以生成单元从"一节"降到"一个回合"。

这不推翻 OpenMAIC 的方法论（两阶段剥壳、强 schema 带 keyPoints + 前置护栏、上下文按需注入、JSON 自愈、语言指令），
而是把同一套原则**作用对象降一档复用**。

## 0.1 产品哲学对比（为何不照搬编排）

| 维度 | OpenMAIC | 本项目 |
|---|---|---|
| 类型 | 生成型（凭空造一堂课）| 诊断型（识别偏误 → 纠偏）|
| 目标 | 丰富、沉浸、覆盖广 | 准确、不污染、可复现 |
| 对话模型 | 多智能体自由讨论（AI 老师 + AI 同学辩论）| 对话式教学闭环（学习者 ↔ 一个 AI 老师，回合化讲解/提问/检验）|
| 结构性 | 生成整节自足课堂 | 生成一个回合的小片段，靠上下文 `previousSpeech`/`curriculumAt` 锚定 |

**关键裁定**：
- 要 **A. 对话式教学闭环**（学习者 ↔ 单个 AI 老师，可控、可校验、贴合费曼）—— 这是首发 shape。
- 弃 **B. 多智能体自由讨论**（发散、贵、难守"宁漏勿错"，与偏误图谱权威冲突）。对话可自由，**图谱写入必须走权威边**。

---

## 1. 范围声明（坚持"宁漏勿错"）

**本次（v1）仅实现两个首发单元**：
- `explain` 费曼讲解片段（命根之一）
- `practice` 练习，接纠偏链（命根之二）

**其余三个后置（建类型位 + `*Spec?: null` 后门，不实现）**：
- `dialogue` 情景对话
- `interactive` 交互小件
- `pbl` 任务项目

后门目的：先占字段槽，避免以后加类型时契约/后端 dispatch 要大改。枚举位必须保留，否则 dispatch 丢分支提示。

---

## 2. Schema 本体（v1.1 终版）

```ts
// ===== 场景类型枚举（dialogue/interactive/pbl 后置，仅类型位+后门）=====
type SceneType =
  | 'explain'      // ✅ 首发：费曼讲解片段
  | 'practice'     // ✅ 首发：练习（接纠偏链）
  | 'dialogue'     // 🔒 后置：情景对话（仅类型位）
  | 'interactive'  // 🔒 后置：交互小件（仅类型位）
  | 'pbl';         // 🔒 后置：任务项目（仅类型位）

// ===== 通用上下文（跨回合连贯 + 多语言 + 图谱锚定）=====
interface UnitContext {
  previousSpeech?: string;        // 上一回合末尾（按需注入一小口，防上下文爆炸）
  allTitles: string[];            // 本场已产出标题，保持连贯
  languageDirective?: string;     // 指令驱动多语言（越/韩/日走这）
  curriculumAt: string;           // 此刻图谱位置（待复习/待巩固点），只读引用
}

// ===== 生成单元地基（四类共用）=====
interface UnitBase {
  id: string;
  type: SceneType;
  title: string;
  keyPoints: string[];            // 正向知识（只装该懂的正向，不装纠错指令）
  forbidden_errors: string[];     // 前置护栏（生成前框死不该犯的）
  context: UnitContext;
  self_language?: 'zh'|'vi'|'ko'|'ja';
  // ---- 后门占位（本次仅建类型位，不实现）----
  dialogueSpec?: null;            // TODO(postponed): 情景对话契约
  interactiveSpec?: null;         // TODO(postponed): 交互小件规格
  pblSpec?: null;                 // TODO(postponed): 任务项目契约
}

// ===== 两个首发单元 =====
interface ExplainUnit extends UnitBase {        // 费曼讲解片段
  type: 'explain';
  for_keypoint?: string;            // 锚定当前知识点（"这一口"的定位）
  teachingObjective: string;        // 教学目标
  estimatedDuration: number;        // 预估时长（秒/分钟）
}

interface PracticeUnit extends UnitBase {       // 练习，写回偏误图谱
  type: 'practice';
  for_keypoints: string[];          // 关联的知识点
  targets_errors?: string[];        // 针对哪些偏误（写回 confirmed/pending）
  task_kind: 'fill'|'mcq'|'rephrase'|'correct'|'open-ended';
  questionCount: number;
  difficulty: 'easy'|'medium'|'hard';
}

type Unit = ExplainUnit | PracticeUnit;
```

## 3. 关键设计说明

1. **`keyPoints` + `forbidden_errors` 借自 OpenMAIC，但改造为服务偏误图谱**：
   - `keyPoints`：只装正向知识（呼应已验证教训 "key_points 只能装正向目标知识"）
   - `forbidden_errors`：前置护栏，生成前就框死不该犯的 —— 与`宁漏勿错`同源。
2. **对话驱动具象化在 `context.previousSpeech` + `curriculumAt`**：
   - 每个单元是"一个回合"，通过"上一口"和"图谱当前位置"锚定，**不做自足课堂**。
   - 直接落实上一轮讨论的分歧——生成单元变小，方法论不变。
3. **后门 = 枚举位 + `*Spec?: null`**：先占字段槽；实现放下次。
4. **`practice.targets_errors` 的关键作用**：明确练习结果要**写回偏误图谱**（化为 confirmed/pending）。
   这是本项目区别于 OpenMAIC 的最硬一点 —— 它不是自缓冲和，是**闭环**。

---

## 4. 从 OpenMAIC 架构吸收的 5 个轻量模式（供前端壳/服务层参考）

本项目**不照搬**其重型 Next.js monorepo（SSR + LangGraph + Canvas 编辑器），但以下模式可吸收：

1. **前端壳 = 薄壳 + API 门面**：`app/api/` 是唯一端点边界。本项目 serve 应保持"薄壳 + 几个端点"，生成/校验全走端点。
2. **两种响应式范式**：异步生成 = 提交 + 轮询（`generate-classroom`）；长对话 = SSE 流式（`chat`）。
3. **回放状态机**（`lib/playback`: idle → playing → live）：做复述/播放/交互时的干净状态抽象。
4. **动作执行引擎**（`lib/action`: 生成的结构化动作 → 执行）：生成动作与执行解耦。
5. **LLM 抽象层**（`lib/ai`）：把服务商抽成接口，接入/替换模型不动业务。

**最有价值的交叉启示**：OpenMAIC 把"一节课"当**可回放/可暂停/可 live 的状态对象**（`app/<classroom>/[id]`）。本项目同理：**"一场对话纠偏"是一个可进出的状态对象**，不只一个静态响应流。

---

## 5. 多语言（含越/韩/日）点位

- `UnitBase.self_language`：本单元目标语言（zh/vi/ko/ja）。
- `UnitContext.languageDirective`：指令驱动多语言，供讲解/回答按学习者语言输出。
- 后续随 languageDirective 扩展，不做独立多 agent 分支。

---

## 6. 验收口径（后续实现时）

- 三个后置单元（dialogue/interactive/pbl）：**不生成、不渲染、不出现在 dispatch 逻辑**，仅枚举/类型位存在。
- 首发两单元产出必须过 schema 校验（强 schema，剔除注释，JSON 合法）。
- 多语言前提下，讲解/回答须遵循 `self_language`。
- 保留一条 `多一点：弃 B（多智能体自由讨论），守 A（对话式教学闭环）`的架构裁定，作为演进红线。

## 7. 字段级取舍说明（逐字段）

> 每个字段问三件事：**为什么需要** / **必选还是可选** / **取舍点在哪儿**。凡标注「呼应」均指向本项目已落盘的教训或铁律。

### 7.1 `UnitBase` 共用字段

| 字段 | 必选? | 为什么 & 取舍 |
|---|---|---|
| `id` | ✅ 必 | 供前端壳节点 / 偏误图谱写回用；同一场对话内唯一。取舍：全局唯一没必要，场级唯一即可（省去跨场协调）。|
| `type` | ✅ 必 | dispatch 分支的判据。取舍：必须是**字符串联合类型**而非自由 string —— 否则后置单元会悄悄漏检。|
| `title` | ✅ 必 | 用于 `allTitles` 连贯 + 前端展示。取舍：短（一句话以内）；字段级唯一由 `allTitles` 校验，防标题重复导致图谱节点歧义。|
| `keyPoints` | ✅ 必 | **正向目标知识**（呼应教训：key_points 只装该懂的正向，不装纠错指令）。取舍：非空才合格；解码侧校验非空，空则重生成。|
| `forbidden_errors` | ✅ 必 | 前置护栏，生成前框死"不该犯的"，与宁漏勿错同源。取舍：允许空数组（合法句），但**存在时不可缺省**——缺省意味着护栏失效。|
| `context` | ✅ 必 | 承载回合连贯 + 图谱锚定。取舍：对象分组而非平铺字段，避免上下文爆炸 & 便于整体注入。|
| `self_language` | ⭕ 选 | 单元目标语言。取舍：默认 zh；非 zh 时须同时给 `languageDirective`，否则多语言指令落空。|

### 7.2 `UnitContext` 字段

| 字段 | 必选? | 为什么 & 取舍 |
|---|---|---|
| `previousSpeech` | ⭕ 选 | 上一回合末尾，按需注入"一小口"防上下文爆炸。取舍：**只注入最近一口**，不注入全量历史 —— 是"对话驱动"的落点，也是防发散的关键。|
| `allTitles` | ✅ 必 | 本场所有标题，保连贯、防图谱节点重名。取舍：由服务层维护，不进校验但进生成 prompt。|
| `languageDirective` | ⭕ 选 | 指令驱动多语言。取舍：覆盖越/韩/日；不走独立多 agent，避免编排复杂度。|
| `curriculumAt` | ✅ 必（只读）| 此刻图谱位置（待复习/待巩固点）。取舍：**只读引用，不参与写回** —— 守卫"图谱唯一权威、无自由发散"。|

### 7.3 `ExplainUnit` 字段

| 字段 | 必选? | 为什么 & 取舍 |
|---|---|---|
| `for_keypoint` | ⭕ 选 | 锚定当前知识点（"这一口"的定位）。取舍：空 = 通用讲解；有 = 定点讲解。这是费曼"讲清楚一个点"的最小粒度。|
| `teachingObjective` | ✅ 必 | 教学目标，驱动讲解不跑题。取舍：一句话；与 `for_keypoint` 若有，须一致，否则讲解方向漂移。|
| `estimatedDuration` | ✅ 必 | 预估时长。取舍：不用来硬限生成，只用于前端节奏展示 + 提示词里"别超"软约束。|

### 7.4 `PracticeUnit` 字段

| 字段 | 必选? | 为什么 & 取舍 |
|---|---|---|
| `for_keypoints` | ✅ 必 | 关联知识点数组（比 Explain 的 `for_keypoint` 多，因为练习可综合多知识点）。|
| `targets_errors` | ⭕ 选 | 针对哪些偏误。**关键作用：练习结果由此写回偏误图谱（confirmed/pending）** —— 这是闭环的最硬点，非自缓冲和。取舍：空 = 只巩固、不写回；有 = 接纠偏链。|
| `task_kind` | ✅ 必 | `fill | mcq | rephrase | correct | open-ended`（open-ended 支持费曼自由输出/复述）。取舍：enum 而非自由 string，保证渲染器能对应到实现。|
| `questionCount` | ✅ 必 | 题量。取舍：防御飞雷 —— 定上限（如 ≤10），防生成失控。|
| `difficulty` | ✅ 必 | easy/medium/hard。取舍：默认由服务层按当前图谱掌握度定，不信任生成侧自报，避免难度虚标。|

### 7.5 后置单元字段（`*Spec?: null`）

| 字段 | 取舍 |
|---|---|
| `dialogueSpec` / `interactiveSpec` / `pblSpec` | **只占字段槽，本次不实现**。取舍：置 `null` 而非整段删除 —— 删除会让以后加类型时契约重改、dispatch 丢分支提示；保留 `null` 是"显式占位 + 承诺未来"的轻量做法。|

## 8. 取舍总纲（一句话版）

- **为何单选对话式闭环**：费曼是双向检验（你讲我听、我检验你懂没懂），不是单向讲课；多智能体自由讨论无法"宁漏勿错"。
- **为何生成单元变小**：响应式诊断型教学是对当下"这一口"对症，不是预先铺完一整节。
- **为何强 schema**：可复现、可校验、可写回 —— 数据即证据，缺陷即契约。
