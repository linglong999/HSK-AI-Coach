## 1. 设计决策（已拍板）

| 决策点 | 结论 |
|--------|------|
| 判据构成 | 过程判据（自动，零外部 LLM）+ 结果判据（LLM-judge） |
| judge 判分结构 | **诊断型乙**：`{score, maxScore, passed, comment, strengths[], improvements[]}` |
| 无 Key 策略 | **只跑过程判据**；结果判据留白待有 Key（不 mock 假 judge） |
| JSON 解析失败 | **标注 `scorable: false` 不记入**（不照 OpenMAIC 给一半分，守宁漏勿错） |
| 黄金集规模 | **15 条**（偏误/纯提问/边界/多轮四类） |
| 合格阈值 | 80%（earned ≥ 满分的 80% → 合格），**代码层判定不靠 LLM 自觉** |
| 对齐现有 | 复用 `run_eval*` 风格，新增 `run_eval_agent.py`，不碰既有测试 |

## 2. 借鉴/偏离 OpenMAIC（一手结论）

### 可借鉴（源文件）

| 借鉴点 | 源 | 本项目落地 |
|--------|-----|-----------|
| 短答评分输入结构 `{question, userAnswer, points}` | `quiz-grade/route.ts` | judge `run()` 入参 |
| rubric 自然语言传参 | `quiz-grade/route.ts` | 结构化 `rubric` 字段 |
| LLM 输出从文本中提取 JSON `{...}` | `quiz-grade/route.ts`、`eval-tail-parser.ts` | 复用 `engine.llm.parse_json` 思路 |
| 诊断型结构 `feedback/strengths/improvements` | `evaluator.ts`（PBL evaluator） | `strengths[]/improvements[]` |
| 判分并行 prompt 多处提取健壮化 | `eval-tail-parser.ts`（fenced/multi-candidate） | judge 内多候选提取 |

### 偏离（守宁漏勿错，不照 OpenMAIC）

| OpenMAIC 做法 | 问题 | 本项目改法 |
|---------------|------|-----------|
| JSON 解析失败给一半分 `round(points*0.5)` | 臆造分数，违背宁漏勿错 | 标注 `scorable:false`，该条不记入达标率 |
| 合格阈值写在 prompt 里（PBL `60+ continue`） | 不可控、不可测 | 阈值提到**代码层**显式 `pass_score` |
| `commentPrompt` 字段名 | 语义偏"评语提示" | 改名 `rubric`（评分要点） |
| 纯 `score+comment` 单维 | 不适学习诊断 | 增 `maxScore/passed/strengths/improvements` |

## 3. judge 判分结构（决策乙）

```json
{
  "score": 8,            // earned 得分（0..maxScore，仅 scorable 时有效）
  "maxScore": 10,
  "passed": true,        // 代码层判定：score >= maxScore*0.8
  "comment": "…",
  "strengths": ["…"],
  "improvements": ["…"],
  "scorable": true       // false = JSON 解析失败，本条不记入达标率
}
```

- `maxScore` 由用例或 judge 调用方指定。
- `passed` 由 `score / maxScore >= 0.8` 代码计算，**不信任 LLM 自评 pass**。
- 解析失败：返回 `{scorable: false, comment: "<默认>", maxScore, ...}`，不调用 `_judge_parse_failure` 算分。

## 4. 黄金对话集（`eval/agent_cases.json`，15 条）

每例结构：
```json
{
  "id": "c01",
  "input": "我想买苹果很多。",
  "expected_trace": ["identify_errors"],
  "expected_answers": ["苹果", "很多"],
  "checkable": true,
  "scenario": "偏误句",
  "max_score": 10,
  "rubric": "是否指出偏误、纠正正确、不含多余超纲"
}
```
覆盖四类（偏误 5 / 纯提问 4 / 边界 4 / 多轮 2），对齐 M6 文档。

---

## 5. 指标

**过程判据（自动，零外部 LLM）**
- 技能轨迹命中率：实际技能序列 vs expected_trace（≥80%）
- 终止率：6 步内必然终止（100%）
- 平均步数：≤6
- 异常率：技能异常占比（须为 0）
- parser 失败率：parse_json_array 失败占比

**结果判据（LLM-judge，need Key）**
- judge 判分达标率（scorable 且 passed）/ scorable 总条数


## 7. 验收标准

- [ ] `run_eval_agent.py` 跑 15 条，输出过程 + judge 两类量化指标
- [ ] 技能轨迹命中率 ≥ 80%；终止率 100%；平均步数 ≤ 6；无崩溃
- [ ] judge 判分达标率达可配置阈值（默认 earned ≥ 满分 80% 判合格）
- [ ] JSON 解析失败：标注 `scorable:false` 不记入，不臆造分数
- [ ] 既有测试全部 PASS，零新增依赖

---

## 8. 边界声明

- 无 Key 时仅跑过程判据，**judge 结果标注 "skipped(no_key)"**，不伪造。
- judge 复用既有 LLM 通道，不加框架依赖，"零框架"成立。
