## 0. 定位与总体结构

学习者在**场景对话**里开口习得为主；**纠错退为"卡壳才触发"的脚手架**；每次产出照常喂入偏误图谱积累资产；新增 **L1 迁移带**承接"母语归因假设"（不进确诊图谱）；学习者可用**个性化栏**自定义 AI 的说话方式。

```
习得主线：/api/dialog 场景对话（预置库起步 + 生成引擎扩写）· 学习者开口产出
   │── 每次产出 → 识别 → 偏误图谱(确诊) + L1迁移带(candidate)
   └── 仅卡壳 → 按需脚手架（轻介入→阻断）
数据底座：偏误图谱 · L1 迁移带 · 复习队列
个性化层：persona → 注入对话主链（与 0.21 语言指令共存）
```

与 0.21 关系：英文脚手架 + 中文内容载体不变；persona 控制"怎么说话"，GLOBAL\_RULES 控制"教学规则"，两组独立拼接。

### 1.1 起步规则表（`data/transfer_rules_en.json`，6 条）

> 规则挂到**已有偏误降类**（`type` / `kp_id`）上做第一层命中——识别先判型，再按 `l1+type` 查规则，避免字符级猜测。
> ⚠️ 执行第一步须先核对 `type` 值与引擎现有 taxonomy 对齐（下列 type 为占位名，以 `recognizer` 实际降类名称为准）。

| rule\_id           | 触发 type  | l1\_anchor（母语利脚）            | zh\_signature    | correction    |
| ------------------ | -------- | --------------------------- | ---------------- | ------------- |
| en-order-num-adv   | 语法-语序    | 英文 many(定语)/a lot(副词)是两个词   | 数量/程度副词后置「买苹果很多」 | 定语位：很多苹果      |
| en-classifier-loss | 语法-量词    | 英文无量词系统                     | 量词缺失「买三苹果」       | 三**个**苹果      |
| en-attr-de         | 语法-“的”结构 | 英文所有格 my friend's book 自带属格 | 中文“的”的该加未加/该省未省  | 我朋友的**书**     |
| en-wh-fronting     | 语法-语序-疑问 | 英文疑问词前置                     | 疑问词留守句首「什么你要」    | 你要**什么**      |
| en-aspect-particle | 语法-动态助词  | 英文时态外显                      | 了/着/过 缺失或误加      | 表完成加“了”       |
| en-be-adj-pred     | 语法-系动词冗余 | 英文 be+形容词                   | 系动词冗余「我是高兴」      | 我很高兴（形谓直接作谓语） |

### 1.2 匹配算法（`engine/transfer.py`）

```
match(errors, native_lang) -> list[TransferHypothesis]
  1) native_lang 为 zh 或空 → 返回 []（迁移只对非中文母语者）
  2) 对每个 error e：
     for rule in rules[native_lang]:
         if rule.type_matches(e.type) or rule.kp_matches(e.kp_id):
            # 二次确认：规整后的 fragment 满足 zh_signature 启发（宁漏勿错）
            if signature_hint(rule, e): append(hypothesis)
  3) 任一条件不满足 → 不产假设（无命中默认不追因）
```

### 1.3 假设对象与讲解

TransferHypothesis JSON（并入识别结果的独立字段，**不进图谱 confirmed 边**）：

```json
{
  "rule_id": "en-order-num-adv", "l1": "en",
  "conf": 0.4, "status": "candidate",
  "l1_anchor": "many(定语)/a lot(副词)是两个词",
  "zh_signature": "数量或程度副词后置",
  "correction": "定语位：很多苹果"
}
```

`explainer` 收到 `transfer` 假设 → 讲解里明示成因（D1.4），中文更正句保留（0.21 规则 8）。

### 1.4 契约：识别结果新增字段

`recognize` / `identify_errors` 结果在既有字段下增加 `hypotheses: TransferHypothesis[]`（缺省 `[]`）。**JSON 接缝契约 v1**：`errors[]` 结构不变，新增可选 `hypotheses`，旧消费方读取原字段不受影响（向后兼容）。

### 3.1 介入判定（确定性函数，max\_steps 经验类比）

```
def decide_intervention(state, interrupt_used, cap) -> "none"|"light"|"block":
  if interrupt_used >= cap: return "none"            # 打断上限 → 静默
  ask_help = detect_help_intent(state.text)           # 主动求助（求助意图）
  empty    = len(state.text.strip()) < 3              # 输出空/犹豫
  unclear  = state.max_conf < 0.55                    # 含义不清（识别置信低）
  streak   = recent_error_rate(state, 5) >= 0.6       # 近5句≥3错
  if ask_help or unclear or empty or streak:
    if ask_help or unclear: return "block"            # 语义阻断 → 上讲解(含归因)
    return "light"                                    # 其余 → 引导提问，不下结论
  return "none"                                       # 流利产出 → 静默记录
```

升级规则：`light` 后下一句仍 `unclear` → 自动升 `block`。

默认阈值：`cap=3`（每场对话打断上限）、`max_conf<0.55`、`error_rate≥0.6(近5句)`。

### 3.2 persona 个性化栏（前端 `settingsNav` 增 `data-tab="persona"`）

字段与枚举（用户拍板：只保留"回复风格"单字段，去掉 style/tone 双档）：

```json
{
  "reply_style": "default|rigorous|friendly|pragmatic|creative|socratic",
  "address": "如何称呼我（自由文本）",
  "identity": "AI 人设描述（自由文本）",
  "custom_instructions": "自定义规则（自由文本）",
  "interrupt_cap": 3
}
```

回复风格六档（英文教学层也按此执行）：
- `default`   默认（跟随 0.21 语言指令默认，不加额外约束）
- `rigorous`  专业严谨
- `friendly`  亲和友善
- `pragmatic` 高效务实
- `creative`  天马行空
- `socratic`  启发引导（引而不答，多提问）

### 3.3 注入格式（`serve._do_api_dialog` → 拼进 `_build_system`）

在 system 追加独立 PERSONA 段（与 GLOBAL\_RULES\_EN/ZH、Scene 段并列，不冲突）：

```

- 回复风格: 亲和友善
- 称呼我：小玲；你以「中文陪练友」身份陪我
- 自定义: 一次只聚焦一个错，别信息过载
- 打断频率上限：3 次/场
```

共处规则：`identity` 优先于 scene role；`reply_style` 覆盖默认说话方式；`default` 回退到 0.21 语言指令默认；与 0.21 语言指令并行不冲突。

| persona/场景冲突 | 人设与场景角色打架                | identity 优先于 scene role，约定优先级      |
| 契约破坏         | 前端误读新字段                  | 新增字段向后兼容 + 补 hypotheses 消费测试       |

## 7. 待确认残留点

1. 起步规则表 `type` 占位名执行前要与 `recognizer` 实际降类名对齐——此项为执行时程序性核对，无需你决策。
2. 阈值默认值（`cap=3`、`max_conf<0.55`、`error_rate≥0.6`）是否为可接受的初值？可后续用真实对话调优。
