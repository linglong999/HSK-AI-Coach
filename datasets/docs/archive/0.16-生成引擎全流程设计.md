## 0. 一句话

把已落地的 authoring prompt + 确定性校验器，串成一条**可执行**的生成引擎流水线：生成单元 = authoring 槽位 → LLM 调用 → 校验反馈 → JSON 自愈重试 → 合法单元（+ 可选写回图谱）。纯标准库，复用既有 `LLMClient` 与 `ErrorGraph`，不重造引擎。

## 1. 流水线（生成引擎）

```
输入(上下文槽)                   输出(合法生成单元 or 结构化降级)
   │                                  ↑
   ▼                                  │
build_*_prompt ──▶ LLM.chat_json_strict ──▶ GenerationUnitValidator
   │                    │  失败/非法JSON           │
   │                    ▼                          ▼
   └────────更新槽位 ◀─── 诊断反馈(repair_feedback) 有诊断 → 拼接修复提示重试(自愈)
                                                   │ 仍失败
                                                   ▼
                                        写回图谱(可选 practice.targets_errors) → 降级结果
```

- **authoring**：`engine/generation/authoring.py` 的 `build_explain_prompt` / `build_practice_prompt`（槽位已备）。
- **LLM**：`engine/llm/client.py` `chat_json_strict`（JSON mode + 重试 1 次 + 降级抛 `JSONStrictError`，R格不静默透传）。
- **校验**：`engine/generation/validator.py` `GenerationUnitValidator`（稳定 code + repair_order）。
- **自愈重试**：把诊断（按 repair_order 升序的 `subject + evidence + supported_fixes`）拼进 repair_feedback，重发更高一轮生成。默认最多 `max_repairs=1` 轮（决策 B 可调）。
- **写回图谱**（决策 A）：可选。practice 命中 `targets_errors` 且 kp 有 `knowledge_point_id` → 走 `ErrorGraph.ingest_error`（或 M8 `Writeback.on_confirmed`）。默认**不自动写回**，由编排层显式调用（守"图谱唯一权威、无自由发散"）。

## 3. 对齐既有铁律

| 铁律 | 落地 |
|---|---|
| 不静默透传坏结果 | 连续失败抛结构降级（非裸 JSON），`degraded` 含稳定 code |
| 宁漏勿错 | 校验不过不产出"看似合法"单元；diff/修复先正确性后结构 |
| 不污染图谱 | 默认不自动写回；写回走 `write_back=True` 显式 + `Writeback.on_confirmed` 两段式 |
| 图谱唯一权威 | `curriculumAt` 只读注入，不参与写回 |
