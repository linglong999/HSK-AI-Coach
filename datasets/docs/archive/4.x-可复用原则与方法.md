## 0. 全景：这一轮"AI-coding 协作"揭示了什么

我们连续跨过 6 个任务（3.x 收口→4.1→4.2→4.3→4.4→M10 方向），从"造引擎"转向"做产品闭环"。这轮最大的变化是：**多数任务不是"写新功能"，而是"识别真缺口 / 守住已有成果 / 定义稳定接口"**。下面 8 条就是在这个转变里冒出来的。

---

## 原则 1 · 用证据核对"任务是否真的存在"，再决定做不做

- **触发**：任何"下一步待办"出现在执行清单时。
- **动作**：开工前回答三问——这件事做过没有？进展到哪？剩余缺口是不是当前阶段能补的？（看落盘文件/代码/甘特图，不靠记忆）
- **本轮实证**：差点把"参数标定"当待办，一查甘特图标 done、`error_graph.py` 里 λ/k/c2 已固化、verify_graph 18/18 已落地，T6-T8 是"待真实用户数据"非纯技术能标 → **划掉，不硬做**。同轮把精力转到真正缺的后端 JSON 接缝。
- **判断边界**：划掉≠偷懒。区别在于"诚实报告已存在事实 + 给出替代的真缺口"，而非"拒绝做事"。反过来：一旦拿到证据（如真用户数据到位），立刻恢复执行。

## 原则 2 · 可让 AI 背「产品与 AI-coding 的分工账」——A=方案决策、我=实现，但实现里仍有裁决点要回抛

- **触发**：任务边界模糊、实现方式有多种等价解时。
- **动作**：识别"该用户拍板 vs 我能自决"两类点。能用契约/模板消除的歧义就消除；真正二选一的（如接缝范围、前端发力点）回抛给用户。
- **本轮实证**：4.4 接缝用 AskUserQuestion 收敛"返回形态/接缝范围"两决策；其余字段顺序、降级结构实现细节自决。**把回抛点压缩到最少、最高价值**，是 AI-coding 提速的关键。

## 原则 3 · 接口改动要连"数据形态一致性 + 所有消费方"一起审

- **触发**：重构一个被多方消费的返回结构（dict、schema、接口）时。
- **动作**：不只测被改对象——列出**所有消费方**和**相邻同类字段的不同形态**，逐一验证对齐。新增回归测试覆盖"透传/消费路径"。
- **本轮实证**：4.4 把 degraded 从字符串改结构化 dict，全部测试 22/23 绿——但**没测到**规则回退的 degraded 还是字符串，`isinstance(list)` 把它静默丢弃（LLM宕机时契约 degraded[] 空）。二次 review 抓出。demo_loop（消费方）的降级打印也错位。教训：**happy path + 注入失败 ≠ 全覆盖，还要测"相邻形态不一致"与"旧消费方"**。

## 原则 4 · 稳定 id 是幂等的根基，用户可见的"确定性"从稳定 key 开始

- **触发**：任何需要幂等/去重的 key（event_key、id、文件名）设计时。
- **动作**：key 必须跨运行稳定——不依赖进程内随机值（如 `hash()`、`random`）。同一实体重复输入应命中同一 key。
- **本轮实证**：demo_loop 用 `abs(hash(句子))` 做 event_key，而 Python 字符串 hash 每进程随机化 → 同一句跑两次 repeat 计数，违背 2.4 的幂等设计。改用"句子本身"缺省回退后稳定。**一句话：能用实体本身做 key 就不用派生值。**

## 原则 5 · "确定性版本升级"要带版本号 + 兼容声明，而不是悄悄改契约

- **触发**：返回 schema、接口字段、行为语义发生变化时。
- **动作**：加显式 `version`/`contract_version` 字段 + 文档注明兼容规则；前端/消费方据此做向后兼容判断。
- **本轮实证**：4.4 契约 v1 在每个结果顶部带 `contract_version`，文档写死"前端只读契约字段，未列=内部实现禁止依赖"+ 4 条消费守则。**版本号是"改动可被感知"的最小痕迹**，也是降级评估你做得好坏的证据。

## 原则 6 · 架构叙事要能对得上"决策史"——面试讲"为什么"而不是"是什么"

- **触发**：对外讲解架构（面试/README/评审）时。
- **动作**：每个关键决策都要能回放"当时看见了什么约束→为什么这么选→代价是什么"。让"确定性图谱唯一权威"这类铁律有出处。
- **本轮实证**：M10 前端壳——用户看到 Explore 的自由发散卡片，我的回应是"借交互范式、不借数据逻辑"，因为自由发散会撞破我们自己立的"图谱唯一权威源"防线。Q13 把这一判断沉淀成面试题。**架构质疑不是要你放弃，是要你能说出不可放弃的那条边界。**

## 原则 7 · 诚实呈现边界是能力，不是短板

- **触发**：指标达不到"好看"、有已知残留、有刻意 trade-off 时。
- **动作**：明确区分"这是缺陷" vs "这是主动选择的代价"，并给出补救路径。在文档里留"已知残留"清单。
- **本轮实证**：3.6 已知残留表（语体漏报/cover-only/参数待真数据）；Q4 把"召回不100%"讲成"宁漏勿错的主动取舍"。**面试要的正是你知道哪里不强、且那是选择不是遗漏。**

## 原则 8 · 让"下一格"的接口先稳定，再谈界面——后端接缝优先于前端壳

- **触发**：要做前端/展示层，但后端数据交互未定稿时。
- **动作**：先定义**前后端唯一数据契约**（字段/类型/降级语义），跑通纯序列化 + 契约测试，再接前端。前端只消费契约，不依赖内部字段。
- **本轮实证**：先做 4.4 契约 v1（文档+规范化+测试 23/23），M10 前端壳才敢动。把"接缝"显式立为里程碑，避免前端返工。

## 原则 9 · 发布 ≠ 上传：正式对外前必须过"发布预检"闸门

- **触发**：任何要提交到共享/git 仓库 / 对外发布的内容时。
- **动作**：设四道闸，全过才推——**①安全**（扫密钥/令牌 `sk-`/`ghp-`/`xox` + 真实 `.env` 不入库只留 example）；**②隐私**（扫个人身份/本地绝对路径/真实邮箱）；**③合规**（License + 数据来源声明 + 第三方原始语料不入库）；**④门面**（README/测试态/功能态校准到真实，别让文档说"14 测试"实为"32"）。
- **本轮实证**：开源 `HSK-AI-Coach` 前，审计脚本扫出 `git add -A` 误收两个 `.bak` 备份（`golden_v1_4.json.bak_v02` 等）——"测试全绿"从不管提交内容干不干净，**这是两码事**。剔除并补 `*.bak*` 到 .gitignore 后才 commit&push。
- **判断边界**：发布预检不是"一直审个没完"——是一次性、可脚本化的闸门；每增加一类敏感物（密钥/语料/个人数据）就补一条扫描规则，让它成为可持续守的防线而非一次性动作。

## 原则 10 · 凭据一旦进入"会留存"的上下文，一律按已泄露处理

- **触发**：账号/密钥/令牌出现在对话记录、日志、缓存、截图等任何可能被他人读到的载体时。
- **动作**：不指望"删掉就安全了"。明确通知使用者**立刻轮换凭据**（如 GitHub 改密 + 清本地凭据缓存），并把它当成标准安全动作而非冒犯。
- **本轮实证**：GitHub 发布用到了账号密码，因经浏览器/对话流转即视为已泄露，向用户明确提示"推送完成后去改一次密码"。
- **判断边界**：宁可过度谨慎也不能侥幸——泄露的成本是一次性改密，侥幸的代价可能是一整套账号资产。**"当已泄露"处理，省去所有猜疑。**

## 原则 11 · README / 门面文档是"可复现"承诺的第一关，必须与真实同步

- **触发**：文档里的数字/状态/能力与代码真实不一致，或是要对外时。
- **动作**：发布前把 README 里所有**测试数、功能项、License、命令路径**逐项对着真实校验，去冗余、去夸饰。文档是别人决定"要不要 clone"的第一印象，错一个数字就消费一分信任。
- **本轮实证**：README 一度写"14 个测试 / M10 未做 / License TBD"，而真实为 32 个测试 / M10 已完成（serve.py + web/index.html）/ 已定 MIT。发布前全部校准，还补了前端壳用法、架构图加 serve/web 层。
- **判断边界**：这不同于"文档优先同步"的强制——是**发布关口**的一次对齐；日常迭代里文档可以滞后，但**对外那一刻必须是真的**。
