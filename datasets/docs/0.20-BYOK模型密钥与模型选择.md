# 0.20 · BYOK 模型密钥与模型选择（对标 Explore）

> 日期：2026-09-02 · 对标 Explore「自带密钥（BYOK）」设置页 + 输入框模型选择器
> 状态：已实现，测试 260 全绿（240→260）

## 一、需求与决策（用户拍板）

| 决策点 | 结论 |
| --- | --- |
| 默认模型 | **DeepSeek**（M6 已按其校准评测）；UI 标注「DeepSeek 已评测，其他模型未评测」，不做每供应商自动冒烟 |
| 模型名 | **手动填**（用户从供应商文档抄），不做 /models 自动拉取 |
| json_mode 兼容 | **必做兜底**：400 → 去掉 response_format 重试一次 |
| 接入方式 | 统一 **OpenAI 兼容协议**（DeepSeek/Qwen/GLM/Kimi/Ollama 通吃） |
| Key 存储 | 服务端 `data/llm_providers.json`（gitignore 挡住，同 .env 信任级） |
| 不做 | ChatGPT 式浏览器 OAuth（账号级授权，复杂且有风险）；计费倍率显示 |

## 二、架构

```
前端                          服务端
┌─────────────────┐   GET/POST/DELETE   ┌──────────────────────┐
│ 设置→模型密钥 tab ├────────────────────→│ /api/providers*      │
│ (添加/测试/默认/删)│                     │  engine/providers.py │
├─────────────────┤                     │  ↓ 原子落盘（tmp+rename）
│ 输入框模型选择器  │   POST /api/dialog   ├──────────────────────┤
│ (popover 会话级) ├────provider_id─────→│ planner 按供应商缓存   │
└─────────────────┘                     │ (id→Planner 实例)     │
                                        │ llm_call 绑 config 覆盖│
                                        ├──────────────────────┤
                                        │ LLMClient.chat(config)│
                                        │ + json_mode 400 兜底  │
                                        └──────────────────────┘
```

### 关键设计

1. **供应商存储（`engine/providers.py`）**
   - 结构：`{"providers": [{id,name,base_url,api_key,model,source}], "default_id"}`
   - `.env` 向后兼容：运行时虚拟为 `id="env"` 供应商，置顶且不可删除；无显式默认时即默认
   - 默认解析链：显式 default_id → env → 首个 UI 供应商；fail-loud：全空 → 400
2. **Planner 按供应商缓存（`serve._get_planner(provider)`）**
   - Planner 无会话状态（history 每轮显式传入）→ 按 provider id 分实例安全
   - 删除供应商后缓存孤儿无害（按 id 查找，不复活）
   - 测试 mock 注入路径（`_dialog_llm`）→ 单实例 `__mock__`，provider 维度被 mock 覆盖
3. **LLMClient 两处扩展**
   - `chat(..., config={base_url,api_key,model})`：请求级覆盖 settings 全局配置（explainer/verifier/generator 走全局不受影响，模型选择仅作用对话主链）
   - **json_mode 400 兜底**：`LLMHTTPError(400)` → 去掉 response_format 重试一次；仍失败抛带说明的错误。4xx 不参与退避重试的既有语义保留（新 `LLMHTTPError` 携带 code）
4. **安全**
   - 响应只含掩码 Key（`sk-***末4位`），完整 Key 绝不出现在任何响应（测试断言）
   - `data/llm_providers.json` 已加入 .gitignore
   - 连通测试在服务锁外执行（网络 IO 不持锁）

## 三、前端交互

- **设置 → 模型密钥 tab**：供应商列表（名称/模型/掩码 Key/默认徽标/测试按钮显延迟 ms/设默认/删除）+ 添加表单（「先测试连通」支持先验后存）+ 评测标注说明
- **输入框左上模型选择器**：绿点 + 模型名（mono 字体），popover 列出全部供应商 + 「跟随默认（服务端）」；选择存 localStorage（`hsk-provider`），随 `/api/dialog` 的 `provider_id` 上送
- **错误联动**：`unknown_provider`（供应商被删）→ 提示重选 + 自动刷新列表；`llm_not_configured` 文案改为双路径（界面添加 / .env）

## 四、API 契约（0.20 新增）

| 端点 | 方法 | 请求 | 响应 |
| --- | --- | --- | --- |
| `/api/providers` | GET | — | `{providers:[{id,name,base_url,model,api_key_masked,source}], default_id}` |
| `/api/providers` | POST | `{name,base_url,api_key,model}` | `{ok, provider(掩码)}`；缺字段 400 |
| `/api/providers/test` | POST | `{id}` 或 `{base_url,api_key,model}` | `{ok, latency_ms, sample}` / `{ok:false, error}` |
| `/api/providers/default` | POST | `{id}`（`"env"` = 回落 .env） | `{ok, default_id}`；未知 404 |
| `/api/providers?id=` | DELETE | — | `{ok}`；env 供应商 404 |
| `/api/dialog`（扩展） | POST | + `provider_id`（可选） | + `provider:{id,name,model}`；未知 400 `unknown_provider` |

## 五、测试（`tests/test_serve_providers.py`，20 个）

- 存储层：掩码格式 / 原子存取 / 损坏文件 fail-open / 默认解析链（显式→env→首个）/ env 虚拟供应商
- 端点：空列表 / 添加即默认 / **响应不含完整 Key** / dialog 默认绑定 / 显式 provider_id 覆盖（捕获 config 断言 model）/ 未知 400 / 缺字段 400 / 测试端点两种入参 / 默认切换 / 删除后默认回落 / 同 root 重启持久化
- env 兼容：置顶默认 / 不可删 / 不被 UI 供应商抢默认
- json_mode 兜底：400 降级重试去掉 response_format（payload 断言）/ 非 json_mode 400 不重试 / 降级仍失败抛描述性错误

**测试关键点**：单测全程 patch `settings.DEEPSEEK_API_KEY/QWEN_API_KEY` 隔离真实 .env 渗透（本机有真实 Key，不 patch 会污染默认解析断言）；LLM mock 打在 `LLMClient.chat` 类方法上，planner 真实路径 + 零网络。

## 六、review 记录

- 冒烟（真实服务）：env 供应商掩码置顶 ✓；添加→列表→删除全链路 ✓；unknown_provider 400 ✓；真实 DeepSeek 连通测试 536ms ✓
- **review 抓获（安全）**：`data/memory_*.json` / `data/ledger_*.json`（学习者对话历史/画像/账本）原不在 .gitignore —— `git add .` 会把用户数据带进仓库。修复：`.gitignore` 的 `data/graph_*.json` + `data/llm_providers.json` 两条细粒度规则收敛为整目录 `data/`（data/ 下零文件被追踪，全部为运行时产物）
- 测试自身教训：本机 `.env` 有真实 Key，单测不 patch `settings.DEEPSEEK_API_KEY` 时会渗透进默认解析断言（env 供应商抢占默认导致 2 例失败）——**环境依赖的单测必须显式隔离全局配置**
- 已确认不做：explainer/verifier/generator 的 per-provider 覆盖（模型选择仅对话主链，保持引擎层稳定性）——如后续需要再评估
- 风险接受：连通测试端点接受任意 base_url（SSRF 向量）——本服务仅监听 127.0.0.1 单用户本地场景，与 .env 同信任级
