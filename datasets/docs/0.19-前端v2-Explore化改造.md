# 0.19 · 前端壳 v2 · Explore 化改造（2026-09-02）

## 一、背景与目标

借鉴 Explore（ai.explore.poker）"知识树"产品的界面与交互设计，对 M10 前端壳做 v2 改造。
**驯化原则不变**：Explore 的自由发散交互必须服从本项目"图谱唯一权威、无自由发散"铁律——
**界面自由，数据规则**。

## 三、卡片分支动作 · 锚定图谱权威边（核心驯化）

Explore 的 ↗/→/↓ 是任意发散；本项目四动作全部锚定图谱权威边，无权威边的方向**置灰不可点**：

| 动作     | 启用条件（实时查 /api/graph）    | 行为                     |
| ------ | ----------------------- | ---------------------- |
| ↗ 子卡深挖 | 该 KP 在图谱 `nodes` 中（已确认） | 发起费曼式深挖请求（核心规则/用法/易错点） |
| → 相邻角度 | 图谱存在连接该 KP 的**混淆边**     | 弹出相邻 KP 菜单 → 讲两者区别与联系  |
| ↓ 沿待复习 | 该 KP 在**复习队列**          | 出针对性巩固练习（practice 单元）  |
| ✕ 删除   | 恒可用                     | 仅移除卡片 DOM，不影响图谱/记忆     |

## 四、新增 API（serve.py，均只读）

### GET /api/profile?learner=

AI 学习报告 + 侧栏数据源。返回：

- `profile`：落盘画像原块（level/native\_lang/历史 common\_errors 兜底）

- `common_errors`：live facts（graph × ledger 实时汇合，与每轮 dialog 写回同源）

- `summary_text`：画像摘要文本

- `sessions[]`：会话元信息（id/title/status/updated\_at/message\_count），按 updated\_at 降序，**不含 messages 防载荷膨胀**

- `stats`：graph\_nodes / graph\_edges / review\_count / repeat\_offenders

### GET /api/conversation?id=\&learner=

URL 深链恢复会话。只透 user/assistant 的 `{role, content}`（window=200），
**不暴露 metadata 内部项**（skills/fallback 等）。

### 会话标题自动设置（dialog 内）

`/api/dialog` 首条消息（该会话 history 为空时）自动 `mem.touch(title=首句前 18 字)`，
仿 Explore 卡片标题取自提问。

## 八、体验反馈迭代（2026-09-02 第二轮）

1. **认知地图独立视图**：侧栏"学习动线"新增「◈ 认知地图」入口，点击主区切换为地图独占视图（对话流隐藏、地图全宽）。实现为单文件 SPA 视图切换（`main.mapview` 类），**SVG 同实例复用**——`layoutNodes()` 以 `svg.clientWidth` 自适应，切换后重调 `renderMap()` 即按新尺寸重排，无需独立页面文件。交互闭环：入口再点/「‹ 返回对话」按钮/点任意会话 → 自动切回对话视图；入口带 `cur` active 态 + 节点数徽标；窗口 resize 防抖重排。窄屏（≤920px）`main.mapview{grid-template-rows:1fr}` 单行适配。
2. **侧栏拉起 bug 修复**：`.side-open.show{display:block}` 原只写在 `@media (max-width:920px)` 内 → 宽屏（含 F11 全屏）收起侧栏后拉起按钮永远 `display:none`，侧栏无法展开。修复：规则提为全局。教训：**响应式专属规则若承载"状态恢复"职责（此处是收起后的唯一展开途径），必须确认所有布局分支下都可达**。

## 八·三、体验反馈迭代（2026-09-02 第三轮：地图退出常驻）

用户反馈："认知地图不还是占据了右边的位置吗？改，之后只能通过点击认知地图入口才能进入。"

1. **地图彻底退出默认布局**：`.right` 默认 `display:none`，主区单列 = 纯对话画布（全宽，内容/输入行居中限宽 880px 保可读性）；仅 `main.mapview` 下显示地图。侧栏「◈ 认知地图」成为**唯一进入途径**。
2. **locateKp 联动**：地图不常驻后，对话流内所有知识点点击点（Smart Annotation 下划线名词、偏误卡 KP chip、复习卡条目、报告卡行）改走 `locateKp(id)`——自动切入地图视图并定位选中节点；地图视图内部三处点击（节点/SVG 底/复习队列条目）保持原 `selectNode` 语义（选中/反选）。
3. **布局细节**：删除两列 grid 与窄屏两行规则（单列后无意义）；旧 `.right{display:flex}` 基础规则改 `min-height:0`，避免后定义覆盖前隐藏规则（CSS 同特异性后者胜出）。
4. **文案同步**：空态×2、地图空态、"怎么用"弹窗——"右侧认知地图"全部改为"侧栏「◈ 认知地图」"。

## 九、关键教训（review 抓获）

- **单引号 vs 反引号视觉混淆可致全站瘫痪**：renderVerify 三元表达式 `?`模板`:` 的闭合符误写为 `'`（U+0027）而非 `` ` ``（U+0060），整个 `<script>` 块语法错误 → 前端所有交互静默失效（HTML 照常送达，肉眼无从察觉）。hex 级检查定位（`U+0027` vs `U+0060` 在等宽字体里几乎无法分辨）。

- **交付流程必须加 JS 静态校验**：手写大量嵌套模板字符串的单文件前端，验收线应含 `node --check`（提取 script 后语法校验）+ 元素 id 引用完整性核对。本轮 review 流程：smoke（HTTP 200 + 标记存在）不够——**语法层错误只有语法检查能抓**。
