# HSK 知识点清单 · MVP 骨架验证版（v0.1）覆盖说明

> 配套数据：`datasets/knowledge_points_v1_4.json`
> 状态：**骨架验证版 v0.1**（跑通 schema 挂接用，**非权威数据**）
> 分工：A=用户决范围，B=我构建实现

## 一、这版为什么存在

按甘特前置数据资产（P2-5）缺口：2.1 识别需要"HSK 知识点清单"供 `knowledge_point_id` 候选与合并层校验；2.4 建节点、2.2 读历史也都依赖它。但**权威 HSK 大纲/词表尚未就位**（工作区现无任何 HSK 标准资产），故先在**小范围人工整理高频点**上跑通"识别→图谱→讲解"的 schema 挂接，验证数据链路可行，权威数据到位后整体替换。

## 二、覆盖与口径

- **范围**：HSK 1–4 级，25 个高频语法点（等级分布：1级6 / 2级11 / 3级6 / 4级2）。
- **粒度**：粗粒度（如"把字句"=1 点），子型区分留给后续。
- **来源**：人工整理高频常考点，等级为**经验判断**，`source = manual-curated (pending authoritative HSK lexicon alignment)`. **非官方、待权威词表校对**——不冒充权威，保诚实性（面试/贡献者可复现，无编造承诺）。
- **键格式**：`id = knowledge_point_id`，直接对应 2.1 schema 的 `knowledge_point_id`，供合并层校验。

## 三、挂接验证点（本版要验证的）

| 环节 | 用什么 | 能否对上 |
|------|--------|---------|
| 2.1 识别候选 | 提示词注入 `{knowledge_tree_portal}` = 本清单；LLM 选 `knowledge_point_id` | 键名一致 |
| 2.1 合并层校验 | 对照清单查 `negated_id`；清单内命中 → 留候选；清单外 → 置空进 2.4 pending_mapping | kp 键可查 |
| 2.4 建节点 | 按 `id` 建 KP 节点，`level` 取清单值 | id/level 可读 |
| 2.2 读历史 | `get_kp(kp_id)` 读图谱（本清单未建图谱时为空上下文，不阻断） | 键可查 |

## 四、与权威数据的衔接（后续替换）

权威 HSK 大纲/词表到位后：直接替换本文件 `knowledge_points` 对象并 bump `version`，键名/结构不变即可无缝升级；等级字段以权威表为准。替换时同步更新本说明的等级分布与来源。

## 五、已知取舍（MVP 状态，不隐藏）

- 25 点远非全量；语法点高频子集 + 少量词汇/汉字/语用类型。**覆盖不足的偏误会落 pending_mapping**——这是设计预期，正好验证 2.4 待映射路径。
- 等级为经验值，非权威；来源已诚实标注。
- 含少量"词的偏误"（量词、介词、代词）与语法点混列，MVP 阶段够，正式版建议区分"语法点 vs 词汇条目"两个区。
