# tutor_quality · 教学 Judge Rubric

> 配套设计：《datasets/docs/0.25-教学judge-rubric-评测设计.md》 · 状态：**首版（待人工校准）**
> 用途：评测 HSK-AI-Coach 每次纠错/讲解/介入的"教学质量"（非 OpenMAIC 式"生成的课好不好"）。
> 判分三层：L1 程序断言（可确定性判定）→ L2 LLM-judge（开放质量）→ L3 红线硬判（一票否决）。

## 一、评分维度（6 条，各 1–5 分）

每个 case 对被测对话的输出，逐维度打分。**1 = 完全没做到，5 = 做得很好。**

| # | 维度 | 判定要点 | 判分层 |
|---|---|---|---|
| 1 | 偏误定位准确 | 是否瞄准真错点（对齐 `error_span` / `error_type` / `correction`），不误报、不教错 | L1（+L2 复核） |
| 2 | 讲解四段完整 | 为什么错 → 正确说法 → 对比 → 验证 是否齐全 | L2 |
| 3 | 复述验证严格 | 是否让学习者复述、连续 2 次不过是否降难度、是否拒绝"假懂" | L2 |
| 4 | 介入时机合理 | 三档介入是否匹配难度/求助，是否过度打断流利表达 | L2 |
| 5 | 语言分层守约 | 英文脚手架 + 中文内容载体（0.21 教学语言分层） | L2 |
| 6 | 归因谨慎 | L1 母语迁移假设是否讲得谨慎，不污染图谱（0.22） | L2 |

## 二、Red lines（5 条，触发任一 → 该 case pass=false，直接阻断，不进平均分）

| ID | 红线 | 判定方式 |
|---|---|---|
| R1 | 教错了（correction 本身错误 ≠ 黄金 correction，且不属合理多解） | L1 + L3 复核 |
| R2 | 误报干净句（clean 句被判成偏误纠正） | L1 |
| R3 | 漏了复述验证（讲了错因却不做任何 `写出语法点验证`/复述引导） | L3 |
| R4 | 流利时过度打断（高置信流利句仍介入打断） | L2/L3 复核 |
| R5 | 归因污染图谱（把 L1 迁移假设当事实写进图谱） | L3 |

## 三、判分口径（复用现有黄金集）

- **事实类**（定位/类型/改法）：用程序断言对 `golden_v1_4.json` 的 `error_span` / `error_type` / `correction`。
- **开放类**（讲解/话术/语言分层/介入/归因）：L2 LLM-judge 按本 rubric 打分，`{verdict:"pass"|"fail", per_dim:{1-5...}, reason}`。
- **红线**：L3 硬判；任一触发即 case fail，红线 case 不参与平均分（对齐知识库"红线不参与均分、一条失败阻断上线"）。
- **pass^k 门槛**：累计 pass 率 < **90%** → 门禁失败。

## 四、LLM-judge 校准（首版必须做）

L2 只用作初判，不能独自终裁。首版人工核 **20 个 case** 的 L2 判定，报告 judge 与人工一致率；
不一致处回填 `gold_judge_hint`，再重跑。目的：报告 judge 自报分之外，给出与人类 gold 的一致性证据（对齐 G-Eval / Anthropic 方法论）。

## 五、版本与回流

- 每次跑在 `README.md` 记录：模型、prompt 版本、case 版本、日期。
- badcase（线上失败 / 人工抽检打回）经《Badcase归因SOP》归因后，新增进 `cases.json` 的 `regression` 子集——它是随时间升值的核心资产，不可丢。
