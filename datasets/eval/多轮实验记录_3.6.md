## 1. 3.1 偏误识别 baseline（golden 句集）

### R1.1 初版 baseline（seed31 + 对抗5）
- **假设**：LLM 判定可对标规则基线，召回优先。
- **变更**：`run_eval.py` 黄金句集 v0.2 + `check_dataset.py` 校验。
- **指标**：F1 0.90（口径初） / 干净句误报 **10.53%**（#016/#019 均"**把字句**"系统性过度纠正）。
- **结论**：❌ 误报不可接受——overcorrection 是哨兵问题，recall 高但 precision 劣于 "宁漏勿错"。⚠️ 此初值**未落盘、不可复跑**，已降级为参考，权威以落盘为准。

### R1.2 overcorrection 专项（约束7）
- **假设**：常见句型（把/被/比）被误判偏误，根因是 LLM 对"合法把字句"缺确定性护栏；用规则守门可清零误报。
- **变更**：`recognizer.py` 新增**约束 7**（把/被/比 常见句型谨慎判偏误）。
- **指标**：误报 10.53% → **0%**；召回 -1（漏 #023 强调句）；F1 0.90 → **0.87**（精确 100% / 召回 76.47% / 对抗 over 0/2 / uncertain=0）。
- **结论**：✅ 误报清零但召回小损，人评审酌后**拍板保留"宁漏勿错"**——防误伤学习者的优先级 > 多抓一条。

### R1.3 把/被/比 压力扩集（证明护栏是规则非背诵）
- **假设**：若约束7 是"学到的对规则"，则对**训练外**的全新合法把/被/比句也应 0 误报。
- **变更**：36→45 句（seed31 + 对抗14，对抗占比 ~31%）；新增 9 条合法把/被/比（把4/被2/比3）。
- **指标**：9 条全新合法句（二语教师全裁定合法）**0 误报**；整体指标稳定（F1 0.87 / 精确 100% / 召回 76.47% / clean 误报 0/28 / over 0/11）。
- **结论**：✅ 证明护栏泛化，非背诵；剩 1 条 disputed 遗留用户终裁。**跨文档台账已登记（指南 v0.6）**。

### R1.4 数据集终裁（golden_v1_4 v0.3）
- **变更**：终裁全量 36 句 = seed32 + 对抗4；偏误17 + clean19；status reviewed35 / disputed1。
- **终裁**：A类 4 条改判 clean 负样本、B类 3 条翻 reviewed、009 归位 seed；ID 前缀 clean 统一 ERR→CLN；arbitrator 归一 l2-teacher-arbitration。
- **结论**：✅ 数据集与 README/check_dataset 全量口径一致，作为后续所有评测的金标单一真源。

## 3. 3.3 复述验证（retell_verification + 黄金集）

### R3.1 数据底座
- MuCGEC 1137 句 + CGED 14517 句工具链跑通；`retell_verification.json` v0.2（58条=方向一34+方向二24；truth：pass16/fail16/partial10/hollow16；二语仲裁 26 条）。

### R3.2 首轮（暴露根因）
- **指标**：判定一致性 **47.1%** / 通过准确率 **33.3%** / 流利拦截 **87.5%**。
- **根因**：key_points 混入**反向纠错指令**（"不能加『很』""该如此好应替换"），verifier 当成"复述应覆盖的要点"，pass 判 partial、fail 反之。
- **结论**：❌ **教训——复述验证的覆盖点=复述者应说出的正向知识；纠错指令/错误特征一律放 explanation，不得进覆盖集**。

### R3.3 清洗重建 + hollow 对抗强化
- **变更**：key_points 清洗重建 v0.3×2；prompt 判定标准加"关键词出现≠覆盖"+ 判别锚点（通用示例，避免背答案）。
- **指标**：流利空洞拦截 87.5% → **93.75%**。

### R3.4 定稿（用户按方案A收尾）

## 5. 3.5 文件讲解效果 + P0/P1/P2（端到端闭环）

### R5 初版（改进前基线，41 条全量）
- **指标**：分流 82.4%(14/17) / span精确 35.3% / span包含 82.4% / 误报 0% / 合规 100% / 纠错讲解人工通过率 64.3%(9/14)。
- **问题**：漏报3（你喝水吧？/一个电影/你几岁？——均**隐性偏误**）；span 切太宽（exact 35.3% 低估定位能力，包含率 82.4% 证明是"切宽"非"找不到"）；讲解 ERR-023/030 跑偏、ERR-018 误用"一般现在时"；泛讲解 8/24 仅 2 要点；英文随机夹杂。

### R6 P1 · 讲解四段式 + 术语规范
- **假设**：讲解质量缺陷靠**模板固化 + 术语白名单**，不靠硬编码答案。
- **变更**：explainer 三段→**四段式**（①指出错误→②解释原因→③给出正确句[必给]→④类比/举例）；约束7 禁英语时态名；约束8 歧义先澄清目标语义再给正确句。
- **指标**：ERR-023 补讲"是……的"、ERR-030 澄清语义+给正确句、ERR-005 兜底正确形式、ERR-018 改用"习惯性动作"——4 条全过。
- **结论**：✅ 模板化解法修复多例，无需逐条喂答案。

### R7 P0 · 隐性偏误识别 few-shot + 确定性护栏
- **假设**：隐性偏误（语用/搭配/语体）表层语法合格、难用规则框定；**同型不同词的 few-shot** 能校准判断，不背答案。
- **变更**：recognizer 新增 3 例+3 反例 few-shot（吧语气词/量词泛化/几岁语体）+ `_is_false_de_adverb` 护栏（状中"地"过度纠正）。
- **指标**：漏报 3→1（吧、一个电影命中；"你几岁"裸句按护栏正确拒报，计上下文相关）；**3.1 baseline F1 0.87→0.97（召回 76.47%→94.12%，误报仍 0）**。
- **结论**：✅ few-shot + 确定性护栏互补，反哺 3.1 baseline，证明"A 料喂给对的方向"。

### R8 P2 · 泛讲解要点下限 + 统一双语策略 + 导出脚本
- **变更**：SYSTEM_PLAIN 强制 key_points≥3；新增【双语策略】（正文中文，母语仅限括号锚定/跨语言对照）；eval_3_5 拆 `compute_metrics`+`write_checklist`，新增 `--from-results` 免重跑。
- **指标**：核心 24 条要点≥3 达标 **24/24**；英文夹杂转为合规 anchor；metrics 增"要点数下限(≥3)达标率"。
- **结论**：✅ 产品级体验约束落实到 prompt + 评测口径双端。

### R9 · span 收紧（约束7 迭代）
- **假设**：exact 低是"切太宽"，收紧 fragment 即可；但**最小 ≠ 残缺**，机制诱发词不可切。
- **变更**：约束7 明确"只圈最小片段、切独立正确成分、保留机制词（频率副词'常常'+了）"。
- **指标**：span精确 52.9% → **76.5%**(13/17)；span包含保持 **94.1%**；分流 94.1% 不变；正确句误报仍 0；3.1 baseline 不回流。
- **一次教训**：第一版"宁短勿长"使 ERR-018 过度收紧（`迟到了`丢 `常常`）cover 破地板→改为"机制词保留"后复原。**平衡点是产品直觉+指标监测共同定**。
- **结论**：✅ P0 三目标全达成，3.5 终态闭环。

| 图谱（3.4） | 18/18 PASS | verify_graph 报告 |

**贯穿性方法论教训（面试加分项）**：
1. **宁漏勿错**：防误伤优先级 > 多抓一条（overcorrection → 约束7 → 用户拍板）。
2. **确定性护栏做守门**，LLM 做带宽，两者分工（把/被/比、的/地）。
3. **few-shot 用同型不同词**，不注入待评原文——防背答案（3.3 hollow 锚点同理）。
4. **模板固化解多例**，不逐条喂答案（四段式）。
5. **"最小≠残缺"**：切独立正确成分、保留机制词——residual balance 靠指标监测调。
6. **评测口径要留档**：span 精确/包含双口径、要点数下限、边界句（上下文相关）显式说明，避免"数字打架"（3.5 报告已固化）。

## 8. 约束7覆盖面复检（2026-08-30 · 短平快）

> **假设**：上轮只验证了"把/被/比"三类高频合法句型护栏，需确认确定性护栏/规则回退**是否还有其他系统性误报小类**（了/着/过、的/地/得、量词、越来越等）。
> **变更**：新建 `datasets/eval/constraint7_coverage_check.json`（14 条合法句 = A 类纯纲内 11 条 + B 类含纲外词合法 3 条）+ `check_constraint7.py` 复检脚本。**边界声明：当前环境无 LLM Key，只验"规则回退层"，不验 LLM 约束7层**。
> **指标**：14 条合法句 **0 误报、0 uncertain**（含把/被/比/了着过/地得的不/越来越 全部干净）；A 类 11/11 纯纲内合法句 0 误报 ✓，B 类 3/3 合法句 0 误报 ✓。
> **结论**：规则护栏在新增高频小类上**无系统性误报**，覆盖复检通过。⚠️ **测试设计局限（诚实标注）**：B 类本想构造"含纲外词合法句"验证超纲 uncertain 边界，但因样本 level 设高（3/4）+ 超纲判定为"宽容相邻一级"（`>learner+1`），`漫步/见解` 等真纲外词未被标记超纲——B 类实际退化为纲内复检，**超纲分支未被真实触发**（属测试构造盲区，非护栏缺陷）。LLM 约束7层仍需有 Key 环境复检。⚠️ **超纲分支未触发这一测试盲区已于第 9 节修复**（v2 样本真实触发，见下）。

## 9. 约束7超纲分支盲区修复（2026-08-30 · 短平快）

> **假设**：上轮 B 类"含纲外词合法句"超纲分支未真实触发（OOV 词不算超纲 + 宽容相邻一级 >learner+1 吞掉 + 词表最高仅 4 级），导致"超纲只产提示、绝不产确认"这一护栏**从未被测过**。需构造真超纲合法句让该分支变得可测。
> **变更**：`constraint7_coverage_check.json` v2 —— B 类改"低等级学习者(1/2级)+词表内确定 4 级词"（阿姨/爱护、包裹、按时、背景、宝贵，均取自 `lexicon_hsk1_4.json` 的 word_level 且等级=4）；`check_constraint7.py` 新增"超纲分支触发"断言（B 类 `beyond_level` 非空、`uncertain` 命中、且 `errors==[]`）。根因确认：`detect_beyond_level` 只标记**在 word_level 词表内**的词，且 `lvl > learner+1` 才超纲 → 词表最高 4 级时，学习者必须 ≤2 级才可能触发。
> **指标**：B 类 5/5 超纲分支**真实触发** ✓，产 uncertain 5/5（命中目标超纲词）✓，**误报 confirmed 0 条**（不污染图谱）✓；A 类 11/11 仍 0 误报 0 uncertain ✓，护栏无回退。
> **结论**：✅ 超纲护栏行为验证成立——超纲合法句只能触发**低置信 uncertain 提示**，绝不产 confirmed，符合"宁漏勿错"。附带发现：`把` 在词表标 4 级，1 级学习者的把字句被判超纲，**语义合理**（"把"字句本属 HSK 中高级语法，对 1 级学习者确属超纲）。残留：LLM 约束7层 + LLM 超纲提示仍未在有 Key 环境复检。
