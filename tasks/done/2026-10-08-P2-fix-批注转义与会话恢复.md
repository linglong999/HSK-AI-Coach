# [P2-fix] 批注转义与会话恢复

**状态：** 通过

**规模：** 大 <!-- 含持久化字段与 /api/conversation 白名单契约变更 -->
**上游依据：** P2 自用基线试跑（2026-10-08，`a1-self01`）中用户实测发现的两个问题
**依赖：** 无

## 目标

1. 前端不再把 `' " & < >` 显示成 `&#39;` 之类的实体（双重转义）。
2. 重新打开已有会话时，朱笔批注、讲解卡、折叠块（来源/语料/材料解析）按实时对话的顺序原位重建。

## 问题根因（Claude 已核实）

- **转义**：`web/src/components/Cards.tsx:14` 与 `AnnotatedSentence.tsx:8` 的 `esc()` 移植自 legacy 手拼 HTML 页面；在 React JSX 文本子节点里 React 已自动转义，再调 `esc()` 就成了双重转义。触发样例：构造诊断 note「否定/能愿词出现在'把'后」。
- **恢复·前端**：`web/src/pages/Speak.tsx:183-187` 恢复时只重建 user / assistant 文本 + why，忽略 `/api/conversation` 已返回的 `cards`。
- **恢复·后端**：朱笔批注依赖的 `identified`（pre_scan 的 errors/uncertain，含 offset、construction_diagnostics）只经 SSE 独立下发（`serve.py:199-204`），`DialogService._compact_cards` 只取 trace，所以从未持久化。`data/coach.db` 实查：有 why（即有偏误）的轮次，cards 里也没有 identify_errors。

## 契约（R2：必须逐字照办）

```python
# dialog_service.py
@staticmethod
def _assistant_payload(res, pre_scan, provider, native_lang, reason) -> dict:
    # 返回 {"cards": [...], "why": [...], "identified": {"errors": [...], "uncertain": [...]}}
    # identified 的构造与 dialog_run.py:708-713 完全一致；pre_scan 非 dict 时为 {}
```

- `/api/conversation`：assistant 消息在 `identified` 的 errors 或 uncertain 非空时透传 `item["identified"]`；user 消息仍不透传任何 metadata。
- 旧会话（无 `identified` 字段）照常恢复，只是没有批注，不报错。

前端恢复顺序必须与实时一致（实时顺序：user → recog → trace 卡 → assistant+why）：

```
对每条 assistant 消息 A（其前一条 user 消息为 U）：
  user(U.content)
  若 A.identified 有 errors/uncertain → recog(text=U.content, errors, uncertain)
  A.cards 中 name !== 'identify_errors' 的每张 → trace(name, result)
  assistant(A.content, why=A.why)
```

不跟在 assistant 后面的 user 消息（例如末尾那条没有回复的）照原样只推 user 行。

## 实现要点

- 去转义时，`dangerouslySetInnerHTML` 的三处（`lblSources/lblCorpus/lblParsed`）不调 `esc` 且只插数字，保持不动。不得新增任何 `dangerouslySetInnerHTML`。
- `safeUrl` 保留，它防的是 `javascript:` 链接，和转义无关。
- `test_retell_target.py` 里用 lambda 伪造 `assistant_payload`，返回 `{"why": []}`。`dialog_run` 通过 `**meta` 展开，缺少 identified 不会出错，不要改这些测试。
- `identified` 里的 fragment 是用户原文，但存在 messages 行内，P1.7 的 purge 本来就覆盖 messages，不新增存储位置。

## 实施方案（Codex 计划对话填写，动代码之前）

**改法：**
- `web/src/components/Cards.tsx`：删除仅用于 JSX 文本节点的 `esc()` 定义及全部调用，改为直接渲染原值，并在需要保持现有空值语义的地方使用 `String(x ?? '')`。保留 `safeUrl` 及三处只接收数字的 `dangerouslySetInnerHTML` 原样，不新增任何 HTML 注入入口。
- `web/src/components/AnnotatedSentence.tsx`：同样删除 `esc()` 及调用；原句片段、纠正、标签、解释和知识点交给 JSX 文本节点自动转义，保持 `collectMarks/splitSegments` 与交互状态不变。
- `src/engine/dialog_service.py`：扩展 `_assistant_payload`。沿用 `dialog_run.py:708-713` 的构造逻辑，从 `pre_scan` 的 `errors` 与 `uncertain` 组成 `identified`；`pre_scan` 非 dict 时使用空对象。返回固定形状 `{"cards": cards, "why": why, "identified": {"errors": ..., "uncertain": ...}}`，不改变 cards/why 生成条件，也不修改 `_compact_cards`。
- `src/engine/serve.py`：在 `/api/conversation` 的 assistant 白名单中仅增加 `identified`，且仅当 errors 或 uncertain 非空时透传；user 分支继续只返回 role/content。更新函数注释，避免暗示 cards 不持久。
- `web/src/pages/Speak.tsx`：扩展恢复消息类型，按相邻 user/assistant 配对重建实时顺序。对每条 assistant：先追加其前一条 user；若 `identified.errors` 或 `identified.uncertain` 非空，追加 `recog`；遍历 `cards`，跳过 `identify_errors` 后追加 trace；最后追加 assistant 与 why。已配对的 user 不重复追加；末尾无 assistant 的 user 原样追加。恢复时对旧消息缺失字段使用空数组/空对象，保证兼容旧会话。同步更新恢复注释。
- `web/src/lib/i18n.ts`：把中英文 `restored` 文案改为仅描述会话已恢复和消息数量，删除“成果卡不随会话持久/仅文本记录”的过时说法；该键虽当前未引用，保留键名以避免无关调用方破坏。
- `tests/test_serve_sessions.py`：在现有会话持久化测试基础上新增带偏误轮次的透传断言：assistant 的 `identified.errors` 非空且包含 `fragment/offset`，user 不含 `identified`；新增无偏误轮次断言 assistant 不含 `identified`。测试使用现有 server/LLM fixture，不引入前端测试框架。

**复用：**
- 复用 `dialog_run.py` 已有的 pre-scan identified 字段语义和 `serve.py` SSE 的 `out["identified"]` 形状，避免产生第二套批注数据模型。
- 复用现有 `_assistant_payload` 的 cards/why 生成、`LearnerMemory` metadata 持久化、`/api/conversation` 的角色白名单、Speak.tsx 的 `TraceCard`/`AnnotatedSentence`/`WhyBlock` 渲染组件。
- 复用测试中的 `_start_server`、`ScriptLLM`、`_post`、`_get` 和 `CardsPersistenceTest` 生命周期；仅增加针对新字段和旧会话兼容性的断言。

**疑问与假设：**
- `dialog_run.py:708-713` 的“完全一致”解释为直接复制其对 errors/uncertain 的筛选和字段保留逻辑，不在本卡自行裁剪 fragment、offset 或 construction_diagnostics；如上游代码在执行前发生变化，应以当时实现为准并由 Claude 重新确认。
- 恢复配对假设后端历史保持 user/assistant 交替；若出现连续 assistant，按每条 assistant 查找最近尚未消费的前置 user，找不到则只恢复 assistant，不虚构 user。卡片未要求处理异常历史的重新排序。
- `identified` 只有在 errors/uncertain 至少一项非空时才进入 `/api/conversation`；因此旧记录和无识别记录保持无该键，而不是返回空对象。
- 本卡不为前端显示动画、实时 SSE 顺序或 `_compact_cards` 增加新契约；手测负责验证刷新后的视觉顺序，自动测试负责后端字段边界。

**风险：**
- JSX 直接渲染虽由 React 自动转义，但若误保留某个 `dangerouslySetInnerHTML` 的字符串路径可能重新引入 XSS 或双重转义；执行阶段需用 `grep` 和前端构建共同验证。
- assistant metadata 中加入用户原文 fragment 会随既有 `messages` 一起持久化；这是卡片明确接受的存储位置，仍依赖 P1.7 purge 覆盖和既有会话访问控制。
- `/api/conversation` 白名单漏加、误加到 user，都会破坏恢复或 metadata 隔离；新增测试及 M1–M3 突变自检必须分别锁定这三条边界。
- 恢复逻辑若错误处理 `identify_errors`，会产生重复朱笔批注；必须跳过该 card，并以 `identified` 作为唯一 recog 来源。
- 修改 i18n 文案虽不影响当前引用，但若其他未搜索调用方依赖旧语义，需通过构建确认类型和资源完整性。
