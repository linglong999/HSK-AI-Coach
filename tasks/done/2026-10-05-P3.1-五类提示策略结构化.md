## 目标

把反馈「怎么说」从现有的 `(方向, L&R 标签, 中文自由文本理由)` 三元组，升级为计划规定的**五类模式 + 可审计 reason code** 的结构化决策。选择规则确定、可回放；给 LLM 的指令和 A1 记录使用同一份决策，满足计划里「文本与元数据一致，不能从文本猜策略」的要求。

**范围限制（计划 §10 规则 2）**：P2 还没有完成，本卡只做 **v1 固定规则**（P3.1–P3.3），不做真实案例回放调优（P3.4），也不改前端（P3.5）。卡片中的规则是 v1 初始规则，不代表产品定论，P3.4 会根据真实记录调整。

**现状（已核实）**：
- `feedback_selector.select_feedback_strategies` 只有 `preferences` 三元组，没有五类模式；理由字段是自由文本。
- `DialogRun._study_strategies` 把 L&R 标签（例如 `metalinguistic`）当作 `mode` 写进 A1 事件，命名空间不对。
- 求助意图在时机层已有信号（`intervention.decide_intervention` 返回 `reason == "help"`），但没有传给策略层。
- 复发次数 `recurrence_map` 来自 `ledger.repeated_count(kp)`，账本在策略选择**之前**已经写入本轮的 `observation_error`，所以这个计数**包含本轮**：第一次出错时为 1。

## 契约（R2：必须逐字照办）

### C1. 常量（`feedback_selector.py` 模块级）

```python
FEEDBACK_MODES = ("recast", "intonation_hint", "local_question", "contrastive_hint", "explicit_correction")
HINT_LEVELS = ("none", "light", "medium", "strong")
MODE_HINT_LEVEL = {"recast": "none", "intonation_hint": "light", "local_question": "medium",
                   "contrastive_hint": "medium", "explicit_correction": "strong"}
REASON_CODES = ("HELP_REQUESTED", "DEEP_DIVE", "SCENE_LOW_IMPACT", "FLUENT_KEEP_FLOW",
                "LOW_LEVEL_MODELING", "LOW_LEVEL_REPEAT", "SLIP_ON_MASTERED",
                "FIRST_PROMPT", "REPEAT_1", "REPEAT_2", "REPEAT_ESCALATE")
MASTERED_THRESHOLD = 0.7
```

### C2. 决策结构

```python
{"mode": str,                 # FEEDBACK_MODES 之一
 "hint_level": str,           # 恒等于 MODE_HINT_LEVEL[mode]
 "reason_code": str,          # REASON_CODES 之一
 "target_kp": str,            # 目标偏误的 knowledge_point_id，缺失时为 ""
 "target_fragment": str,      # 目标偏误的 fragment，缺失时为 ""
 "user_requested_help": bool}
```

### C3. 单个目标的决策函数（纯函数）

```python
def decide_feedback(error: dict, *, position: int, is_deep: bool, hsk_level: int,
                    intervention_level: str, intervention_reason: str,
                    scene_active: bool, recurrence: int, mastery: float) -> dict
```

令 `c = recurrence`（含本轮的累计撞错次数），`sev = _severity(error)`。`user_requested_help = (intervention_reason == "help")`，同一轮内所有决策取值相同。按以下顺序**取第一条命中**的规则：

| # | 条件 | mode | reason_code |
|---|---|---|---|
| R1 | `intervention_reason == "help"` 且 `position == 0` | explicit_correction | HELP_REQUESTED |
| R2 | `is_deep` | explicit_correction | DEEP_DIVE |
| R3 | `scene_active` 且 `sev < 2` | recast | SCENE_LOW_IMPACT |
| R4 | `intervention_level == "none"` | recast | FLUENT_KEEP_FLOW |
| R5a | `hsk_level <= 2` 且 `c <= 1` | recast | LOW_LEVEL_MODELING |
| R5b | `hsk_level <= 2` 且 `c >= 2` | explicit_correction | LOW_LEVEL_REPEAT |
| R6 | `c <= 1` 且 `mastery >= MASTERED_THRESHOLD` | intonation_hint | SLIP_ON_MASTERED |
| R7a | `c <= 1` | intonation_hint | FIRST_PROMPT |
| R7b | `c == 2` | local_question | REPEAT_1 |
| R7c | `c == 3` | contrastive_hint | REPEAT_2 |
| R7d | `c >= 4` | explicit_correction | REPEAT_ESCALATE |

`hint_level` 一律取 `MODE_HINT_LEVEL[mode]`。`hsk_level` 不是正整数时按 3 处理；`recurrence` 和 `mastery` 不是数字时分别按 0 和 0.0 处理。

### C4. `select_feedback_strategies` 扩展

签名新增三个**仅限关键字、带默认值**的参数（默认值保证现有调用方的行为不变）：

```python
def select_feedback_strategies(errors, hsk_level, intervention_level, recurrence_map=None,
                               deep_dived_kps=None, *, intervention_reason: str = "",
                               scene_active: bool = False, mastery_map=None)
```

- 返回 dict 新增键 `"decisions"`：对 `[deep] + light_marks`（deep 为 None 时省略）按顺序逐个调用 `decide_feedback`，`position` 为该列表中的下标。`recurrence` 取 `recurrence_map.get(kp, 0)`，`mastery` 取 `(mastery_map or {}).get(kp, 0.0)`。
- **求助不被吞掉**：`intervention_reason == "help"` 时，即使 deep 为 None（比如所有 KP 都深攻过），第一个 light_mark 也会因 R1 得到 explicit_correction。
- encourage 档或没有错误时，`decisions` 为 `[]`。
- `deep_dive`、`light_marks`、`silent_kps`、`preferences`、`deep_dive_count` 等现有键的**取值不变**。`preferences` 保留，作为 L&R 编码框架，不再驱动文案。

### C5. `compile_strategy_section` 改由 decisions 驱动

- 每个目标一行。这一行必须包含该目标的 fragment，以及该 mode 在 `_MODE_LABEL` 中的标签（新增模块级常量，中英双语，五个 mode 各一个标签）。
- 各 mode 的指令语义（具体措辞由 Codex 决定，但语义必须符合）：
  - recast：回复中自然地用上正确形式，**不指出错误**；
  - intonation_hint：用疑问语气重复学习者的说法，提示这里可能有问题，**不给出正确答案**；
  - local_question：只针对这一个点提一个简短的问题，**不给出正确答案**；
  - contrastive_hint：给出两个形式让学习者二选一，**不说哪个对**；
  - explicit_correction：明确说出正确形式和原因；如果是 deep_dive，再引导学习者复述。
- 段落里**不得出现任何 reason_code 字符串**（这是内部代码）。
- `decisions` 为空时返回 `""`，与现在一致。段首标记 `[FeedbackStrategy]` 保持不变（`tests/test_dialog_run.py` 和 `tests/test_feedback_selector.py` 都依赖它）。保留现有的「其余错误静默进复习队列」那一行（中文版要包含「复习队列」四个字）。按这样写，`test_feedback_selector.py` 的 `CompileSectionTest` 预计不需要修改。

### C6. `DialogRun` 接入

`_select_and_log_strategies` 增加关键字参数 `reason: str = ""`、`scene_active: bool = False`，调用处传入 `reason=reason`、`scene_active=bool(ctx 中的 scene_id)`（scene_id 需要从 `_pre_scan_intervene` 的调用链传下来）。`mastery_map` 按以下方式构造，单个 KP 出异常时按 0.0 处理：

```python
node = (self._router.graph.get_kp(kp) or {}).get("node") or {}
mastery_map[kp] = float(node.get("mastery") or 0.0)
```

`_study_strategies(strategies)` 改为直接读取 `strategies["decisions"]`，每项输出 `{"kp_id": d["target_kp"][:120], "mode": d["mode"], "hint_level": d["hint_level"], "reason_code": d["reason_code"]}`，并过滤掉 `kp_id` 为空的项。**不再读取 `preferences`。**

### C7. A1 校验（`study.py`）

`_validate_payload` 中对 `strategies` 的每一项新增校验：存在 `mode` 时必须属于 `FEEDBACK_MODES`；存在 `hint_level` 时必须属于 `HINT_LEVELS`。两个常量从 `engine.feedback_selector` 导入，不要复制一份。

## 实施方案（Codex 计划对话填写，动代码之前）

**改法：**
- `src/engine/feedback_selector.py`：保留 `LR_TAGS`、`TYPE_PREFERENCE`、`preferences` 和现有错误排序行为，新增 C1 的 `FEEDBACK_MODES`、`HINT_LEVELS`、`MODE_HINT_LEVEL`、`REASON_CODES`、`MASTERED_THRESHOLD`，并新增双语 `_MODE_LABEL`。实现纯函数 `decide_feedback(...)`：先把非法/非正 `hsk_level` 归一为 3、非法 recurrence/mastery 归零，再按 C3 R1→R7d 严格取第一条命中规则，输出 C2 的六字段结构；不修改 `intervention_level` 或 `intervention_reason`。扩展 `select_feedback_strategies` 的三个关键字参数，保持 `deep_dive`、`light_marks`、`silent_kps`、`preferences`、`deep_dive_count` 的旧取值不变；对 `[deep_dive] + light_marks` 按顺序生成 `decisions`，求助时即使没有 deep dive 也让第一个 light mark 命中 R1，且同轮所有决策保留 `user_requested_help=True`。重写 `compile_strategy_section` 为只消费 `decisions`：每个目标输出 fragment、对应 mode 的双语标签和符合 C5 的表达指令，不输出任何 `REASON_CODES` 字符串；保留 `[FeedbackStrategy]` 段首和“其余错误静默进复习队列”一行，`decisions` 为空仍返回空串。
- `src/engine/dialog_run.py`：在 `run()` 调用 `_pre_scan_intervene` 时传入 `ctx["scene_id"]`，给 `_pre_scan_intervene` 增加 scene 参数，再沿调用传到 `_select_and_log_strategies`。该方法新增 `reason`、`scene_active` 关键字参数，调用选择器时传入当前时机层 reason、`scene_active=bool(scene_id)`；为每个预扫错误从现有图谱 `get_kp(kp)` 读取 node.mastery，单点异常按 0.0，不改变图谱。保留当前预扫先写 `observation_error` 的顺序，因此 `recurrence_map` 继续包含本轮次数，符合卡片现状口径。选择器返回后仍把 deep dive 加入会话去重集、记录现有账本 `feedback_presented`，只新增 decisions。
- `DialogRun._study_strategies` 改为读取 `strategies["decisions"]`，为 A1 事件逐项输出截断后的 `target_kp`、`mode`、`hint_level`、`reason_code`，过滤空 KP，不再从 `preferences` 推断 mode 或 hint level。这样 planner 指令和 A1 元数据都源自同一个 decisions 结果，避免从自由文本反推策略。

**疑问与假设：**
- C3 规则表本身没有需要本轮擅自调整的冲突，方案逐条照办；R1 与 R2 都选择 `explicit_correction`，区别仅由 `HELP_REQUESTED`/`DEEP_DIVE` reason code 审计，假设这是有意设计而非重复规则。
- `scene_active` 的契约来源是 `bool(ctx["scene_id"])`：当前场景数据没有独立的“生存任务”字段，因此任何非空且可能只是普通教学的 scene_id 都会命中 R3。方案不自行扩大场景模型；这会在风险中保留，后续由真实案例回放决定是否需要显式场景属性。
- `scene_id` 只需沿 `run → _pre_scan_intervene → _select_and_log_strategies` 传递，策略选择不需要重新加载场景或改变 `intervention.decide_intervention`；假设未知/未命中的 scene_id 仍按“非空即 active”执行 C3，而不是按场景加载成功与否判定。
- `recurrence_map` 当前在策略选择前由预扫写入本轮 `observation_error`，因此 `c` 包含本轮撞错次数；方案按卡片现状和 C3 照办，不改账本时序或另造“上一轮次数”。
- `mastery_map` 只读取 `get_kp(kp)` 返回的 node.mastery；节点缺失、接口异常、非数值均按 0.0，不能因为 mastery 读取失败阻断选择。`bool` 属于 Python 的整数子类，方案按“非正整数/非数字归一”处理时会将布尔值视为无效输入，避免把 True 当 HSK1 或 recurrence1。
- `_MODE_LABEL` 的具体中英文措辞由实现确定，但五种 mode 的语义、fragment 必须出现、reason code 不得出现是不可变验收条件；不把 L&R 标签当作 mode，也不删除 `preferences`/`LR_TAGS`。
- `compile_strategy_section` 的输入按 C5 假设来自同一选择器生成的 decisions；对旧调用方手工构造的仅含 deep/light/preferences 字典不承诺继续编译旧文案。现有测试通过选择器生成数据，若发现其他直接调用方失败，应写入问题与阻塞而不是添加未约定的兼容路径。

**风险：**
- scene_id 传递遗漏会使 scene_active 始终为 False，导致生存场景 R3 不生效；需要在策略单测和对话/A1 测试中同时验证调用链和最终元数据。
- C3 规则按第一条命中执行，顺序错误会改变求助、深攻、低水平和复发升级的结果；特别是 R1 必须先于 R3，R5b 必须先于 R7d，R6 不能覆盖 c=2 的 R7b。
- `decisions` 与 `preferences` 并存期间可能出现文案、A1 元数据或旧测试仍读取 L&R 标签的错配；必须让文案和 A1 都只读 decisions，同时保留旧键供 B6 评测。
- `mastery` 读取失败或图谱节点缺失会把已掌握错误按 0.0 处理，可能从 R6 降级到 FIRST_PROMPT；这是确定性降级，需在测试和复盘记录中可见但不能阻断对话。
- 低严重度 scene_active 一律 recast 可能在真实生存任务中仍过度隐性，任意非空 scene_id 也可能把普通场景误当生存任务；P3.4 前不得用主观案例修改 C3，只能记录观察。
- `compile_strategy_section` 的自然语言若与 mode 元数据不一致，会违反“不能从文本猜策略”的核心目标；五种 mode 的禁止事项（不给答案/不指出错误/不阻断任务/引导复述）需分别由文案测试锁定。
- 策略项被写入 A1 后，旧事件和新事件可能混合；`StudyTracker` 只校验新写入项，不迁移历史 payload。reason code 进入结构化事件但不得进入学习者可见 planner 指令，任何文案泄露都会造成内部字段暴露。
