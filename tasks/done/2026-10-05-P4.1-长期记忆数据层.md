## 目标

建立第三层「经历记忆」的数据层：独立的 `memory_items` 表，加上 `LongTermMemory` 深模块，负责候选、确认、拒绝、召回、遗忘，以及去重和权限边界。新表要纳入 P1.7 的试用分区整体清除。

- 短期对话记忆：现有的 `sessions`/`messages`；

## 契约（R2：必须逐字照办）

### C1. 表结构（追加到 `_SCHEMA`；新表，不需要迁移）

```sql
CREATE TABLE IF NOT EXISTS memory_items (
  memory_id     TEXT PRIMARY KEY,
  learner_id    TEXT NOT NULL,
  kind          TEXT NOT NULL,
  status        TEXT NOT NULL,
  content_json  TEXT NOT NULL DEFAULT '{}',
  source_json   TEXT NOT NULL DEFAULT '{}',
  dedup_key     TEXT NOT NULL,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  confirmed_at  INTEGER,
  last_recalled_at INTEGER,
  recall_count  INTEGER NOT NULL DEFAULT 0,
  last_actor    TEXT NOT NULL DEFAULT '',
  UNIQUE (learner_id, dedup_key)
);
CREATE INDEX IF NOT EXISTS idx_memory_items_lookup ON memory_items(learner_id, kind, status);
```

### C2. 常量（`long_term.py` 模块级）

```python
MEMORY_KINDS = ("life_event", "unfinished_task")
MEMORY_STATES = ("candidate", "confirmed", "rejected", "forgotten")
CONFIRM_ACTORS = ("learner", "operator")       # 可以执行 confirm / reject / forget
CONTENT_FIELDS = {
    "life_event": {"summary", "place", "when", "tags"},
    "unfinished_task": {"summary", "scene_id"},
}
SOURCE_FIELDS = {"conversation_id", "extractor", "event_key"}
MAX_TEXT = 200          # 每个字符串字段的最大长度
MAX_TAGS = 10           # tags 最多 10 项，每项 ≤ 40 字符
RECALL_LIMIT_MAX = 20
```

### C3. 构造与接口

```python
class LongTermMemoryError(ValueError): ...   # 不要命名为 MemoryError，那会覆盖 Python 内置异常

class LongTermMemory:
    def __init__(self, learner_id: str, root: str = "data",
                 now: Optional[Callable[[], int]] = None,
                 id_factory: Optional[Callable[[], str]] = None): ...
    def add_candidate(self, kind: str, content: dict, source: dict) -> str: ...
    def confirm(self, memory_id: str, actor: str) -> None: ...
    def reject(self, memory_id: str, actor: str) -> None: ...
    def recall(self, kind: str, query: str = "", limit: int = 5) -> list[dict]: ...
    def forget(self, memory_id: str, actor: str) -> None: ...
    def get(self, memory_id: str) -> Optional[dict]: ...
    def list_items(self, status: Optional[str] = None) -> list[dict]: ...
```

- 数据库连接通过 `store.ensure_store(root)` 获得，所有查询都带 `learner_id=?`，**不能读写其他学习者的记录**。
- `memory_id` 默认取 `"mem-" + secrets.token_hex(10)`。
- 所有不合法的输入一律抛 `LongTermMemoryError`。

### C4. 内容校验与去重键

- `content` 必须是 dict，所有键都要在 `CONTENT_FIELDS[kind]` 范围内，并且 **`summary` 必填且非空**。字符串字段去掉首尾空白后长度不超过 `MAX_TEXT`；`tags` 必须是 str 列表，满足 `MAX_TAGS` 和每项 40 字符的限制。
- `source` 必须是 dict，所有键都要在 `SOURCE_FIELDS` 范围内，值为长度不超过 160 的 str。
- 去重键：先做归一化，`norm = json.dumps({"kind": kind, **content_cleaned}, ensure_ascii=False, sort_keys=True)`，其中 summary 要先去首尾空白、转小写、并把连续空白合并成一个空格；然后 `dedup_key = sha256(norm)` 的 hex 前 32 位。

### C5. 状态机

| 操作 | 允许的起始状态 | 结果 | 其他起始状态 |
|---|---|---|---|
| `add_candidate` | 不存在 | 新建 `candidate` | 同一个 `dedup_key` 已存在（无论什么状态）→ **返回已有的 id，不做任何改动**（rejected 和 forgotten 不能被复活） |
| `confirm` | `candidate` | `confirmed`，写入 `confirmed_at` | `confirmed` → 什么都不做（幂等）；`rejected` / `forgotten` → `LongTermMemoryError` |
| `reject` | `candidate` | `rejected` | `rejected` → 什么都不做；`confirmed` / `forgotten` → `LongTermMemoryError`（已确认的记忆要用 forget） |
| `forget` | `candidate` / `confirmed` / `rejected` | `forgotten`，**同时把 `content_json` 和 `source_json` 清空为 `'{}'`** | `forgotten` → 什么都不做 |

- `confirm` / `reject` / `forget` 的 `actor` 必须属于 `CONFIRM_ACTORS`，否则抛 `LongTermMemoryError`（例如 `"system"`）。这是权限边界：模型或系统只能提出候选，不能自行确认。
- 每次状态变化都要更新 `updated_at` 和 `last_actor`。
- 记录不存在、或属于其他学习者时，抛 `LongTermMemoryError`。
- **forget 只保留 `dedup_key`（一个哈希值），不保留任何原文。** 这个墓碑的作用是：同样的经历以后再被提取出来，也不会被重新创建。

### C6. 召回

- 只返回 `status == "confirmed"` 且 `kind` 匹配的记录。
- `query` 非空时，要求 `summary` 或任意一个 tag 中包含 query（大小写不敏感，子串匹配）。匹配逻辑放在私有方法 `_matches(item, query)` 里，作为以后替换检索实现的接口。
- 按 `updated_at` 降序排列，同值时按 `memory_id` 升序。`limit` 必须是 1 到 `RECALL_LIMIT_MAX` 之间的整数。
- 每返回一条记录，就更新它的 `last_recalled_at` 和 `recall_count += 1`。**状态仍然是 confirmed**：计划 §3.3 中的 `recalled` 在这里实现为属性，而不是单独的状态，因为同一条记忆可以被多次召回，召回不应改变它是否可用。
- 返回项**只包含** `{"memory_id", "kind", "content", "confirmed_at"}`，不返回 `source`。

### C7. `get` / `list_items`

- `get(memory_id)`：返回该学习者这条记录的完整 dict（解析后的 content 和 source、状态、各时间戳），不存在时返回 None。
- `list_items(status=None)`：按 `created_at` 升序返回该学习者的全部记录，可以按状态过滤（status 必须属于 `MEMORY_STATES`）。forgotten 的记录也会列出，但它的 content 为 `{}`。
- 这两个函数**只用于查看**，不更新召回计数。

### C8. CLI（`python -m engine.memory.long_term`）

- `list --learner-id L [--status S] [--root DIR]` → 输出 JSON `{"learner_id", "count", "items"}`
- `forget --learner-id L --memory-id M [--root DIR]` → 以 `actor="operator"` 执行 forget，输出 `{"memory_id", "status": "forgotten"}`
- 出现 `LongTermMemoryError` 时，把错误信息写到 stderr，退出码为 2。

### C9. 整体清除覆盖（`study.py`）

- `learner_data_counts` 的返回结果新增键 `"memory_items"`，统计 `memory_items WHERE learner_id=?` 的行数。
- `purge_learner` 在同一个事务内统计并删除 `memory_items`，返回值的 `deleted` 中新增 `"memory_items"`。
- **（2026-10-05 方案审查修订）** 新分区检查（`create_session`，约第 122 行）和 `delete` 保护（约第 317 行）都是**显式列出**要检查的键 `("ledger_events", "sessions", "messages", "profiles")`，不会自动覆盖新表。这两处的键元组里都必须加入 `"memory_items"`。

## 实施方案（Codex 计划对话填写，动代码之前）

**改法：**
- `src/engine/memory/store.py`：在现有 `_SCHEMA` 末尾追加契约 C1 的 `memory_items` 表及 `idx_memory_items_lookup` 索引。继续由 `connect()` 的幂等 `executescript` 建表；不对既有表做迁移、不改变 `ensure_store()` 的旧 JSON 迁移流程。
- `src/engine/memory/long_term.py`：新建一个深模块 `LongTermMemory`，把校验、规范化、去重、状态机、确定性召回、查看和 CLI 都收拢在此处；调用方不直接操作表。构造时通过 `store.ensure_store(root)` 获取连接，时间和 ID 使用注入依赖。
  - 输入校验严格按 C2/C4：先校验 `kind`、字段白名单、`summary` 和字符串长度，再复制并清洗字符串字段的首尾空白；`tags` 的每项也清洗首尾空白并保留顺序。
  - C4 去重键实现为：`summary` 在清洗后再 `lower()`，并把连续空白折叠为一个 ASCII 空格；将清洗后的 `{"kind": kind, **content_cleaned}` 以 `ensure_ascii=False, sort_keys=True` 序列化，取 UTF-8 `sha256` 十六进制前 32 位。`source` 不参与去重。插入依赖 `(learner_id, dedup_key)` 唯一约束；冲突时返回已有 `memory_id`，不重置状态、不复活 `rejected/forgotten`、不改原内容。
  - `confirm/reject/forget` 先校验 actor，再以 `learner_id` 和 `memory_id` 定位记录；按 C5 实现成功、幂等和非法状态报错，并在状态变化时更新 `updated_at/last_actor`。`forget` 在同一更新中把 `content_json`、`source_json` 清为 `'{}'`，保留哈希墓碑。
  - `recall` 只查询当前学习者、匹配 `kind` 且 `status='confirmed'` 的记录；在 Python 私有 `_matches()` 中做大小写不敏感子串匹配，按 `updated_at DESC, memory_id ASC` 排序并限制 1–20。对实际返回的每条记录更新召回时间和次数，返回严格四字段，不返回 source。
  - `get/list_items` 只读当前学习者记录；CLI 仅实现 C8 的 `list` 和 `forget`，错误转 stderr 与退出码 2。
- `src/engine/study.py`：
  - `learner_data_counts()` 的初始字典和 SQL 统计循环加入 `memory_items`。
  - 绑定新分区与 `delete()` 的“已有数据”检查，将 `memory_items` 纳入现有检查键集合，使 P1.7 的保护通过统一计数自动生效。
  - `purge_learner()` 在现有单一 SQLite 事务中先统计 `memory_items`，再与其他 learner 分区表一起删除，并在 `deleted` 返回 `memory_items`。SQL 删除出错时整体回滚；文件删除仍在数据库提交后进行，失败只进入既有 `file_errors`，不回滚已提交的数据库清除。
- `tests/test_long_term_memory.py`：使用 `tmp_path` 的真实 SQLite，注入固定 `now/id_factory`，覆盖状态机全组合、actor 权限、隔离、去重（含 rejected/forgotten 墓碑）、遗忘清空、召回/排序/查询/计数、输入校验和 CLI。
- `tests/test_study_partition.py`：不改现有断言；新增独立用例，在 `a1-x` 写入 `memory_items` 后验证统计、绑定拒绝、purge 后为零，并验证 `demo` 的行不变及 `deleted["memory_items"]`。现有 `snapshot()` 的既有断言保持原样，新增覆盖直接查询该表。

**疑问与假设：**
- C4 只明确 `summary` 的大小写折叠和连续空白归一化；本方案对其他字符串采用“首尾清洗、语义保持”，`tags` 只清洗每项并保留顺序，不额外做 Unicode 规范化、标签排序或同义词归并。如需这些更激进的规则，应由 Claude/用户另行修改契约。
- C9 的“新分区检查和 delete 保护自动覆盖”在当前代码中并非仅调用 `any(counts.values())`，而是显式列出检查键；因此实施时必须把 `memory_items` 明确加入两个键集合，不能只新增统计字段就认为已覆盖。
- 现有 purge 成功测试对 `result["deleted"]` 是逐键断言，新增返回键不会破坏这些断言；拒绝路径比较的是同一时点的完整 `snapshot`，新增计数字段会在前后同时存在，也不改变其语义。若后续发现其他测试对旧字典做完整字面量相等，应只新增兼容性测试，不修改卡片禁止修改的既有断言。
- “新表、不需要迁移”按 `CREATE TABLE IF NOT EXISTS` 解释：老库首次打开时自动创建空表，不为历史长期记忆补数据，也不改旧迁移记录。

**风险：**
- schema 只追加表但现有数据库可能被并发连接使用；依靠 SQLite 的幂等建表、WAL 和 busy timeout，仍需全量回归确认无锁冲突。
- `memory_items` 加入 purge 后，任何遗漏 `learner_id=?` 的查询都会造成跨学习者读写或清除；主测试和 M6 突变自检必须覆盖所有读写路径。
- 去重键规范化若与未来候选提取器的字段语义不一致，会出现重复候选或过度合并；本卡只采用契约明确的确定性规则，不在数据层自行扩展语义。
- 遗忘只清空当前数据库行的原文；既有 `local_backup.py` 备份可能仍保留历史内容，本卡不修改备份代码，需由后续说明文档明确这一残留边界。
