## 契约（R2：必须逐字照办）

### C1. `study.EVENT_FIELDS` 的最终形态

```python
EVENT_FIELDS = {
    "input_observed": {"conversation_ref", "text_chars", "scene_type"},
    "intervention_decided": {
        "conversation_ref", "level", "reason", "error_count", "uncertain_count", "scanned",
    },
    "feedback_presented": {"conversation_ref", "strategies", "strategy_count"},
    "learning_confirmed": {"conversation_ref", "verdict", "covered_points", "total_points", "degraded", "source"},
    "learning_pending":   {"conversation_ref", "verdict", "covered_points", "total_points", "degraded", "source"},
    "learning_rejected":  {"conversation_ref", "verdict", "covered_points", "total_points", "degraded", "source"},
    "writeback_completed": {
        "conversation_ref", "retell_pass_count", "error_count", "notice_count",
    },
    "review_queue_observed": {"conversation_ref", "queue_count"},
    "dialog_completed": {
        "conversation_ref", "status", "fallback", "steps", "degraded_count",
    },
    "dialog_failed": {"conversation_ref", "stage", "reason"},
}
```

变更点：
- `input_observed` 删除 `text_sha256`；
- 三个学习事件删除 `kp_ids`，新增 `verdict` / `covered_points` / `total_points` / `degraded`；
- 新增 `learning_pending`；
- `writeback_completed.confirmed_count` 改名为 `retell_pass_count`。

### C2. `_validate_payload` 的校验规则

- 删除 `text_sha256` 校验和 `kp_ids` 校验；
- `verdict` 必须是 `{"pass", "partial", "fail"}` 之一；
- `covered_points`、`total_points`、`retell_pass_count` 加入非负整数校验列表；
- `degraded`、`fallback`、`scanned` 必须是 `bool`。

### C3. 复述判定到学习事件的映射

| `verify_retell` 结果中的 `verdict` | 事件类型 |
|---|---|
| `pass` | `learning_confirmed` |
| `partial` | `learning_pending` |
| `fail` | `learning_rejected` |
| 其他值或缺失 | 不发事件 |

payload：

```python
{"conversation_ref": ..., "verdict": <原值>,
 "covered_points": int(result.get("covered_points") or 0),
 "total_points": int(result.get("total_points") or 0),
 "degraded": bool(result.get("degraded", False)),
 "source": "verify_retell"}
```

`event_key` 沿用 `f"learning_result:{index}"`。

### C4. 发射接口改为惰性构造

```python
def _emit_study(self, event_type: str, build_payload: Callable[[], dict], event_key: str) -> None
```

- `self._study_event is None` 时**直接返回**，`build_payload` 一次也不调用；
- `build_payload()` 本身抛出异常时也要吞掉，这和回调异常的处理方式一致，都不阻断对话；
- 所有现有发射点都改成传入 lambda 或局部函数。

### C5. 事件顺序（一次成功的请求）

```
input_observed → intervention_decided → writeback_completed
→ [learning_* × N，按 trace 顺序] → review_queue_observed
→ feedback_presented → dialog_completed
```

`feedback_presented` 从 planner 调用之前，移到 `_build_dialog_response` 之后、`dialog_completed` 之前。内容仍然取自 `pre["strategies"]`。

### C6. `dialog_failed`

`DialogRun.run` 内部维护当前阶段变量 `stage`，取值依次为 `"pre_scan"` → `"planner"` → `"writeback"` → `"response"`。主链抛出异常时：
1. 先发 `dialog_failed`，payload 为 `{"conversation_ref", "stage": stage, "reason": type(exc).__name__}`，`event_key="failed"`；
2. 然后**原样 `raise`**，不吞异常、不改返回值。

`reason` 只写异常类名，**不写异常消息**，因为消息里可能带有原文。

### C7. 列出过期试用（只列出，不删除）

```python
def list_expired(self, now: Optional[int] = None) -> list[dict]
```

返回 `retention_until < now` 的会话，每项只含 `study_session_id`、`status`、`retention_until`，按 `retention_until` 升序排列。`now` 缺省时取 `self._now()`。

CLI 新增子命令 `expired`：`python -m engine.study expired [--root DIR]`，输出 JSON `{"now": <int>, "count": <int>, "sessions": [...]}`。

## 实现要点

**背景（审查发现）：** `skills/verify_retell.py` 的输出只有 `point_judgements / verdict / covered_points / total_points / coverage_ratio / degraded / next`，**没有任何知识点 ID**，判定取值只有 `pass / partial / fail`。现有代码去读 `knowledge_point_ids` / `kp_ids`，并把 `reject` / `rejected` 当作拒绝，所以 kp 永远为空，`partial` 也被丢弃。本卡不解决「复述对应哪个知识点」的问题，**不要尝试推导或关联 KP**。

- `dialog_run.py` 顶部的 `import hashlib` 修改后已经不再需要，删掉。`from engine.study import reference` 移到各个 `build_payload` 里面，或者在模块级惰性导入，保证不开试用时不触发。
- `trace` 的结构是 `{"name": ..., "result": ...}`（见 `src/planner/loop.py` 中的 `trace.append`）。
- 端到端测试的推荐做法：沿用 `tests/test_dialog_run_smoke.py` 里 `DialogSmokeBase` 的假 planner / 假图谱。给假 planner 构造一个包含 `verify_retell` 步骤的 trace，通过 `DialogService.dialog()` 走完整条链路。
- `retention_until` 由 `create_session` 依据注入的 `now` 写入；测试用注入的 `now` 来构造过期场景，不要 sleep。
- 不变式：锁仍然只由 `DialogService` 入口持有，`DialogRun` 内部不加锁（见 `CONTEXT.md`）。

## 实施方案（Codex 计划对话填写，动代码之前）

**改法：**
- `src/engine/study.py`：按 C1 替换 `EVENT_FIELDS`，移除 `input_observed.text_sha256` 和学习事件的 `kp_ids`，加入 `learning_pending`，并将 `writeback_completed.confirmed_count` 改为 `retell_pass_count`；按 C2 重写 `_validate_payload`，校验三态 `verdict`、非负整数计数及布尔字段。新增只读的 `list_expired(now=None)`，严格筛选 `retention_until < now`、按截止时间升序返回且每项只保留规定三字段；在现有 CLI 中增加 `expired [--root DIR]`，输出可解析的 `now/count/sessions` JSON。复用现有 `study_sessions`、`study_events` 存储，不改表结构和删除逻辑。
- `src/engine/dialog_run.py`：引入 `Callable`，把 `_emit_study` 改为接收惰性 `build_payload`；试用记录器为空时立即返回且不调用 builder，builder 或回调异常均吞掉，不影响对话。删除不再需要的 `hashlib`，将 `reference` 放进需要它的惰性 builder。把所有发射点改为 lambda 或局部 builder，按 C5 将 `feedback_presented` 从 planner 前移除并放到 `_build_dialog_response` 后、`dialog_completed` 前；保持策略内容来自 `pre["strategies"]`。按 C3 遍历 `trace` 中的 `verify_retell` 结果，`pass/partial/fail` 分别发 `learning_confirmed/learning_pending/learning_rejected`，只写规定的原值和统计字段，其他 verdict 不发事件，并使用 `learning_result:{index}` 作为幂等键；不推导或关联 KP。为主链维护 `pre_scan`、`planner`、`writeback`、`response` 阶段，异常时先以 `failed` 键发 `dialog_failed`（只写异常类名），再原样抛出，且发射失败不能遮蔽原异常。保持 `DialogService` 持锁，`DialogRun` 不新增锁。
- 测试与文档：在 `tests/test_study.py` 更新白名单断言，增加过期边界、排序和 CLI JSON 测试；在 `tests/test_dialog_run.py`、`tests/test_dialog_run_smoke.py` 更新新的事件顺序/数量，并补惰性 builder 与失败阶段覆盖；新建 `tests/test_study_flow.py`，沿用 `DialogSmokeBase` 的假 planner/假图谱，覆盖 C5 严格顺序、三态映射、未同意试用 400、无试用时零开销、planner 失败记录和 payload 无原文/无 `text_sha256`；`EVALUATION.md` 只更新“当前可复现数字”第一条的回归数字与日期，其余章节不动。

**复用：**
- 复用 `study.py` 现有 `StudyTracker` 的会话/事件写入、时间注入、事件幂等和 payload 校验框架；`list_expired` 直接基于已有 `study_sessions` 查询结果实现，不引入迁移或新依赖。
- 复用 `DialogRun` 现有的 `_emit_study` 调用位置、`pre` 预扫描结果、planner 返回的 `trace`、`_build_dialog_response`、写回与复习队列统计；复用 `DialogService.dialog()` 的试用同意校验、锁和响应错误语义。
- 复用 `skills/verify_retell.py` 已定义的 `verdict`、`covered_points`、`total_points`、`degraded` 输出，以及 `tests/test_dialog_run_smoke.py` 的测试夹具和假依赖；不改该技能契约，也不新增依赖。

**疑问与假设：**
- C4 与当前实现存在直接冲突：当前 `run()` 会无条件导入 `reference`、计算旧哈希并构造 payload，而契约要求不开试用时 builder 一次也不调用；假设可通过所有发射点改用惰性 builder 解决，并将 `reference` 导入移入 builder，若仍有入口在发射前执行试用专用逻辑，应记录为阻塞而不改契约。
- 卡片遗留问题指出普通 `LearnerMemory`/图谱数据与 A1 study 数据的删除入口分离，`study_session_id` 不能反查并清理普通会话；本卡文件边界禁止修改 `dialog_service.py`、`serve.py`、`memory/store.py`，因此只收紧 study 事件边界和过期列出，整体删除关联留给后续卡片（P2 前仍需处理）。
- `verify_retell` 不提供知识点 ID，假设本卡的学习事件只记录覆盖统计，不尝试从 `point_judgements` 或 trace 推导/关联 KP；这意味着事件暂时不能回答确认了哪个 KP。
- `dialog_failed` 的覆盖范围假设为 `DialogRun.run()` 主链四阶段中的异常；空输入、未同意试用、游客配额等入口前置拒绝不发该事件。若 `_build_dialog_response` 后、`dialog_completed` 前发生异常，按 `response` 阶段记录失败且不重复发 completed。
- C5 将 `feedback_presented` 延后到响应组装后；假设该事件表示策略已经准备/呈现的审计节点，内容仍取 `pre["strategies"]`，不改变 planner 的策略计算或实际展示文本。
- 假设旧数据库中已存在的事件 payload 可以保留旧字段；校验和测试只约束本次新写入事件，不做历史数据迁移。

**风险：**
- 严格事件顺序可能暴露除主链外的现有调用路径或测试夹具，需要逐一确认所有发射点仍符合 C5；`feedback_presented` 的时机变化也可能影响依赖旧顺序的统计。
- planner、writeback 或 response 异常时，失败事件本身的构造/回调可能再次失败；实现必须确保发射失败不遮蔽原异常，并始终保留原异常类型、消息和返回语义。
- 惰性 builder 若有任一发射点遗漏，仍会在未开启试用时触发 `reference`、原文相关计算或其他副作用；需用零开销测试覆盖所有主链路径。
- `partial` 从被丢弃改为 `learning_pending` 后，会改变学习事件数、后续统计和复习确认语义；`fail` 也必须保持仅产生 rejected。
- `list_expired` 的边界必须是严格 `<`，等于 `now` 的会话不能列出；排序和 CLI 输出字段缺失都会造成运维误判。
- 不修改 schema 会保留旧事件中的旧字段，历史数据与新白名单可能并存；同时试用记录与普通会话/图谱的删除边界仍未解决，属于 P2 前的持续数据治理风险。

附加执行要求：
- **A1（零开销测试要能证明自己有效）**：`from engine.study import reference` 必须写在 builder 函数**内部**，不能写在模块级。原因是：如果在模块级写成 `from … import`，`dialog_run` 会持有自己的一份引用，测试里 patch `engine.study.reference` 就不会生效，零开销测试即使 builder 被调用了也照样通过，变成假阳性。零开销用例里还要**加一个对照**：保持同样的 patch，开启已同意的试用，再跑一次对话，断言对话仍返回 200 且**试用事件数为 0**（所有 builder 都依赖 `reference`，被 patch 后全部抛异常并被吞掉）。这个对照证明 patch 确实命中了。
- **A2（失败记录不能改变原有行为）**：异常路径用 `except Exception` 捕获（不要捕获 `BaseException`，以免拦下 `KeyboardInterrupt`），在 except 块里调用 `_emit_study` 发出 `dialog_failed`，然后**直接写 `raise`**，不要写 `raise exc` 或包装成别的异常，以保留原始 traceback。失败用例中除了断言 `stage` 和 `reason`，还要断言 `dialog()` 抛出的就是测试注入的**同一个异常对象**（用 `assertIs` 比较 `ctx.exception`）。
