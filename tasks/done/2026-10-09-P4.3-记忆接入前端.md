## 目标

1. 学习者开新对话时，看到一张开场卡：上次练过场景的，问一句"要接着练吗"；有待确认的记忆候选，逐条选"记住"或"不用"。
2. React 前端补上场景选择入口，不再只能从 /legacy/ 进入场景。会话会记住自己属于哪个场景，重新打开时能恢复。
3. 设置里新增「我的记忆」页：查看全部已记住的内容、逐条遗忘、全部遗忘，以及记忆总开关。
4. 无痕对话（简版）：新对话可以设为无痕。无痕对话不会被提取成记忆，也不会注入已确认的记忆；对话记录和学习数据照常保留。

## 契约（R2）

### 后端

- 无痕标记由**前端第一条 dialog 请求**携带 `incognito: true`，`dialog_run` 写入 sessions。之后每轮请求都会带上，写入是幂等的。已经是普通会话的，不能中途改成无痕（第一轮之后的 `incognito=true` 忽略）。判断"第一轮"用 `history` 是否为空。
- 当前会话已标记无痕，或本次请求 `incognito=true` → `memory_brief` 必须为 `""`，不调用 recall。
- `previous_session` 的 SQL 增加 `AND s.incognito=0`。这样无痕会话既不会被扫描提取，也不会出现在续接提议里。
- `session_meta(session_id) -> {"scene_id": str, "incognito": bool} | None`。
- `GET /api/conversation` 响应顶层增加 `"scene_id": str`、`"incognito": bool`；会话不存在时取 `""` 和 `false`。
- `POST /api/memory/forget_all`：请求 `{}`，可选带 `learner`。把该 learner 所有状态不是 forgotten 的条目逐条 `forget(actor="learner")`，返回 `{"forgotten": n}`。

### 前端

**开场卡（OpeningCard）**
- 触发条件：Speak 页对当前 convId 恢复会话后，`lines` 为空（全新对话），并且不是无痕会话 → `POST /api/memory/opening {conversation_id}`。每个 convId 只请求一次（用 ref 去重）。
- 显示条件：`enabled` 为 true，并且 `resume` 或 `candidates` 至少有一个非空，才显示；否则什么都不渲染。
- `resume` 一行：「上次在「{title_zh}」练习，要接着练吗？」，按钮 [接着练] 和 [不用]。点「接着练」→ 当前会话设为该 scene_id，然后自动发送该场景的 seed，复用现有的 `send(prefill)`。
- 每条候选一行：summary（有 place/when 时附上），按钮 [记住] 调 confirm，[不用] 调 reject。点完这一行就消失，失败用 toast 提示，这一行保留。
- 卡片底部一行小字：「只有你点了"记住"的内容，教练以后才会提起。可在 设置 → 我的记忆 管理。」，链接打开设置的 memory 标签页。
- 开场卡容器 `role="region"`，`aria-label` 为「开场」。按钮都是真正的 `<button>`，能用键盘操作。

**场景选择（ScenePicker）**
- 全新对话、并且当前会话还没有 scene_id 时，在「来一次吧」按钮下方显示 `/api/scenarios` 返回的场景卡：显示 title_zh 或 title（按界面语言）、等级、goals 前 3 个。
- 点卡片 → 设置当前会话的 sceneId（组件状态），然后发送 seed。sceneId 从此随该会话的每轮 dialog 请求发出。
- 恢复会话时，sceneId 取 `/api/conversation` 返回的 `scene_id`。有场景时顶部显示场景名标签。
- 接口失败或返回空列表 → 不渲染，不报错。

**无痕**
- Sidebar 的「新对话」旁边加一个次级按钮「无痕对话」→ `newSession({incognito: true})`。
- 前端用 `sessionStorage` 记住 `incognito:<convId>`，第一条请求前就能知道这是无痕会话。恢复会话时以 `/api/conversation` 返回的 `incognito` 为准。
- 无痕会话：dialog 请求带 `incognito: true`；不请求 opening；对话区顶部显示标签「无痕 · 这段对话不会被记住」，加明显的边框样式；侧栏列表项显示无痕图标，`aria-label` 为「无痕」。

**设置 → 我的记忆（memory 标签页）**
- 开关「记忆」，说明文字：「开启后，教练会在新对话开头询问是否记住你分享的经历；只有你确认过的内容才会被使用。」切换时调 `POST /api/profile {memory_enabled}`。
- 列表：`GET /api/memory?status=confirmed`，每条显示 summary、place/when、确认日期，配 [遗忘] 按钮。遗忘后从列表中移除。
- 「待确认」小节：`status=candidate`，每条配 [记住] 和 [不用]。
- [全部遗忘] 按钮：先弹 `window.confirm("确定遗忘全部记忆吗？此操作不可撤销。")`，确认后调 forget_all，再刷新列表。
- 列表为空时显示「还没有记住任何内容。」。操作结果的提示用页内 `role="status"` 区域，这个区域要常驻 DOM。

所有新文案都要写进 i18n 的 zh 和 en，组件里不准硬编码字符串（现有 Speak 页的硬编码不在本卡处理范围）。

### 二、逐文件实施办法与调用时序

#### 1. 数据层与后端入口

- `src/engine/memory/store.py`：在新库 `_SCHEMA.sessions` 增加 `incognito INTEGER NOT NULL DEFAULT 0`；旧库沿用 `connect` 的 `PRAGMA table_info(sessions)` 检查及条件 `ALTER TABLE`。重复连接不重复迁移，历史记录默认 0，保留既有 `scene_id`、`memory_scanned_at` 和所有消息，不重建表、不动真实用户库。
- `src/engine/memory/learner_memory.py`：在 `touch` 尾部增加可选 `incognito=None`，保持旧调用签名兼容，None 不更新，bool 用 0/1 绑定参数写入。`list_sessions` 的显式查询及响应投影增加 `scene_id`、bool 类型 `incognito`，不改变排序及原字段。新增 `session_meta(session_id)`，复用 `_safe`，查询同时绑定 `learner_id`、`session_id`，仅返回契约两字段或 None，不隐式创建会话。`previous_session` 原 SQL 增加 `AND s.incognito=0`，保持 user 消息存在条件及原排序，让最近无痕会话被跳过、可选到更早普通会话。
- `src/engine/dialog_service.py`：在 `_load_session_context` 读取 `payload.get("incognito", False)`，用严格 bool 检查拒绝显式 null、数字、字符串等，返回 400；不使用 `bool(value)` 强制转换。合法值加入 ctx。校验在 `_consume_visitor_quota`、provider 解析、`DialogRun`、消息/学习事件写入之前，缺失字段继续为 False。
- `src/engine/dialog_run.py`：`run` 先取 history，再读取当前 `session_meta`；分别计算 `first_round = not history`、`requested_incognito = ctx.get("incognito", False)`、`effective_incognito = stored_incognito or requested_incognito`。给 `_assemble_directives` 增加末尾默认参数以传入有效无痕状态，召回分支在创建长期记忆/调用 recall **之前**检查该状态；无痕直接保持 `memory_brief=""`，不先召回再清空。普通首轮仍按原开关召回，普通后续轮仍不召回。
- 无痕写入时序：仅 `first_round and requested_incognito` 才调用 `touch(conversation_id, incognito=True, bump=False)`；安排在 directives/planner 和首条消息 append 之前，在既有服务锁内完成。这样首轮生成或后续写回失败时，空会话仍带无痕标记；没有 user 消息就不会被 `previous_session` 选中。标记读写失败不可套用场景写回的吞异常路径，不允许先保存普通消息再静默失败；沿既有异常链退出，不新增 SSE 契约。首轮 False 不写清除操作；普通第二轮 True **不落盘**，但本次请求仍抑制召回；持久化为 True 时，即使请求省略/False 也不能重新启用召回。保留原 `scene_id` 写回、历史、图谱、学习数据和事件顺序。
- `src/engine/serve.py`：`GET /api/conversation` 在原锁内读取 `session_meta`，顶层追加 `scene_id`、`incognito`；None 时严格返回 `""`、false，消息及 metadata 白名单不变。新增 `POST /api/memory/forget_all`，复用 JSON 对象校验、可选 learner 的默认解析、服务锁及 `_memory_root`，创建该 learner 的 `LongTermMemory`；取条目快照，仅对 `status != "forgotten"` 的条目逐个 `forget(memory_id, actor="learner")`，按成功次数返回 `{"forgotten": n}`，finally 关闭连接。保留墓碑，不物理删除、不跨分区遍历，不自创批量 SQL 更新。默认 GET 的空列表冲突处理见第三节，未经审查不改其语义。

#### 2. 会话状态、恢复及发送

- `web/src/lib/session.tsx`：Session 类型追加 `scene_id`、`incognito`，Profile 追加 `memory_enabled`；上下文及实现同步改为 `newSession(opts?: {incognito?: boolean})`，全部既有无参调用有效。新建无痕时，在 `switchSession(id)` 触发渲染 **之前**写入 `sessionStorage["incognito:" + id]`；普通新建不继承上一个会话的标记。侧栏首次未落盘占位可读取此标记；已落盘列表用服务端值。删除成功时清理对应本地标记，不把 sessionStorage 当永久权威。
- `web/src/pages/Speak.tsx`：增加当前 `sceneId`、`incognito`、恢复完成状态和对应会话身份引用（ref）。切 convId 时先失效旧异步任务、停止旧流，再清理画面并读取新 convId 的本地意图；不能因临时 `setLines([])` 就触发 opening。conversation 响应成功且属于当前 convId 后，恢复原 user/recog/trace/assistant 顺序，并设置服务端场景及无痕信息。未落盘无痕的特殊取值须先解决第三节疑问 1。
- 恢复成功后才判定“全新”：依据本次响应恢复出的消息为空，而不是上一渲染的 lines。恢复失败不假定新会话、不发 opening；未确认元数据时不自动发送场景 seed，避免错误场景或隐私标记。保留 outbox 的“恢复后消费”顺序，消费前先检查 alive/当前 convId；元数据未就绪时保留待发内容，不让迟到的旧 effect 消耗它。
- `send(prefill, badge)` 保留兼容，增加可选的本次发送上下文参数，例如第三参数 `{sceneId, incognito}`。场景按钮先更新状态再显式传入 **同一份** sceneId 发送 seed，不依赖 `setSceneId` 的下一次渲染；恢复后立即消费 outbox 同样传本次恢复的局部元数据。其他输入/卡片分支使用当前会话上下文，每轮 dialog payload 增加 `scene_id`、bool `incognito`。同步发送锁用 ref 防止同一渲染内双击发两次；busy 仍用于画面。既有 badge、输入和停止按钮保持兼容。
- opening 用按 convId 存放 Promise/结果的 ref Map 去重，不仅仅用“请求过”的 Set：React 严格模式（StrictMode）重跑 effect 时复用同一请求，新 effect 能消费结果，避免首个 effect cleanup 丢结果、第二个又被去重拦住。仅恢复成功、新会话、非无痕时创建一次 `POST /api/memory/opening`；失败也记入本会话去重记录，不在 render/refresh 时自动重试。请求、操作结果及 SSE 回调均核对 convId/发送身份，旧会话结果不得写入新画面；切换后取消或忽略旧结果。
