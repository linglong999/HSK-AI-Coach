## 契约（R2：必须逐字照办）

```python
# intervention.py
def decide_intervention(text, max_conf=1.0, recent_error_flags=None,
                        interrupt_used=0, cap=DEFAULT_CAP, last_level="none",
                        diagnosed: bool = False) -> Tuple[str, str]: ...
# 判定顺序：cap → help → frustrated → diagnosed → unclear → empty/streak → fluent
# diagnosed=True → ("block", "diagnosed")

class InterventionTracker:
    def observe(self, text, max_conf=1.0, error_flag=None, cap=DEFAULT_CAP,
                diagnosed: bool = False) -> Tuple[str, str]: ...
```

- **诊断条目**的定义是 `pre_scan["errors"]` 中满足 `e.get("source") == "construction_diagnostics" and e.get("verdict") == "error"` 的项。只看 `errors`，不看 `uncertain`；edge 级仍进 `uncertain`，行为不变。
- `max_conf` 改为只在**非诊断条目**（errors 中的其余项加上全部 uncertain）上取最大值；一项都没有时取 1.0。`error_flag` 的计算不变，诊断条目仍算本轮有错。
- `_REASON_LABEL`：`"diagnosed"` 中文为「构造诊断判错」，英文为 `"construction check failed"`。
- block 指令：`reason == "diagnosed"` 时用独立文案，不复用"含义不清"的那段。中文文案的意思是：「本轮规则诊断已确定这里有结构错误：请直接指出问题所在，按下方 [FeedbackStrategy] 的形态处理；如为明确纠正，给出正确说法与规则，再引导学习者复述。」英文给出对应译文。文案措辞由 Codex 定，但必须包含"按 [FeedbackStrategy] 处理"这层意思，否则同一会话第二次出现时（已深攻过，策略降为 local_question）指令会互相矛盾。
- `_study_strategies`：不再因 `target_kp` 为空而跳过，空串照常写入 `kp_id: ""`。`study.py` 现有校验已允许空串，不改 `study.py`。

## 实施方案（Codex 计划对话填写，动代码之前）

**改法：**

- `src/engine/intervention.py`：在 `decide_intervention` 末尾新增兼容默认值为 `False` 的 `diagnosed` 参数，并在 cap、help、frustrated 之后、unclear 之前判断；命中时返回 `("block", "diagnosed")`。同步给 `InterventionTracker.observe` 增加同名参数并原样传入，保持现有调用的关键字/位置兼容。扩展 `_REASON_LABEL` 的中英文 `diagnosed` 标签，并在 `build_intervention_directive` 的 block 分支增加独立中英文文案；文案明确规则诊断已确定结构错误、按 `[FeedbackStrategy]` 处理、明确纠正时给出正确说法与规则并引导复述。更新函数 docstring 和允许的 reason 说明，不调整任何既有阈值。
