## 1. 总体目标与设计约束

### 1.1 目标

把“引导而不是代答”落实为一条可以被真实用户使用、被系统记录、被人工复盘、被后续调整的产品链：

```text
真实场景输入
  -> 确定性预扫与介入时机
  -> 反馈表达策略
  -> 用户继续、求助、拒绝或复述
  -> 事件账本/错误图谱/记忆写回
  -> 复习或下一次连续开场
  -> 匿名试用记录与人工复盘
```

### 1.2 约束

- 近期只支持单机使用，真实数据留在本机受保护目录。
- A1 是内部可用性试验，不是模型性能、教师仲裁或学习增益实验。
- 真实学习者数据必须有协议、匿名编号、保存期限和删除路径后才能采集。
- 先复用当前 SQLite、事件账本、错误图谱和 `LearnerMemory`；只有现有接口确实不够时才增加新模块。
- LLM 可以生成候选内容，但不能未经确认直接写入“已确认生活事实”或改变教学规则。
- 每个新增模块都要有一个小而稳定的接口；调用方不直接操作 SQLite 表或内部状态。

## 3. 数据状态模型

### 3.1 A1 试用状态

```text
created -> consented -> active -> completed
                     \-> withdrawn
```

- `created`：只生成匿名试验编号，未采集学习事件。
- `consented`：协议版本和同意时间已记录，可以开始采集。
- `active`：正在使用。
- `completed`：试用者主动结束或达到内部观察目标。
- `withdrawn`：撤回后禁止继续写入，并触发该编号的数据删除流程。

### 3.2 学习事件状态

```text
observed -> pending_confirmation -> confirmed
                         \-> rejected
```

未确认事件不能进入已确认学习记忆，也不能单独改变复习队列。现有图谱的 `pending/confirmed` 状态继续作为偏误确认的权威来源，A1 记录只引用状态变化，不复制另一套偏误状态机。

### 3.3 生活经历记忆状态

```text
candidate -> confirmed -> recalled
      \-> rejected       \-> forgotten
```

候选可以由规则或 LLM 结构化提取，但只有用户明确确认后才可在后续开场中作为事实使用。`forgotten` 使用软删除或删除标记，召回查询必须排除。

## 4. 模块设计

### 4.1 `StudyTracker`：A1 试用记录模块

建议位置：`src/engine/study.py`。它是一个深模块，向调用方暴露少量操作，隐藏事件表、脱敏、保存期限和导出细节。

建议接口：

```python
class StudyTracker:
    def create_session(self, protocol_version: str, scene_type: str) -> str: ...
    def consent(self, study_session_id: str, consent_version: str) -> None: ...
    def record(self, study_session_id: str, event_type: str, payload: dict) -> None: ...
    def complete(self, study_session_id: str, reason: str = "") -> None: ...
    def withdraw(self, study_session_id: str) -> dict: ...
    def export_summary(self, study_session_id: str | None = None) -> dict: ...
```

接口不接受 API Key、完整异常堆栈或未经协议允许的原始身份字段。`record` 对事件类型和 payload 做白名单校验；不合规事件返回结构化拒绝结果或抛出明确的 `ValueError`，不静默写入。

建议新增 SQLite 表：

- `study_sessions`：匿名编号、协议版本、场景、状态、创建/结束时间、保存截止时间；
- `study_events`：试用编号、事件类型、会话 ID、结构化 payload、时间；
- 可选 `study_consent`：同意版本、同意时间、撤回时间、协议摘要哈希。

原始学习者文本是否保存必须是协议中的独立选择。默认导出聚合字段；若为复盘确需保存原文，放入单独受保护目录并带 `retention_until`，不能随普通日志永久保存。

### 4.2 反馈策略接口

继续使用 `feedback_selector.py` 作为唯一策略模块。把现有偏好/标签扩展成稳定结构：

```python
FeedbackDecision(
    mode="recast|intonation_hint|local_question|contrastive_hint|explicit_correction",
    hint_level="none|light|medium|strong",
    reason_code="...",
    target_error="...",
    user_requested_help=False,
)
```

`intervention.py` 的时机结果仍然是上游输入；策略模块不得自行把 `none` 改成 `block`。`compile_strategy_section` 负责将决定编译成给 LLM 的内部指令，响应层和 A1 记录同时保存结构化决定，避免从自然语言反推策略。

### 4.3 三层记忆接口

现有 `LearnerMemory` 继续只负责会话历史、摘要、画像和删除会话。新增 `src/engine/memory/long_term.py` 的 `LongTermMemory` 深模块负责经历候选、确认、召回和遗忘；调用方不直接更新 `profile_json` 或 `memory_items` 表：

```python
class LongTermMemory:
    def add_candidate(self, kind: str, content: dict, source: dict) -> str: ...
    def confirm(self, memory_id: str, actor: str) -> None: ...
    def reject(self, memory_id: str, actor: str) -> None: ...
    def recall(self, kind: str, query: str = "", limit: int = 5) -> list[dict]: ...
    def forget(self, memory_id: str, actor: str) -> None: ...
```

三层映射如下：

- 短期对话记忆：现有 `sessions/messages`，按会话窗口注入；
- 学习记忆：现有错误图谱、账本和 `profile.common_errors`，不重复存一份偏误事实；
- 经历记忆：由 `LongTermMemory` 管理独立的 `memory_items` 表，`kind=life_event`，必须经过确认才可召回。

第一版召回使用 SQLite 的确定性过滤、标签和时间排序；`LongTermMemory` 内部预留检索适配器接缝，未来确有规模需要时再替换实现。当前不引入向量数据库。
