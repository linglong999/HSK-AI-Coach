# HSK-AI-Coach 全库审查报告

**审查日期：** 2026-09-29

**审查基线：** `main` / `070e6dd8a5e65e2de763c66f2ffd5a45991b8be0`

**审查范围：** 源码、前端、数据集、评测管线、测试、CI、README、设计文档、架构图

## 0. 结论摘要

HSK-AI-Coach 已经超过普通 LLM Demo，形成了一个可运行的“偏误诊断 + 解释 + 复述验证 + 图谱记忆 + 间隔复习”教学引擎，并配有 React 产品壳、SSE 对话、多供应商接入、OCR、评测资产和 CI。

当前状态更准确的定义是：**教学研究型产品原型，适合本地使用和受控内测；尚未达到公网生产就绪。**

最需要处理的不是继续堆功能，而是四件事：

1. 修复当前失败的确定性教学回归。
2. 统一 README、架构图、CI、实施计划和代码的事实口径。
3. 收紧公网安全边界，特别是认证、CORS、BYOK 密钥和任意 Base URL。
4. 把“代码能运行”与“学习者确实学会”分成两套证据体系。

## 1. 本轮复核方法与证据

本轮特别针对上一版结论做了反证复核：

- 检查 Git 基线、分支状态、提交历史和唯一作者信息。
- 对照 `pyproject.toml`、`README.md`、CI、架构图和实际源码。
- 统计测试函数数量并执行 Python 测试。
- 单独复跑失败的 `run_all` 确定性闸门，取得具体失败用例。
- 执行前端 TypeScript/Vite 生产构建。
- 检查 API 路由、锁、文件存储、密钥处理、Cookie、CORS、调试开关和 SSRF 风险。

### 1.1 可复现命令结果

在项目对应的 Python 3.12 解释器、`src` 和项目根目录加入 `PYTHONPATH` 后：

```text
pytest tests -q --ignore=tests/test_run_all.py
1058 passed, 7 skipped, 32 warnings
```

前端构建：

```text
npm.cmd run build
vite v5.4.21
✓ 52 modules transformed
✓ built
```

完整测试不能标记为全绿。`tests/test_run_all.py` 的确定性回归失败，具体结果为：

```text
tutor_l1_l3: total=27, passed=26, pass_rate=0.963
fail_ids=["TQ-HSK2ERR005"]
```

失败样例是：

```text
我把书在桌子上放了。
```

因此，“1058 passed”只能表示排除 `test_run_all.py` 后的测试结果，不能表述为完整回归通过。

### 1.2 关于 AI 生成代码

用户说明主要代码由 DeepSeek v4 和 GLM 5.3 协助完成。Git 历史显示提交作者为同一人工账号，仓库没有保存完整的模型、提示词、会话或人工复核记录，因此无法从仓库独立验证每一段代码由哪个模型生成。

这不改变审查结论。AI 生成代码的审查重点应放在：

- 需求是否变成可执行契约；
- 边界条件是否有测试；
- 失败路径是否诚实暴露；
- 文档是否与实现同步；
- 安全假设是否经过攻击路径验证；
- 测试是否覆盖真实集成，而不是只覆盖 mock。

本库已经有不少很好的确定性护栏，但也出现了 AI 协作项目常见的组合风险：旧注释残留、跨批次演进后的口径漂移、广泛 `except`/`pass`、本地安全假设被带入公网场景，以及测试数量增长快于真实学习证据。

## 3. 架构设计审查

### 3.1 已验证的优点

架构图 v3 与当前代码主干基本一致：

```text
React 产品壳
  → FastAPI / SSE
  → VisitorGate
  → DialogService
  → Planner / Skills
  → 识别、解释、验证和生成
  → 偏误图谱、SQLite 记忆、FSRS、评测
```

关键证据：

- `src/engine/serve.py`：FastAPI 路由、SSE、静态托管和邀请守卫。
- `src/engine/dialog_service.py`：共享业务编排和回合写回。
- `src/planner/loop.py`：Planner ReAct 主循环。
- `skills/registry.py`：技能注册表。
- `src/engine/graph/error_graph.py`：确定性图谱服务。
- `src/engine/memory/store.py`：SQLite 账本、会话、消息和 profile。
- `src/engine/scheduler/fsrs_adapter.py`：FSRS 适配。

设计上最有价值的原则是“LLM 负责生成候选，规则负责守门，图谱负责权威写入”。迁移解释作为候选而不是确诊，也减少了模型推断污染教学数据的风险。

### 3.2 架构风险

1. `DialogService`、图谱和 HTTP 层共享 `RLock`。它保证单进程一致性，却会把关键业务闭环串行化，限制吞吐，并放大一次慢 LLM 请求对其他请求的影响。
2. SQLite、JSON 配额文件和 JSON provider store 是单机状态方案。多进程、多实例、容灾和跨节点一致性没有设计。
3. 架构图是逻辑架构图，不是生产部署图。它没有呈现认证主体、租户隔离、反向代理、TLS、监控、告警、备份、恢复和密钥轮换。
4. `web_legacy` 仍作为第二个壳存在。它有兼容价值，但会增加入口、契约和文档同步面。

### 3.3 建议

先保留单机架构，明确产品边界；只有当真实并发和多用户需求出现后，再拆分状态服务。拆分前应先补：请求 trace、锁等待时间、LLM 延迟、失败率和每用户成本指标。

## 4. 教学法内核审查

### 4.1 已验证的优点

- 教学闭环不是单轮纠错，而是“发现偏误 → 解释 → 复述 → 写回 → 复习”。
- `none / light / block` 介入策略适合口语陪练，避免每句都打断。
- 母语迁移被标为候选假设，不直接进入确诊图谱。
- `unpack_guard` 对超纲词执行检测、重试和降级。
- 脚手架有渐退逻辑，且失败后可以回撤一档。
- 正向证据、复习反馈和 fossil priority 让图谱不只记录错误。

### 4.2 教学证据的边界

README 已诚实说明黄金集主要为自建、自审，尚未经二语教师仲裁。当前指标能证明部分工程行为和规则一致性，不能单独证明长期语言能力提升。

尚缺少以下证据：

- 前测/后测和延迟后测；
- 不同母语、等级和任务类型的分层结果；
- 教师盲评；
- 新题和迁移题泛化；
- 与规则纠错、普通 LLM 或人工反馈的对照；
- 学习者是否真的减少同类错误，而不是只在验证题上答对。

当前 `TQ-HSK2ERR005` 的失败还说明：教学红线仍会在确定性回归中被击穿，必须先修复或重新裁定预期行为，再继续扩大指标宣传。

## 5. 工程质量审查

### 5.1 已验证的优点

- 代码分域清晰：`engine`、`planner`、`skills`、`datasets`、`eval`、`web`、`tests`。
- 测试覆盖图谱、诊断、生成、验证、SSE、会话、BYOK、配额、前端静态资产等多个层面。
- CI 包含 Python 回归、确定性评测和 React 构建。
- 生产前端构建已经成功。
- SQLite 使用 WAL、busy timeout 和原子迁移；图谱快照使用临时文件替换。

### 5.2 问题

1. 完整回归未通过，且失败用例耗时约 175 秒，影响反馈速度。
2. 当前工作站的 `.venv` 是从 Python 3.12 环境迁移而来，直接使用系统 Python 3.11 会出现 `pydantic_core` 二进制不匹配；直接 `uv run` 也不可用。这属于环境复现问题，不应误判为业务代码失败，但安装文档必须让新用户避开它。
3. README 测试数量为 640，架构图写 1074，实际本次统计约 1072 个测试函数。多套数字会削弱可信度。
4. 广泛的异常吞掉和 `pass` 需要按“可忽略、可降级、必须失败”重新分类，尤其是配额落盘、LLM、迁移和网络调用路径。

## 7. 安全与部署审查

当前适用边界：**本地使用、个人使用、受控内测。**

### 7.1 P0/P1 安全问题

1. `INVITE_ALLOWLIST` 默认为空，邀请守卫默认旁路。
2. CORS 使用 `Access-Control-Allow-Origin: *`。
3. BYOK 完整 API Key 明文写入 `data/llm_providers.json`。
4. `/api/providers/test` 接受任意 `base_url` 并由服务端发起请求，存在 SSRF 风险。至少要阻断 localhost、私网网段、链路本地地址、云元数据地址和重定向绕过。
5. `DEBUG=True` 默认开启。
6. 没有正式的生产部署文件、TLS、反向代理、备份恢复、密钥轮换和数据删除说明。
7. 用户输入、自定义指令和外部检索内容进入 LLM 上下文，需要继续验证 Prompt Injection、工具调用边界和敏感信息外泄。

### 7.2 已有的安全措施

- `.env`、数据库、provider store 和运行数据已加入 `.gitignore`。
- API 列表接口对 Key 做掩码。
- 游客 Cookie 使用 `HttpOnly`、`SameSite=Lax`，检测到 HTTPS 时附加 `Secure`。
- 邀请守卫同时保护页面和 `/api/*`。
- 静态资源路径有路径穿越防护。

这些措施能降低本地误操作风险，但不足以构成公网安全方案。

## 8. 产品完成度与行业位置

### 8.1 已形成的产品能力

- React 产品壳和 7 个页面；
- SSE 对话和结构化结果卡；
- 图谱、复习、报告和度量面板；
- BYOK 和多供应商切换；
- 游客能量与回合限制；
- OCR/文档输入；
- 会话、profile 和长期记忆；
- HSK 3.0 词表、考纲和教材映射；
- 确定性评测和 CI。

### 8.2 距离成熟产品的差距

- 没有账户、多设备同步和真正的多租户隔离；
- 没有数据导出、删除、保留期限和隐私政策闭环；
- 没有生产级日志、监控、告警和成本治理；
- 语音输入、发音反馈和口语评测尚未形成完整链路；
- 缺少大规模真实学习者数据；
- 缺少正式课程、任务编排和长期学习目标系统。

更准确的行业定位是：**面向 HSK 学习者的可审计、偏误驱动、LLM 增强型中文教学引擎原型。**

## 9. 建议整改顺序

### P0：恢复可信发布基线

1. 修复或重新裁定 `TQ-HSK2ERR005`，让 `run_all --layer deterministic` 通过。
2. 在 CI 中明确区分“测试通过”和“评测闸门通过”。
3. 统一测试计数、评测样本数和指标口径。
4. 给每个公开指标增加：样本来源、样本量、是否人工仲裁、运行命令、最后更新时间。

**完成条件：** `pytest tests -q` 和 `python -m datasets.eval.run_all --layer deterministic` 均返回 0；README 的数字可由命令直接复现。

### P1：完成文档事实收口

1. 更新 README 的依赖、Python 版本、前端技术栈、服务框架、测试数和启动方式。
2. 更新架构图中的评测口径，删除过时的 κ 门槛，补充“逻辑架构图，不代表公网部署”的说明。
3. 更新实施计划和 CI 注释中的 ThreadingHTTPServer 旧描述。
4. 新增 `ARCHITECTURE.md`、`EVALUATION.md`、`SECURITY.md`、`DEPLOYMENT.md`，分别指定唯一事实来源。

### P1：公网安全加固

1. 默认要求认证或明确只监听本机；公网启动必须显式开启。
2. 将 CORS 改为配置化 allowlist。
3. 对 provider Base URL 做协议、域名、IP 解析、重定向和私网阻断。
4. API Key 改为系统密钥库、加密文件或至少受权限保护的独立 secrets 文件。
5. 默认 `DEBUG=False`，响应中不返回内部异常细节。
6. 补充反向代理、TLS、备份、恢复、密钥轮换和数据删除流程。

### P2：教学效果证据升级

1. 建立教师仲裁集和双人复核流程。
2. 按等级、母语、任务和偏误类型扩充评测。
3. 增加前测、后测、延迟后测和新题迁移。
4. 与基线系统做对照实验。
5. 将“系统判断正确率”和“学习者长期习得”分开发布。

### P3：产品化与可运营性

1. 增加用户身份、租户隔离和跨设备同步。
2. 增加结构化日志、trace、指标、告警和成本预算。
3. 将配额、供应商、会话和数据迁移从单机文件方案抽象为可替换存储接口。
4. 补齐语音、课程、任务和长期目标能力。

## 11. 当前审查结论

项目方向成立，教学内核是仓库最有价值的部分，架构图 v3 也已经能够较准确地表达当前主干实现。当前阻碍项目可信发布的主要因素是评测闸门未全绿、事实文档未收口和公网安全边界不足。按 P0 → P1 → P2 → P3 执行，能够以较小改动先恢复可信度，再逐步补齐安全、教学证据和产品化能力。
