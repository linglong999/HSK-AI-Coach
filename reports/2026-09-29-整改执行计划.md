### P1-4 本轮实施方案（先落盘，后改代码）

- Windows 单机：UI 添加的 BYOK Key 使用当前 Windows 用户的 DPAPI（数据保护 API）加密后落盘；旧版明文供应商文件首次读取时原子迁移。仅保存在当前用户/当前系统可解密，跨设备恢复需重新填写 Key。
- 非 Windows：暂不声称加密，继续使用仅当前用户可读的文件权限；公开部署前必须改用密钥管理服务。`.env` 仍是明文配置文件，不由本轮自动改写。
- 加密/迁移失败必须明确报错并保留旧文件，不允许悄悄当作空供应商清单；在临时目录验证写入、读取、迁移和失败保护，不读取真实 `data/llm_providers.json` 的 Key。

### P1-5 本轮实施方案（只在隔离目录演练）

- 备份工具复制 `data/` 顶层文件，并通过 SQLite backup API 生成一致的 `coach.db` 副本；生成哈希清单。要求先停止本机服务，避免图谱/JSON 在快照期间变化。
- 恢复只允许写入不存在的新目录；先验清单和哈希，不覆盖现有用户数据。Windows DPAPI 文件仅能在原 Windows 用户/系统环境解密，跨设备恢复需重新添加 BYOK Key。
- 删除与轮换先形成明确操作清单，并仅在临时目录测试，不对真实 `data/` 运行清理命令。
