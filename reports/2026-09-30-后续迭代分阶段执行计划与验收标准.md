# HSK-AI-Coach 后续迭代分阶段执行计划与验收标准

**制定日期：** 2026-09-30

**适用阶段：** 单机真实使用准备与小规模内部试用

**上游依据：** 《HSK-AI-Coach-产品总纲与改造文档》、2026-09-29 全库审查与整改计划、用户确认的需求取舍

**详细编排：** 具体模块接口、P1–P5 任务依赖和文件级验收见[《后续迭代架构设计与任务编排》](2026-09-30-后续迭代架构设计与任务编排.md)。

## 1. 已确认的产品决策

本轮需求取舍已经确定，后续执行不再反复讨论以下方向：

1. 产品核心命题是“AI 负责引导，而不是直接代答”。
2. 第一批真实使用者为项目作者本人和少量留学生。
3. “三位学习者各约 20 句/次有效互动”属于内部可用性试验，不属于模型性能验收，也不构成学习增益证据。
4. 提示表达层先实现五类固定策略，再根据真实使用记录调整；第一版不追求完全个性化。
5. 记忆分为短期对话记忆、学习记忆和经历记忆，复用现有 SQLite、事件账本和错误图谱。
6. 执行顺序为：A1 真实场景使用闭环 → 提示表达层 → 对话记忆 → 教学法文档。
7. 真实二语教师双人标注与终裁、补充母语/等级元数据、真实学习者对照实验，留到正式留学生教学阶段。
8. 近期保持单机使用；账户体系、租户隔离、公网身份认证、生产费用硬上限和完整目录迁移不属于本轮执行范围。

## 2. 证据边界

本计划中的证据分为四类，发布或验收时必须标明类别：

| 证据类别 | 可以证明 | 不能证明 |
|---|---|---|
| 工程回归 | 代码在既有测试和契约下未回归 | 真实学习效果、外部泛化能力 |
| 内部可用性试验 | 真实用户是否能完成流程、是否理解反馈、闭环是否可用 | 模型准确率、行业水平、长期学习增益 |
| 教学专家仲裁 | 标注和反馈是否符合二语教学判断 | 学习者长期进步 |
| 学习增益实验 | 在明确实验设计下的学习结果和迁移 | 对所有学习者、模型或场景的普遍结论 |

A1 阶段只产生前两类证据。任何 A1 报告不得使用“教师验证”“准确率证明”“学习增益”或类似表述。

## 3. 执行前置：A1 数据与隐私协议

在邀请留学生使用前，先完成一份简短的试用说明和数据记录协议。协议应以可读语言说明：试用目的、记录哪些字段、哪些字段不记录、数据保存位置、保存期限、删除方式、是否可以跳过或退出、是否影响课程或其他权益。

这一步需要做一次范围严格的官方资料调研，重点确认知情同意、数据最小化、可撤回、删除和小规模学习研究记录的通行要求。调研只服务于 A1 协议，不改变产品路线，也不把项目包装成正式临床或教育效果研究。研究结果写入独立笔记后，才能冻结 A1 记录字段。

**交付物：**

- A1 试用说明与知情同意文本；
- 数据字段白名单和禁止采集清单；
- 本地数据删除/导出操作说明；
- 调研笔记：`reports/2026-09-30-A1-学习者试验与数据治理调研.md`；
- A1 试验记录模板。

**前置验收：**

- 用户能够用自己的语言说明试用目的、记录内容和退出方式；
- 记录字段不包含与教学闭环无关的身份证件、联系方式、精确位置或完整个人档案；
- 每条真实记录均有匿名化试验编号，真实姓名与项目数据分离保存；
- 退出后可以定位并删除该试验编号产生的数据；
- 未完成协议前，不导入留学生真实数据。

## 4. 阶段 A1：真实场景使用闭环

### 4.1 目标

让项目作者和少量留学生完成真实交互，并验证一条可追踪闭环：

`用户输入 → 识别/候选 → 反馈或静默记录 → 用户回应/确认 → 图谱或账本写回 → 复习队列`

A1 的核心问题是“真实用户能否完成并理解这条链”，而不是“模型在小样本上有多高分”。

### 4.2 真实场景

至少覆盖三类场景，每类至少产生一轮可追踪记录：

1. **语言困难：** 不知道怎么说、说得不自然或反复出现同类偏误；
2. **学习困难：** 记不住、复习中再次出错、对反馈不理解；
3. **生存场景：** 办卡、问路、预约、租房、就医等需要完成任务的对话。

每位试用者可按真实意愿使用，不强行凑满样本。建议把“三位学习者各约 20 句/次有效互动”作为观察目标；没有达到时记录原因，不补造数据。

### 4.3 工程交付

- 为每次试用生成匿名 `study_session_id`，与现有 `learner_id` 分离；
- 记录结构化事件：输入、识别状态、介入档位、反馈策略、用户是否继续、确认/拒绝、图谱写回、复习队列变化；
- 增加本地试用仪表盘或导出报告，至少显示识别数、待确认数、已确认数、复习队列数、场景覆盖和异常数；
- 增加一条端到端测试，覆盖“输入到复习队列”的最短闭环；
- 真实数据与测试数据分根目录保存，真实数据不提交 Git。

### 4.4 A1 验收标准

满足以下条件才算 A1 完成：

- 至少有一条真实场景记录完整走通输入、反馈、确认、写回和复习队列；
- 每条记录可通过 `study_session_id` 关联到处理结果，不需要读取原始 API Key 或完整内部异常；
- 用户可以理解系统为何介入，能够指出至少一类“应该介入”和“介入过早”的例子；
- 至少一条偏误被写入待确认或已确认状态，并能在复习队列中被检索；
- 至少一条用户明确拒绝或跳过反馈的记录不会被错误标记为“已掌握”；
- 试用结束后能生成一份只含匿名编号和聚合结果的报告；
- 代码回归测试和确定性教学评测继续通过；
- 形成失败清单，明确哪些问题进入下一阶段，哪些问题暂缓。

**A1 不得宣称：** 识别准确率、教师仲裁、学习增益、行业领先或对外泛化能力。

## 5. 阶段 B：提示表达层

### 5.1 目标

把“是否介入”与“如何表达”分成两个可观察决策。第一版只实现五类固定策略：

| 策略 | 适用含义 |
|---|---|
| 无声重铸 | 保持交流，给出自然正确形式 |
| 升调暗示 | 提示学习者自行修正 |
| 局部追问 | 只追问当前需要的知识点 |
| 对比提示 | 对比两个可能形式，推动学习者选择 |
| 显性纠错 | 明确指出形式、原因并要求复述 |

### 5.2 第一版输入与输出

策略选择器只依赖已存在或可审计的字段：

- 学习者等级；
- 偏误严重度和是否影响理解；
- 同类偏误重复次数；
- 是否主动求助；
- 知识点是否已掌握；
- 当前是否处于生存任务或连续对话。

每次选择都记录：

```text
intervention_mode
hint_level
reason_code
target_error
user_requested_help
```

### 5.3 验收标准

- 五类策略均有确定性选择条件和反例测试；
- 用户主动求助时不会被无声重铸吞掉请求；
- 生存任务中不会因低影响偏误阻断任务完成；
- 同一偏误在重复出现时可以升级提示强度，但升级原因可解释；
- 反馈文本与策略元数据一致，不出现“记录为暗示、实际直接给答案”的错配；
- 每条反馈都能回溯到目标偏误和 reason code；
- 至少用 A1 真实记录回放一轮，人工确认策略是否符合预期；
- 代码回归、确定性评测和新增策略测试全部通过。

## 6. 阶段 C：对话记忆

### 6.1 目标

让系统记住有用信息，并把记忆用于连续开场、反馈调整和复习。第一版复用 SQLite、事件账本、`learner_memory` 与错误图谱，不新增外部向量数据库。

### 6.2 三层记忆模型

| 层级 | 内容 | 写入规则 | 使用方式 |
|---|---|---|---|
| 短期对话记忆 | 最近轮次、当前场景、未完成任务 | 当前会话自动写入 | 维持上下文和连续任务 |
| 学习记忆 | 已确认偏误、知识点掌握、复习状态、反馈偏好 | 识别/确认/复述验证后写入 | 选择提示强度、安排复习 |
| 经历记忆 | 学习者主动分享且确认过的地点、事件、目标 | 先提取候选，确认后写入 | 后续开场和真实场景练习 |

模型猜测不得直接成为经历事实。每条长期记忆应有来源事件、更新时间、置信状态和删除标识。

### 6.3 验收标准

- 新会话能够召回经用户确认的上一场景或未完成任务；
- 学习记忆能影响一次提示策略或复习排序，并在日志中可解释；
- 未确认的经历候选不会作为确定事实呈现给用户；
- 用户删除某条记忆后，后续召回不再使用该条内容；
- 记忆写入失败不会阻断当前对话，且会留下可诊断的结构化状态；
- 同一事件重复写入具备幂等性，不产生重复记忆；
- 记忆查询不把完整原始对话和敏感字段无条件注入 LLM；
- 提供单机阶段可执行的查看、删除和备份说明；
- 新增记忆测试与现有全量测试通过。

## 7. 阶段 D：教学法文档

### 7.1 目标

把经过 A1、B、C 实际使用检验的策略写成可读、可复核、可继续迭代的教学法说明。

### 7.2 文档结构

1. 产品命题与适用边界；
2. 七条教学策略及其理论来源；
3. 介入时机与五类提示表达；
4. HSK 等级、偏误重复和场景任务的调整规则；
5. 记忆如何服务于复习和连续开场；
6. 一条完整真实对话案例；
7. 当前已实现、仅内部试用、待正式教学验证的边界；
8. 失败案例、已知限制和下一轮假设。

### 7.3 验收标准

- 每条原则都能指向代码策略、事件字段或真实案例；
- 文档区分产品原则、当前实现、内部观察和待验证假设；
- 不把 A1 小样本观察写成模型性能或学习增益结论；
- 读者可以据文档解释一次提示选择和一次记忆召回；
- 文档中的入口、字段名、测试命令与代码一致；
- 由至少一名非实现者通读后，能够复述产品为何介入、如何介入和如何记录。

## 8. 阶段门禁与执行顺序

执行顺序固定为：

`A1 协议与调研 → A1 代码与真实使用 → B 提示表达层 → C 对话记忆 → D 教学法文档`

每一阶段必须同时具备三类证据才能进入下一阶段：

1. 代码或文档交付物；
2. 自动化测试或可重复的检查命令；
3. 人工使用记录或人工复核记录。

任一阶段出现以下情况时暂停扩展：

- 真实用户无法理解或无法完成核心流程；
- 记忆写入错误导致事实混淆或无法删除；
- 反馈策略元数据与用户看到的文本不一致；
- 真实数据边界不清，无法确认是否可以继续采集；
- 新增实现破坏确定性教学评测或现有 API 契约。

## 9. 当前明确暂缓项

下列事项不进入本轮计划，待正式留学生教学或公网部署前重新立项：

- 真实二语教师双人独立标注与第三方终裁；
- 带母语、等级、任务和偏误类型元数据的新样本建设；
- 前测、后测、延迟后测和迁移题的学习增益实验；
- 基于真实供应商价格的费用硬上限；
- 覆盖 `data/` 子目录的完整目录迁移与跨环境恢复；
- 公网身份认证、租户隔离、TLS、反向代理和生产级 SSRF 防护。

这些事项已经在上一份整改执行计划中登记，后续更新完成时需要主动提醒。

## 10. 下一次执行的最小任务包

下一次进入执行对话时，先完成以下内容：

1. 产出 A1 数据字段白名单、禁止采集清单和试用记录模板；
2. 完成官方资料调研并写入指定研究笔记；
3. 设计匿名 `study_session_id` 与最小事件协议；
4. 为输入到复习队列的最短路径补一条端到端测试；
5. 只在上述协议和测试通过后，开始作者本人第一轮真实使用。
